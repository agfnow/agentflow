# Session recovery and ownership

Read for actual owned on-record work, including Q&A, after the entrypoint’s off-record, isolated-looper, lifecycle, setup and idle guards. Those exceptions prevail. Read [delivery](delivery.md) only when updating/rendering STATUS, Reply or next Ask, closing out, archiving, renaming or performing configured Git delivery. Q&A alone requires neither planning nor execution procedures.

## Activate and recover

Apply [entrypoint routing](../SKILL.md#route-before-records) first; it owns off-record/looper/lifecycle/setup/idle ordering, command alias and early guards. Configuration owns discovery/migration and date-gated release checks; owner-facing hosts apply those checks, delegates/isolated loopers do not. Apply configured switches throughout; with `saving-mode: on`, load [saving mode](saving-mode.md) before authoring and pass it to report authors. `.agentflow/` means configured ag-dir except literal bundled assets; configuration is `<checkout>/<ag-dir>/ag.json`, root notebook `<ag-dir>/<notebook-name>`. Explicit/feature routing and absent-notebook history checks still apply.

1. Verify physical startup directory or verified `/cd` binding, Git root/branch/worktrees (outside Git, existing folder and Branch N/A) before recovery/writes. Apply entrypoint missing/Trash/contradictory-identity stops: only read-only inspection, verified feature directory transition or bounded terminal cleanup of an already-authorized own-feature drop/post-cleanup merge-delivery recovery is allowed. Never recreate/fall back. Before routing/execution for lifecycle requests, managed `<main>/.wts/` paths/subdirectories or feature branches, read [features](features.md) for routing, STATUS rejection, records and handoffs; authorized `aglite-*` looper worktrees instead use their execution contract’s explicit isolated notebook. Lifecycle never accesses main/root notebook/archive/claim; root state cannot block it. Read [Windows](windows.md) for Windows/explicit portability operations. Subprocess cwd cannot relocate the session; only a verified Codex/Claude Code `/cd` handoff under features may rebind subsequent identity/routing. Never delete startup checkout/ancestors except explicitly authorized terminal cleanup of its successfully merged/dropped own feature under that contract.

2. Missing managed-feature notebooks follow [features](features.md), never generic setup. Outside a managed feature, use the explicitly supplied notebook or `<ag-dir>/<notebook-name>` (default name derived under configuration). A feature branch outside the managed layout requires an explicit local notebook. If absent and the idle shortcut did not apply, follow [setup](setup.md#first-time-setup) after identity/routing checks. For an existing notebook, read only the latest Ask heading needed to claim it, then follow [Notebook ownership](#notebook-ownership) before STATUS, full recovery or task execution, unless the idle shortcut applies. Reread under ownership and reconcile the Ask before continuing. Inspect Git status when available and preserve unrelated edits; isolate or stop writes conflicting with another writer.

3. Apply [evidence storage](#evidence-storage), then read the active Ask through its end, linked plan/design/tracker and permitted recovery records. With save-evidence off, skip optional round-evidence links, including legacy links, unless explicitly requested; read necessary retained work files, pending state and dedicated operational records. On restart/resume follow STATUS Current and active/next Ask recovery links; before dependent work read tracker Recovery and permitted evidence, or Current’s pending state/permitted evidence without a tracker. Verify notebook/Ask identity and proof against live files/handles. Missing/mismatched evidence leaves dependent claims unproved; never assume completion or treat arbitrary `.tmp` search as authority. At each on-record round’s start, apply [inline-comment intake](#inline-comment-intake) to the latest delivered round and linked earlier replies. Search live `ans:`, `-> ask:`, `-> ans:` and question IDs; read surrounding questions and later resolutions. Skip handled questions only if the named Reply fully answers them; newer corrections prevail. Read permitted evidence relevant to active work/reviewed claims; reconcile files, Git and handles. Empty answers, defaults and stale state are not approval. Under ownership, a selected STATUS with old `Configuration: … schema v8` or combined `Current commit` and `Open`/`Streams` fields loads [legacy projection recovery](legacy-migration.md#apply-and-recover) before dependent work; no preclaim/history sweep or lifecycle root probe. Recover pending [batches](batches.md) before declaring idle. Bare `godev` resumes nonempty work; empty Ask/no pending uses the idle shortcut.

4. Before task edits, copy each unrecorded manually authored owner chat/terminal message in order; stage explicit `append-rounds` messages and corrections explicitly targeting a pending batch under [batches](batches.md) instead of inserting them into the active Ask; exclude feature-lifecycle exchanges/results from root-notebook capture and later summaries, following features.md instead; leave content already authored in the Ask unchanged. Preserve message contents except credential redactions and these capture prefixes: prepend `+ ` to each blank-line-delimited prose paragraph; related paragraphs about one matter may share one prefix on the first paragraph. Preserve code-block interiors and existing `+ ` prefixes; separate groups with a blank line. Add no standalone `--`, blockquote prefixes or closing separator. Exclude host-injected context even when carried in a user-role message (e.g. AGENTS.md instructions, environment metadata, skill/system wrappers). Use message provenance, not role or headings alone; preserve such text when the owner quotes it as task input. Insert owner messages immediately before the active Ask’s first Open questions/RUN/WIP/Reply heading; if none exists, append after its existing input. Never place owner input inside RUN/WIP. Redact credentials with an explicit secure-location reference. Carry recovered answers with their source; append a current-round resolution naming the original question. Preserve historical bytes except authorized owner-input insertion or explicit owner-authorized capture corrections; verify placement before delivery.

5. Before task work, follow [Project rules and backlog](#project-rules-and-backlog), then read [system invariants](invariants.md) and follow its discovery, applicability and maintenance rules, even without a design/tracker. Infer outcome, scope and observable success from the whole Ask; inferred intent never overrides explicit requirements. Anticipate the next consequential need when it affects the outcome. Challenge mistaken premises, infeasible approaches or needless complexity with reasons and a workable alternative; distinguish facts from uncertainty. Respect informed owner choices and existing authorization. For low-impact ambiguity, use a reasonable assumption and continue; name assumptions affecting the result or recommendation. Ask only for material missing decisions, requested checkpoints or new authority; continue independent authorized work meanwhile. Advice, inferred intent and agreement with an idea's merits grant no new authority; preserve existing workflow permissions and finish authorized normal substeps without repeated approval. Corrections steer the task; questions do not cancel it. Activation alone authorizes only eligible first-time setup, never invented project tasks.

## Project rules and backlog

- After identity/ownership and capture on actual work/setup, read [shared project rules](project-rules.md), then established local rules (default checkout-root `<ag-dir>/rules.md`) if present. Preserve rules; never copy the baseline locally or merge automatically. Report unavailable authority/conflicts; defer dependent shared-record writes and invariant/review acceptance, continuing independent authorized work. Configured ag-dir is independent of notebook/feature paths. No idle adoption; host uses direct file operations, no helper.

- Before creation/adoption, discover established rules/backlog/registry from root directives/current records. Different established paths or missing referenced authority require owner routing/reconciliation; explicitly “if present” references remain optional. Never overwrite authority or duplicate records/local-file directives. During [setup](setup.md#first-time-setup), create missing [backlog](../assets/.agentflow/backlog.md)/empty [registry](../assets/.agentflow/sys-invariants.md); otherwise only for the first trackable item/accepted durable guarantee respectively. Reuse owner-designated records. Foreign backlogs are read-only for deduplication absent append/move authority. Registry entries follow [invariants](invariants.md). Owner-authorized moves preserve entries/links; no automatic migration or replacing known custom records because defaults are missing.

- Reconcile relevant backlog entries at actual task recovery, relevant decisions/corrections/deferrals and before closeout, never an idle/timed sweep: capture actionable future work from owner discussion/questions as proposed, explicit accepted deferrals as deferred; exclude off-record exchanges, ordinary explanations, speculative agent suggestions and completed work; deduplicate preserving corrections, update changed status/outcome/reasons, record source/outcome/open reason/effort or next decision, and notify the owner with ID/status/reason/link. Entries, questions, defaults and elapsed time grant no execution authority; bare activation never schedules them. Save proved completion or explicit owner cancellation in the notebook before removing its entry; never infer cancellation. Preserve other open entries; never clear backlog during setup. Move owner-scheduled work with its source into the active tracker/notebook.

- At actual recovery, surface relevant backlog dependencies/overlaps; ask only for material unresolved decisions. At closeout, add backlog Questions only for unresolved choices affecting active work, with B-NNN links and suggested defaults; do not repeat unchanged entries solely as reminders. On explicit backlog/next-work requests, show short prioritized candidates with reasons, dependencies and effort; await owner selection before scheduling. Idle activation never scans/schedules backlog; timed reminders require an explicit owner request.

Encountered old Agentflow startup/manual-writer directives first follow [authorized legacy correction](legacy-migration.md#hooks-and-startup), not silent duplicate adoption. On actual work or setup, check root AGENTS.md and add missing directives under [adoption](setup.md#agents-adoption) after discovery above; no idle/off-record adoption.

## Notebook ownership

- After the idle check, at first notebook access after routing, resolve its physical path (the physical parent plus filename if new), discover only its claim Ask ID, and exclusively create `.<notebook-basename>.owner` beside it (e.g. `.devlog.md.owner`) with `fs.openSync(path, 'wx')` or equivalent before recovery or task execution; never check then overwrite. Store JSON `{session, ask, claimed_at}`. Use the actual host session ID, or generate one UUID and retain it across turns and compaction in host session context; never use a tool PID or host name. Reading an ID from a marker or notebook is not proof of session identity; lost identity requires explicit handoff. In Git, ignore each marker with an exact notebook-relative rule in the local exclude file; never commit it.

- An existing marker permits only the same session and Ask. Foreign, empty, malformed or mismatched activation claims immediately block execution; report the valid marker fields (session, ask, claimed_at), or the parse defect, and an exact-notebook takeover request in chat without writing the blocked notebook. Do not infer a cause or live owner from marker age. Other notebooks remain independently claimable.

- Only for a late ownership conflict after task work began: stop further task edits, retain results and retry exclusive acquisition after waits of 60, 120 and 180 seconds (three retries over six minutes); never clear/overwrite a claim or rerun task effects. Defer the conflict report until exhaustion; then report the refusal fields above and unsaved result. After acquisition, reread STATUS, the latest Ask/Reply and resolutions; reconcile newer instructions and actual files. Reuse only an empty trailing Ask with no unresolved work in that Ask (separately staged batches do not occupy it), or append a separate unused Ask at EOF after a closed round, with the original request/source and retained result; never insert into another round or bury pending work. An occupied/unresolved tail or unsafe reconciliation stops writes for an owner decision. Rebind only this session's verified marker to the receiving Ask before mutation; per-mutation checks still apply.

- Before every notebook mutation, verify the marker still matches this session and Ask, including input capture, RUN/WIP, STATUS, archive and Reply. A verified Reply plus next Ask closes the round even when recovery remains. Before yielding for owner answers, follow [question closeout](delivery.md#questions-during-work); waiting alone never keeps a round or claim open. An actually unfinished round retains its claim; the idle shortcut creates none. If a reread within an already-claimed turn shows the Ask advanced, reconcile and rebind only this session's verified marker before task work; a foreign or unexplained mismatch remains blocked.

- After verifying Reply plus the next Ask, finish immediately possible authorized delivery while retaining the claim; pending approvals still block gated effects, never question closeout or settled claim release. Before yielding, settle all task-owned workers and mutating operations. If one cannot be settled, retain the claim, save its live handle and next action in Current/tracker, and report blocked claim release. Inspect immediately available external identities first. If delivery is blocked or its external result remains unknown after the process settles, verify saved authority, operation identities, unfinished state and next action in Current/tracker. For pending Git delivery, attribute exact prior-round paths/hunks, index entries, local commit IDs and remote target; preserve other staging and delivery boundaries. Then recheck ownership and release only this session's marker under the owner's deletion policy, even with carried recovery or unfinished delivery. A task-owned process that may still mutate, failed recovery persistence or an unverified round transition blocks claim release. An unknown external result from a settled process does not. Reacquire and reread before later task work, notebook mutation or delivery retry; inspect saved external identities before retry. Open means no verified Reply-plus-next-Ask transition. Abrupt interruption and non-question feature-lifecycle exceptions retain existing claim rules; activation with a same-session Ask mismatch still requires explicit handoff. Read devlog owner answers/resolutions and any historical question fields after claiming and rereading a released closed round. Foreign/stale claims require explicit owner-authorized clearing or handoff; never infer release from a Reply alone, age, silence or process state. Release grants neither completion nor approval.

- Hosts execute these filesystem operations directly; no helper, write lock, heartbeat or daemon. This coordinates cooperating agents, not unrestricted editors. Feature lifecycle commands never use main’s root notebook/claim; feature-notebook exceptions follow the feature reference.

## Evidence storage

`switches.save-evidence` is required on|off, default off; setup/migration adds off only when absent, preserving valid values. Deferred migration uses missing off in memory; invalid values stop dependent effects. This section governs all ordinary workflow callers requesting evidence, proof accounting, risk/review/route notes or linked round records, including fast-lane, advisors and isolated task sessions. Explicit owner deliverable/destination requests prevail for their named scope; generic workflow requirements are not such requests.

- **Off:** create/update no optional evidence files (e.g. standalone `.tmp/` proof, captures or optional briefs). Do not redirect evidence to devlog, tracker, product artifacts or another hidden path. A skipped resume-critical link is a named blocker: obtain explicit inspection authority or re-prove recovery before dependent effects. Perform required checks/review/risk/invariant assessment in active context; absent saved proof requires rechecking, never presumed success. Keep answers, mandatory notices and only essential unfinished state/authority, blockers, live/uncertain operation identities and next safe action in Current/existing tracker. Do not persist routine proof accounting there.

- Skip disabled optional evidence during ordinary recovery/review, including old links; explicit inspection may read it. Preserve existing files/history unchanged. Turning on later is prospective: never fabricate/backfill missing evidence. Reduced proof detail may require rerunning checks or leave uncertain effects blocked; design/tracker/devlog/Git recovery remains available.

- **Work files (either setting):** Retain all files produced to do the work, including required briefs and handoffs, through ordinary closeout and scratch cleanup. For every operation and route, save each original/revised draft already needed for the work, including in-session drafts verbatim. The host saves worker drafts that have no file. Prefer direct file output or exact local capture over model retranscription. Reuse an exact match for the same Ask, author and revision. Otherwise save promptly to an exclusive unused path under the producing Ask’s artifact root, or host-only storage while blind. Apply [Round evidence](#round-evidence) claim, path and Git ignore safeguards to these saves. Keep needed recovery links in Current/tracker, inaccessible to blind peers. Report failed saves. Honor read-only, access, no-record, explicit cleanup and delivery limits. Before replacing a living draft in place, save its exact displaced bytes if no exact copy exists. Never generate new drafts, synthetic snapshots, transcripts or duplicates solely for retention.

- **On:** save only useful evidence under [Round evidence](#round-evidence); no file when nothing needs retaining. Keep a few short bullets for ordinary work; expand only for concrete failure, required independent proof or safe retry. Retain facts unsafe to reconstruct and the minimum result/disposition needed for completion/reuse. Consolidate superseded intermediate notes within the active evidence record when their history is unnecessary; never rewrite historical evidence.

- [Pending batches](batches.md#append-rounds), required feature lifecycle retry records, looper queue/attempt/process/integration records and migration/release operation identities/backups retain their dedicated contracts, regardless of this switch. Keep these operational exceptions bounded; do not use them as alternate sinks for disabled round evidence. Requested deliverables, claims, checks/review/independence, gates and devlog capture/answers remain required. No deletion authority follows.

## Round evidence

Apply [evidence storage](#evidence-storage) first: optional evidence paths/fields below apply only when enabled or explicitly requested; retained work files, product artifacts and mandatory operational records follow their applicable rules.

Round reports/related records (designs, trackers, briefs, raw evidence, captures) use checkout-relative `<ag-dir>/features/<name>/artifacts/A-NNN/` in managed features, otherwise `<ag-dir>/artifacts/A-NNN/`; A-NNN is the producing Ask. This selected artifact root also owns prepared looper runs and ignored-proof fallbacks. Create only needed files; use unused names for inherited/unrelated collisions, never overwrite. Source/product files, notebooks/archives and ownership markers keep their own paths; explicit owner destinations prevail. Preserve existing locations; link carried work instead of copying it each round. Workflow proof follows the exception below; link needed raw evidence. No owner-facing verification report unless requested.

Keep technical verification, check/review results, invariant accounting and debugging logs out of devlog STATUS, RUN/WIP and Reply: no Verification sections, proof paragraphs or detailed logs. Save needed new evidence under `<ag-dir>/.tmp/A-NNN.md`; an existing tracker keeps task/recovery state and links this evidence rather than duplicating it. For non-root notebooks use `<ag-dir>/.tmp/<notebook-basename>/A-NNN.md`. Explicit destinations prevail; preserve established records/history without automatic moves/reformatting. Identify physical notebook/Ask and verify namespace before reuse. Foreign/ambiguous collisions require safe unused locations, never replacement. Reject escapes/symlinks; create exclusively; before updates verify this session’s claim and unchanged source.

Before interruption/handoff, link all resume-critical evidence from STATUS Current directly or via tracker Recovery, and from its producing Ask before Reply. Each pointer states supported facts and next safe action. Keep Current linked to canonical recovery while work remains; honor legacy Ask links without copying them into new Asks. Link every unfinished thread and its authority in one tracker; when fast-lane waives tracker creation, use labelled Current pointers to existing recovery evidence instead. Establish links before omitting next-Ask pointers or archiving their sole legacy pointer; never remove historical links. Retain pointers as STATUS advances until dependent work settles; filenames alone cannot provide recovery. Other proof needs only its producing Ask link. Despite `.tmp`, linked evidence is durable: never automatically ignore/delete it. In Git, check ignore rules before creating/linking; use an unused nonignored path under the selected artifact root when needed, and include the record in authorized delivery. Keep unfinished state/authority/next action in Current/tracker; new owner questions use [devlog questions](delivery.md#questions-during-work), linked from recovery; preserve historical answer fields. Off-record/idle rules prevail.

Keep detailed [risk dispositions](review.md#risk-triage) and [human review accounting](deep-review.md#human-handoff) in enabled evidence only; implementation-result review answers give the risk level and short reason, plus decision-changing blockers/limits, sensitive actions requiring attention and actual approval requests. Disabled storage creates no substitute record.

Lifecycle recovery required by features.md retains notebook/Ask identity, authorized operation/cleanup scope, exact retry-prevention refs, last proven result and next safe action. Retain pending gates/path updates and details needed for unresolved failures, required checks/review or consequential decisions; never omit fresh safety checks. No new record location/mandatory report; drop has no durable record.

New evidence retains only recovery, required review/proof or consequential-decision support. Use these fields in order, localized for human readers; omit empty/inapplicable fields, placeholders and facts already owned elsewhere (link them). No separate file when nothing needs retaining. This default applies with saving-mode on or off; no line cap or extra report follows.

- **Scope:** physical notebook/Ask; exact checked/reviewed source identity only when needed to bind proof.

- **Checks:** meaningful check/review result, required per-ID accounting and proof limits; link existing raw proof once. Group same-reason N/A IDs.

- **Findings:** review finding, consequential decision or unresolved defect, with disposition and supporting reason/authority.

- **Resume:** unfinished action, last proven state, blocker, live/uncertain operation identity and next safe action; link canonical Current/tracker state rather than duplicate it.

Omit routine command sequences/output, successful tool setup, copied drafts/transcripts, chronological narration, source-reproducible detail, repeated results/model-control explanations and hashes unless exact identity matters. Retain details required for unresolved failures, review dispositions, authority and safe retry; link necessary raw proof instead of copying it. Apply these fields to new workflow evidence, not fixed design/tracker, feature/looper or requested deliverable formats. Preserve their required recovery/proof, established paths and historical bytes; never automatically compact/delete old evidence. Evidence location never waives checks/review or turns missing proof into a pass. The devlog retains concise outcome/recovery pointers, required RUN/WIP milestones and notices, answers, Questions and decision-changing blockers/limits; link proof instead of copying it.

## Inline comment intake

Identify the latest delivered round by its verified Reply and next Ask under [delivery](delivery.md#notebook-and-delivery). Recover incomplete transitions under ownership. Within the caller-selected rounds, check for additions embedded beside the text. Use initials such as `+jx:` to find candidates. Require independently attributable owner edits or direct owner confirmation before treating a note as input or approval. Exclude quotations, already captured inputs, host-authored/injected text and notes resolved in a later Reply. Clarify ambiguous provenance before acting.

An attributable pending note counts as work on bare activation. Under ownership, capture the activation normally, link the note from the active Ask and treat it as owner input within its explicit scope. Keep the original in place. Answer it in Reply or carry the unresolved point with its source and blocker; record any needed clarification through the existing Questions procedure.
