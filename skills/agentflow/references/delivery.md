# Delivery and notebook operations

Read when rendering/updating STATUS, Reply or next Ask, closing out, archiving, delivering Git changes or renaming a notebook; simple intake does not load archive/rename procedures.

## Notebook and delivery

Render human labels/prose in the configured locale under [use-lang](configuration.md#discovery-and-validation); English labels below and in assets specify semantics. Preserve fixed structure/tokens and existing history. New Ask/Reply headings use `# → <localized label> / A-NNN`: the same right arrow for both, distinct phase labels, first heading Ask then Reply for each ID, then the next consecutive Ask. Only Ask may have a parenthesized asker suffix.

- Locale-rendered `# STATUS` comes first: **Project** name; **Notebook** actual path/kind; **Checkout** physical root/folder; **Branch** observed branch/detached commit/N/A; **Current** active Ask/recovery/tracker link; **Proven** latest concise verified outcome/evidence or none, no check/review details; **Next** safe action/awaiting request; **Archived eras** actual adjacent archive/none. **Stream**, **Cleanup**, **Session** occur only in managed feature records under [features](features.md). Refresh all fields from observations after recovery/material changes/closeout; prior STATUS proves no success, unavailable checks stay unproved. Link canonical records; duplicate no task lists/store no configuration.

- History is append-only except STATUS and owner input in the active Ask. Use increasing Ask IDs and unique question IDs (e.g. Q-012-1). Each round is `Ask → enabled RUN/WIP → Reply → next Ask`; all progress precedes Reply. Resumed work after Reply belongs in the next Ask.

- Before delivery reconcile compound asks, corrections, inline answers and deferred proposals. Append `Handled Q-012-1 in Reply / A-013` only for that Reply’s complete answer/working link. Compare files/proof with acceptance, design-local and applicable canonical [system invariants](invariants.md); distinguish done/blocked/running/unproved. Finish authorized Git delivery, preserve foreign work, report material failures.

- Any registry content change requires a dedicated `System invariant changes` heading with affected IDs, changes and reasons in saved Reply and owner-facing closeout, even with `inline-reply: off`; newly added/materially changed backlog items require owner notification with ID/status/reason/link. Show notice sections before the exact short receipt. Saved Reply and chat report path-only moves under `System invariant relocation`. Notices also accompany feature handoffs.

- Answer the request directly. Omit routine planning, review, validation, unchanged-scope and delivery-status summaries; use [Round evidence](session.md#round-evidence) for needed workflow facts and RUN/Current/tracker for milestones/recovery. Include failures, blockers, proof limits or delivery status only when they affect the requested outcome, the owner’s next action, or were explicitly requested.

- Every new Ask (including setup/features) has standalone `---` with a blank line before/after; apply `omit-asker`, preserve IDs/history. Reply heading → blank line → `* _YYYY-MM-DD HH:mm:ss ±HHMM_` from actual update time/timezone (e.g. `* _2026-10-04 05:11:15 +0800_`). Omit bare `godev` from answer items, not required capture; cover messages with further instructions.

- Reply excerpts: original questions/requests in order, numbered (1., 2., …); quote only each first paragraph, capped at 100 Unicode code points including spaces/punctuation, never splitting graphemes. Each correction/compound subrequest gets its own capped excerpt. Safely quote text, preserve literal backticks without backslash escapes, escape other syntax only as needed; if truncation leaves an unmatched backtick, cut before it. Append `...` for any omission. Immediately below, indent short answer paragraphs/nested items or exact report-section link within the same item. Redact credentials; repeat no full answer.

- End with locale-rendered `## Questions (batched — each with a suggested default)`: each material unresolved question has unique Q-NNN-n, suggested default (or “none — owner decision required”) and one empty `- ans:`; otherwise locale-rendered `- None.`. Existing design questions use exact section/ID links and existing answer fields, never duplicate locations. Defaults/empty answers grant no approval. Feature lifecycle overrides generic Reply rules, including chat-only drop results.

- Multiple reports: within the relevant numbered answer add **Key Records — read these first**, linking every generated/updated report the owner needs in recommended order, each with one sentence explaining contents/importance. Exclude intermediate/superseded reports unless needed for a material limit. Indent guide; label and each link/sentence occupy separate blank-separated source lines.

- Save one complete final answer in Reply or requested report linked to exact section. Same write: next Ask in each receiving notebook plus STATUS refresh; new-feature bootstraps follow [features](features.md). Keep unfinished work/recovery/authorizing input in tracker, or Current without one; STATUS Current must reach every unfinished thread through tracker or labelled evidence pointers when waived, honoring legacy Ask links. Next Ask is empty except captured input, with no recovery pointer; unspecified future work is no carry-forward. Keep latest completed round live; read back each Reply/tail, verifying no progress follows Reply.

- `inline-reply: off`: save every substantive answer/proposal/example/batched question in Reply or linked report; [gate-tracker](planning.md#planning-modes-and-gates) has its saved-request exception. Except for [required preparation terminal choices](looper.md#prepare-and-route), chat/terminal answers require explicit destination requests, separately for each compound answer; “show me”, “what will be displayed”, examples or future-output changes grant none. Keep questions at existing answer locations. Never echo saved answers through tools/shell/question tools; readback uses byte/hash/structural checks outputting status only. Chat progress reports activity only. Preserve off-record/idle, pre-setup Git choice, required notices (including newer same-product release), blocked/unfinished status and actual feature handoffs; hypothetical handoffs stay saved.

- Blank-separate Markdown items; never hard-wrap prose; honor owner conventions. With `inline-reply: off`, completed work with no essential remainder outputs only locale-rendered `→ Updated: A-NNN | <notebook>\n  (<working-directory>)`, except required invariant/backlog/newer same-product release notices, preparation terminal choices, explicit chat/terminal answers or actual feature handoffs. Completion explanations stay saved. Use completed Ask ID, not empty next Ask; [batches](batches.md) governs multiple completions.

- Receipt paths: physically resolve verified session-directory binding/actual notebook. Abbreviate only verified directory home prefix to `~/`, otherwise absolute. Notebook is relative to that directory with every component (e.g. `.agentflow/devlog.md`), or absolute if outside; never resolve against home. Localize only `Updated`; preserve arrow/colon/ID/pipe/two lines/two-space indentation exactly.

- `inline-reply: on`: complete saved Reply (all newly completed batch Replies), then receipt. Explicit chat/terminal destination: only requested saved answers, then receipt; “complete answer” without explicit destination does not override off. Feature lifecycle results/handoffs override receipt; create no root Reply. If essential work remains, save unfinished status/proof limits/next action, then receipt acknowledging update, never completion.

- Archive above 750 lines or on request: retain unresolved material/latest completed round; append older completed bytes unchanged/in order to one adjacent `<notebook-stem>.archive.md` (remove final `.md` only). Exclusively create if absent; otherwise verify existing content/unchanged source before append. Verify saved history before live-byte removal; keep one pointer. Never number era files/overwrite history. Ambiguous archives/unsafe boundaries/failed verification leave history untouched; report limit.


## Git delivery

- Eligible first setup or explicit main-rooted new-feature preparation authorizes only the [empty bootstrap](setup.md#empty-bootstrap), even with auto-commit off; explicit commit prohibitions prevail. Later delivery follows the switches below.

- After bootstrap from approved `git init` or an existing repository without commits, limit first delivery to verified task/setup changes; preserve pre-existing unrelated staged entries and leave untracked contents untracked unless separately authorized for inclusion. Retain this exclusion through preparation/setup recovery and delivery; bootstrap authority never includes those contents and overrides automatic owner-edit delivery below.

- auto-commit on makes the task commit first, containing all verified Ask changes, including records/settings. Then inspect and commit owner-authored edits and foreign work separately, including pre-existing edits. Inspect index/diffs before each commit; stage named paths/hunks and commit only its verified content, preserving other staging without reset. Exclude secrets. Uncertain authorship or unsafe separation blocks only affected delivery; report it. off grants no commit authority. Without Git, skip both controls.

- auto-push on pushes this checkout's task and separate owner-edit commits on its observed branch; off grants no push authority. With auto-commit off, push only already-committed authorized results; bootstrap alone grants no push authority. No remote: skip. Otherwise use upstream or the sole remote with explicit current branch. Detached/changed branch, ambiguous remote or unexplained outgoing commits block push. No force/pull/rebase/reset/stash. New-feature preparation stays uncommitted except the empty bootstrap, and unpushed; drop-feature stays uncommitted/unpushed. Merge-feature follows feature-specific lifecycle rules after verified integration/checks and gate approval, excluding main’s root notebook/archive/claim and unrelated owner-edit delivery.

- After checks/review/gates save/verify Reply/next Ask → task-record commit → separate owner-edit commit → enabled push. Retain claims during delivery. Verified closed round with blocked/unknown delivery: save recovery, settle workers/processes, release claim at turn yield under [session](session.md#notebook-ownership), retain unfinished status; open-round/feature exceptions prevail. Verify commit paths/remote tip; rejected/unknown push stays unfinished, inspect identity before retry.

- Before notebook mutation rebind own claim to next Ask. Preserve Reply; save delivery failure/next action in tracker or Current, linking canonical recovery from STATUS Current under [Round evidence](session.md#round-evidence), honoring legacy Ask links. Outside feature lifecycle, before later-round delivery reconcile attributed prior-round paths/hunks, index entries, local commits and remote target. Finish authorized prior delivery first, or commit safely separated attributed prior work before new task commit. Missing attribution/authority blocks affected delivery; never absorb earlier work/unrelated staging. Preserve repository boundaries; report material local-only/blocked state.

- Never commit/push merely to log successful hashes. Settings authorize no release/deployment/send/cleanup/unrelated-repository work. Failed/unavailable required checks block delivery commits/pushes, not recovery records. Before staging record justified byte-preserved history/capture check exceptions in tracker/notebook; never rewrite those bytes or waive task-authored failures.


## Notebook routing and rename

Unless the idle shortcut applies, on activation route and claim under [SKILL.md](../SKILL.md), then refresh the selected notebook's STATUS path; an existing configured notebook needs no relocation. If the configured path is missing, inspect root/configured work-directory notebook/archive candidates before setup; known history or ambiguity requires owner selection, never a replacement notebook. A setting change alone does not authorize moving files or abandoning unresolved work.

Explicit rename follows identity/ownership/delivery rules. Claim source and exclusively reserve destination for same session/Ask; reject collisions, foreign claims and routing/path violations. Discover single adjacent archive from STATUS and `<old-notebook-stem>.archive.md`; replace only notebook stem, removing final `.md` if present (e.g. `devlog.md`/`devlog.archive.md` → `notes.md`/`notes.archive.md`). Reconcile disk/STATUS; missing listed archive or ambiguous/custom association (including shared stem/archive-shaped name) needs owner selection. Include verified unlisted stem archive; multiple archives need owner reconciliation, never auto-merge; absent archive means none.

Preflight all sources/destinations/affected live links before moving; reject unsafe paths, collisions, foreign claims/concurrent changes. Recheck unchanged source/config/both claims; move notebook/archives without overwrite, verifying each destination’s historical bytes before STATUS/live-link edits. Outside ag-dir requires authorized routing (ag-dir change/explicit notebook selection), never path-valued notebook-name. Atomically update basename where applicable, STATUS/affected live links; verify old paths absent/new history/config/links correct, close out at destination, release only own claims after delivery. Ignore every marker locally.

Same-directory stem renames include associated archives under the explicit notebook-rename authority; update affected live links, preserve historical bytes. Directory relocation or historical-link edits need explicit authority. Before any rename/relocation, check unchanged historical links, including notebook/archive filenames; broken links stop for owner reconciliation. On interruption, retain claims and each notebook/archive source, destination and observed move state; inspect partial state before retry and report recovery paths, including a moved notebook with incomplete archives/configuration. Never recreate, overwrite or clear claims to recover.
