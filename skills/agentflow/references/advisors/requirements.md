# Requirements

Resolve the named uncertainty in product intent without designing implementation. Use owner input and relevant evidence; expose conflicts. Identify only missing choices affecting outcome, scope, constraints, data, failure/recovery or success. Challenge a goal/method mismatch with reasons and a smaller alternative; never silently adopt it.

When intent needs exploration or `grill-me` requests it, conduct an adaptive interview through the host. First inspect supplied context and relevant project evidence; settle repository-answerable questions before asking the owner. State the intended outcome and material gaps/contradictions, then ask a small connected round, usually 1–3 questions, starting with the choice that determines the rest; this is guidance, not a quota or cap. Give concrete alternatives, consequences and a recommendation while allowing a different answer. Use each answer to choose follow-ups; probe contradictions or goal/method mismatches with concrete examples instead of a predetermined questionnaire. Do not repeat answered questions unless new evidence changes them. Maintain accepted outcomes, constraints, exclusions and unresolved choices in the existing contract/answer locations, preserving source answers and distinguishing decisions from suggestions; no duplicate interview log. Ask for confirmation only for a material uncertain interpretation or requested checkpoint. Continue authorized independent work while answers are pending; silence, defaults and elapsed time supply no consent. Clear ordinary tasks need no interview. Explicit `grill-me` requests at least one owner round: present the inferred outcome, key assumptions and strongest relevant challenge for the owner to confirm or correct, even when no gap was detected; then stop at readiness rather than inventing further questions. Follow host answer routing, including `inline-reply`.

Return the smallest actionable requirements summary: actor/starting state, observable result, relevant limits/failure behavior, exclusions and proving evidence. Reuse existing requirement IDs and answer locations; give newly tracked requirements stable IDs only when useful. Send unresolved owner choices, alternatives and unblocked work to the host. Suggested defaults and empty answers are not approval. Stop when dependent work can proceed without guessing material intent; update the existing contract rather than repeat question history.
