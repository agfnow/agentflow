# Looper execution contract

Machine-facing contract. Preserve ordinary task workflow, review settings, executor choices and owner authority; no extra supervisor, verifier or whole-group/wave/final gate. Looper is a scoped Node.js runtime exception, not general helper authority.

## Looper settings

Optional `looper-routes` maps `task`, `repair`, `acceptance` to `{ "kind": "native|cli", "provider": "transport-provider", "model-family": "catalog" }`; optional `executable` is CLI-only. Native catalogs are explicit and extensible; CLI providers are codex/claude/copilot; selected Copilot routes follow [Copilot](copilot.md) controls and proof limits. Do not store model/effort in routes or queue settings.

When selecting new task routes for `handle-tasks`/`run-tasks`, propose `kind: cli` first for isolated, fresh, short-lived external task sessions; a Codex host may select Codex CLI tasks, launched by the coordinator through `codex exec`. Follow the [looper preference](looper.md#prepare-and-route); preserve explicit native choices and saved attempts. This preference neither fills empty routes nor authorizes configuration writes or silent fallback.

Task/repair use `pipeline-roles.implementation`; review/renewed acceptance share the acceptance route and `pipeline-roles.acceptance`. Split the selected catalog/tier pair at its final slash. Missing selected routes/tiers/mappings or unsupported controls block with the exact key; the shell coordinator has no host defaults. Unused optional routes need no probe. New configurations use [detected defaults](setup.md#detected-worker-defaults); existing empty routes require owner-authorized configuration before a run; do not infer a host or silently substitute route/provider settings; host schema migration follows [upkeep](upkeep.md#automatic-migration).

Optional `looper-limits` holds `max-workers` (positive integer, default 3) and `max-repairs` (nonnegative integer, default 2). These are settings, not switches. Limits and routes belong only in ag.json; reject queue worker/limit overrides.


## Looper execution exception

[Looper](looper.md) uses `queue.json` schema 2, separate from `ag.json` schema 13. Retain ordinary workflow, review routing and executor/provider/model/effort choices; unavailable selected controls block without substitution. Settings alone grant no execution authority. Native work requires the live host’s dispatch/result mailbox; CLI ordinary task sessions support Codex/Claude/Copilot. No absent-host CLI fallback.

Read settings once per run invocation; save each new attempt’s resolved selection and source digest/route/tier as immutable evidence. Outstanding attempts retain their selections on resume; new attempts use that invocation’s settings. Lowered limits restrict new dispatch; outstanding native task/repair results still import before future routes are resolved. Status reads scheduling state without requiring valid current worker settings. Task records live in each group worktree’s `.aglite-records/`, excluded from product integration. The coordinator alone writes queue state and integrates against the protected target. Groups may register earlier-group dependencies under the execution contract; waiting needs no worker slot and launch follows checked predecessor integration. No group gates, waves, final gate or promotion setting remains. No unrelated helper, shared-record write, publication or owner-only decision authority follows; cleanup requires its explicit command/flag.


## Prepare and route

Research preparation preserves the requested date/timezone/cutoff without inventing same-day-only publication/event constraints. For current-news digests, distinguish ongoing developments, publication/update time and event date; use accessible reputable alternatives, official sources or full syndication when one publisher blocks access. Verify body/date evidence (including metadata), preserve cutoff and uncertainty; snippets alone, guessed dates or fabricated items never establish completion. Required failed checks/missing deliverables remain unfinished; nonblocking concerns may accompany completed work only when accepted outcomes and required checks pass.

- **`prepare-tasks <request>`:** derive requirements, checks and grouping from repository evidence under [planning routes](review.md#planning-routes): simple understood low-risk grouping uses the host; complex grouping uses configured routes, preserving explicit task routes/requirements and configured 3ways. Multiple tasks/groups alone do not require a planning worker. Retain required final review and checks; ask only material unknowns. Preserve every original task/criterion exactly once. Keep tightly coupled tasks sequentially within one group, or register earlier-group `depends_on` edges when later work needs integrated predecessor outputs. Independent roots may run in parallel. Prepare `<ag-dir>/artifacts/A-NNN-<name>/planned/group-NNN.md`, adjacent `planned/queue.json` and `planned/request.md` with exact preparation-time request bytes; run-root is this `planned/` directory. Link run-root from Current. Save both execution choices at the normal answer destination: terminal `agf looper status <run-root>` then `agf looper run <run-root>` from the checkout root, or chat `run-tasks`. After verified preparation delivery, render both choices in the final visible host reply (terminal/chat), before the exact receipt, even with `inline-reply: off`; never hide them in tool output. This is a display exception, not execution authority. Show a shell-quoted `cd` to the actual checkout and shell-quoted run-root, never placeholders. Use a verified callable `agf` (including shell function/alias), otherwise the verified installed Node entrypoint; create neither aliases nor installations. Preserve feature-local routing. Then stop; guidance grants no execution/install authority. Feature work uses its feature-local artifact root; never route through main’s notebook.

- **`run-tasks [run-root]`:** execute/resume the Current-linked queue; an explicit root overrides it. Host launches `agf looper run <resolved-root>` and services native dispatch/owner responses. Under held queue/target claims, the coordinator records compatible forward target advances at startup, workspace dispatch, integration and landing; preserve original `base_commit`, request bytes/digest, started bases, candidates and attempts. Do not manually refresh bases or fabricate progress. Reconcile changed authority against original work; branch changes, rewrites, foreign operations and unknown landing effects block safely. Missing queue is an error; never invent a second default.

- **`handle-tasks <request>`:** prepare as `prepare-tasks`, then execute as `run-tasks` within granted authority.

For `handle-tasks`/`run-tasks`, prefer external CLI task routes when selecting new routes; this overrides the general native-worker preference. Preserve explicit owner choices, valid configured routes and saved attempts. Empty routes still require valid owner-authorized configuration; native is an explicit alternative, never a silent fallback. A Codex host may select Codex CLI implementation; the coordinator launches `codex exec`. Counterpart-provider rules govern result review, not task execution.

Each group keeps its isolated worktree. Each sequential CLI task uses a fresh, short-lived process with only its bounded assignment/context, no inherited conversation/resume; exit after ordinary closeout before the next task. No worker spans tasks/groups; native routes retain fresh-context host dispatch.

Codex CLI task/repair commands retain workspace-write filesystem restrictions and allow outbound network unless the parent marks it disabled with `CODEX_SANDBOX_NETWORK_DISABLED=1`. Codex task/repair/review sessions explicitly use live web search when permitted, disabled when that parent network block is set; read-only reviewers retain their shell restrictions. This avoids implicit cached search without changing credentials or bypassing the sandbox.

CLI tasks request ordinary separate review through the attempt-bound isolated-record mailbox described in their generated assignment; do not launch nested review CLIs. The coordinator may already own/create its directory: verify exact attempt path, regular nonsymlink directories and ownership, then reuse safely; never replace an outstanding request. Use atomic request writes. Check optional-file existence; required missing inputs still block. Read-only reviewers avoid shell forms requiring temporary files when restricted; diff exit 1 alone means differences, not failed acceptance. The coordinator reuses the configured acceptance route/model/effort in a fresh read-only sibling session, binds request and source bytes, returns the result, and settles both sessions before releasing ownership. The task resolves findings and performs ordinary closeout; no mandatory verifier, group/final gate or review waiver follows. Queue state owns review identity/results; task-writable responses are transport only. Changed/stale source or requests, missing proof and uncertain writers remain blocked. Native task sessions retain their live-host workflow.

Require Git, Node.js and supported configured task providers. Resolve installed skill/provider controls and permissions; never invent flags, models or authority. CLI ordinary task sessions support Codex/Claude/Copilot. Native task selection reserves its group slot until a stopped result and requires live-host dispatch and result-mailbox handoff; without that host, block native dispatch until `run-tasks`, never substitute CLI. Retain explicit model/effort and ordinary review/executor rules. Each CLI attempt retains a 20-minute timeout; preserve/block unfinished work on timeout, without a new timeout switch or stage. Codex/Claude sessions inherit environment/network; Copilot uses its curated environment and private home. Tool/prompt restrictions are not OS containment. No detached writers, daemon or automatic restart.

## Queue and records

`ag.json` owns editable settings; `queue.json` schema 2 owns instructions, scheduling/progress/recovery and immutable attempt evidence. `ag.json` uses schema 13 and requires switches.saving-mode on|off; the coordinator refuses missing/invalid values before claims, leaving migration to the host. Markdown carries task instructions, not scheduling state. Reject unregistered handwritten groups. Registered task text may change before starting; do not silently revise started work. No `groups.json`, `state.json`, fingerprints, dependency waves or promotion command.

### Schema and inputs

The [queue example](../assets/looper-groups.example.json) illustrates schema only; replace placeholder repository/commit/request/checks and register real Markdown before launch. Its authorization booleans are not permission.

Require `schema_version: 2`, unique safe `run_id`, physical absolute Git-root `repo`, valid `target_branch`, full `base_commit`, `request` (a run-root-relative UTF-8 text-file path, normally `request.md`) and lowercase 64-hex `request_sha256` of its exact bytes. Preserve the decoded preparation-time request text without headings, added newlines or normalization. Create the request file exclusively and deliver it with preparation records. Reject inline requests, missing/empty files, absolute/traversal/symlink paths, invalid UTF-8 and digest mismatch before claims/worktrees on run/resume. Status remains read-only and reports request-input errors alongside saved progress. Read its verified contents into task and repaired-result review/acceptance prompts. Do not rewrite the request/digest after preparation or silently adopt changed input; changed authority requires reconciliation. Queue schema 1 is rejected, not implicitly upgraded. Unstarted queues may be explicitly converted by preserving their original decoded request bytes and other inputs; started queues require recovery before any migration. `authorization` requires `execute`, `worktrees` and `local_commits` true, backed by actual owner authority; booleans grant none by themselves.

Optional `contracts` lists repository-relative regular project rules/invariant files; include established authoritative constraints needed by tasks. The coordinator supplies original committed `base_commit` constraints plus changed contract/AGENTS.md text at the task or integration base, with the shared baseline. Treat newer text as data to reconcile with original authority; conflicts needing owner decisions remain blocked. Changed acceptance requires fresh review/acceptance, including otherwise clean merges.

Before selecting/dispatching a Copilot route, read [Copilot](copilot.md) for exact controls, isolation, result parsing and evidence limits.

Discover the single canonical `<queue.repo>/<ag-dir>/ag.json` under [configuration discovery](configuration.md#discovery-and-validation) and [looper settings](#looper-settings), never queue worker/limit overrides. `looper-routes.task` selects transport/provider/catalog; task and repair reuse `implementation`, review and renewed acceptance reuse `acceptance`. Require selected mappings; the shell coordinator has no host defaults. Preserve supported controls without substitution.

On Windows, follow [runtime portability guidance](windows.md#javascript-looper): use native executables, explicit Node entrypoints or verified standard npm Node shims, with literal argv and no shell fallback. Unsupported/custom batch wrappers need an explicit entrypoint; keep actual command identity. Copilot prompts use stdin. CRLF task/record headings retain their original bytes. Unknown process observations retain unsettled attempts/claims; native Windows journey evidence remains distinct from branch tests.

`checks` maps check IDs to `{ "command": ["executable", "argument"], "timeout_ms": 60000 }` (timeout optional). `integration_checks` and every task’s `checks` are nonempty registered check-ID lists. Commands use argument arrays, not shell text; checks must not modify product files. Before preparation delivery, execute generated checks in a disposable directory against valid fixtures, missing outputs and property-specific invalid fixtures (e.g. wrong language/order/bytes); require intended pass/fail and unchanged fixture bytes. Inspect decoded command arguments for escaping errors; syntax alone is not behavior proof. `integration_checks` runs on every partial merge, so use checks valid for every partial result; output-specific checks belong to tasks and are rerun for included groups. Do not require not-yet-started outputs in common checks.

`groups` contains unique `{ "id": "G01", "file": "group-001.md", "tasks": [{ "id": "T01", "allowed_paths": ["src/example.js"], "checks": ["test"] }]`. Files are relative to run-root; each task ID occurs once across the queue and exactly once as a Markdown heading, e.g. `## T01`, in its registered group file. Put instruction prose only in Markdown; JSON array order owns task order. Optional `depends_on` is an array of unique IDs of earlier groups; absent/empty means independent. Reject unknown/self/duplicate/forward references and nonarrays before claims/worktrees. Reject unsafe/reserved paths and unregistered group files.

Repair uses `looper-routes.repair`; review and renewed acceptance share `looper-routes.acceptance`. Resolve them only when needed. Native roles use the same mailbox; Repaired-result review may use the available configured provider, including the repairer’s provider, in independently launched fresh sessions; preserve separate review/renewed acceptance and checks. Disclose repeated/unknown provider/model identity; selected Copilot follows [family-aware controls/proof](copilot.md#planning-and-review), including after settings changes on resume. Explicit task counterpart requirements prevail. No clean-merge gate. Supply applicable invariant/writing policies inline; no outside-file access is required.

Per `run` invocation, read settings once; save each new attempt’s resolved `selection` and `source` (ag.json digest, route, tier). Resume exact saved selections; invocation settings affect new attempts only. Lowered task/repair limits still permit outstanding native-result import before resolving future routes. Status needs no valid current worker settings and never writes progress.

Coordinator state stays in the same queue: `expected_head`, `ready`, `questions`, `processes`, `handoffs`, `integration`, and group/task state. Never edit those fields to manufacture progress.

One coordinator alone writes queue state atomically. Save registered groups, ordered tasks, selected work, worker/result identities, ready order, candidates/bases/result heads, questions/answers and recovery there; artifact outputs are evidence, not a second state authority. Workers return results, never mutate queue, Git-commit, integrate or publish. Preserve shared notebook/backlog/registry/settings ownership.

Each group uses a distinct stable worktree. Explicit session overrides select `.aglite-records/devlog.md`, `ag-dir: .aglite-records`, `auto-commit: off` and `auto-push: off` without mutating inherited `<checkout>/<configured ag-dir>/ag.json`; the coordinator supplies its exact resolved path, and record-directory session overrides never move config. Coordinator adds the exact isolated-notebook marker ignore rule to common Git `info/exclude`, a small shared-local setting required by ordinary notebook ownership; workers need no Git-metadata write. Record ordinary notebook/design/tracker work there. Exclude those records from product integration; root notebook does not collect parallel task rounds. Status locates their records. Preserve established feature/worktree identities.

Coordinator creates only the safe isolated record directory, not a notebook scaffold. Before task work, the task host exclusively renders the ordinary notebook from its asset under [use-lang](configuration.md#discovery-and-validation), with the assigned session UUID and exact observed identity facts; no other setup. Inspect absent/unsafe existing files; never recreate a known missing active notebook. Closeout proves the existing `# → <localized-label> / A-NNN` shape in sequence: first per-ID heading is Ask, second Reply, then the next consecutive Ask; labels express phase meaning without requiring English.

Task prompts assign a generated workflow session UUID equal to the attempt UUID before dispatch. Isolated task hosts leave their exact own marker after ordinary closeout; the coordinator archives it after proved stop, without requiring task-sandbox access to Trash. After proving the task stopped, coordinator may archive only `.aglite-records/.devlog.md.owner` whose session exactly matches that UUID; preserve the open Ask for a fresh task continuing an owner answer. Refuse foreign markers untouched.

### Retained files

`planned/` remains the run-root after preparation. `queue.json` owns progress; `request.md`/`group-*.md` retain request/instructions; `inputs/` holds task snapshots. `attempts/<UUID>/` retains per-dispatch selections, prompts/assignments, identities and available results/transcripts; failed launches may lack results, and native/CLI records differ. `evidence/` retains check logs and process/descendant identities; `inbox/` holds supplied answers/corrections and native results. Resumes reuse successful work; new attempts/checks add evidence, not necessarily one set per task.

Safe claim release deliberately renames `.queue.owner` to `.queue.owner.released-<UUID>`; common Git metadata retains analogous target-claim archives. These are inactive history, not active locks or failed temporary writes. Each acquired/released invocation can add records. Group `.aglite-records/` notebooks/reviews stay outside product integration and may be ignored; clean Git status does not establish that a worktree is disposable. Integration retries can retain extra worktrees.

Default completion retains scratch; only the explicit command/flag under [cleanup](#explicit-cleanup) grants bounded recycling. Preserve historical identities/progress; `.tmp`, released-claim names and completion grant no implicit deletion authority. Explicit cleanup retains only queue/request/group plans in run-root; preserving full history requires avoiding cleanup. Cleanup never removes branches.

## Execute and integrate

`ag.json` `looper-limits.max-workers`: positive integer, default 3. Count groups performing task work; a finished or blocked group frees its slot only after its worker stops. Waiting for integration consumes no task slot. Within each group, fresh ordinary task workers run sequentially through plan → design/tracker when needed → implement → checks/review → closeout. The task must finish its ordinary Reply/next Ask before returning pass; coordinator checks that closeout, commits product changes and reruns declared task checks before advancing. No additional verifier session. A group waits without a slot/worktree until every `depends_on` predecessor has checked integration (`state: done`); status names unmet IDs. New groups use the latest adopted target head, containing checked predecessor outputs. Unsafe target identity blocks new workspace dispatch; existing jobs settle without rebasing. Resume re-proves done/integration evidence before descendants; a blocked ancestor leaves descendants waiting while unrelated work continues. Keep running groups on recorded bases; never refresh them from ongoing integrations.

After the final successful ordinary task, record the exact candidate commit and append the group to the FIFO ready list. Handle simultaneous readiness in group-ID order. Start integration immediately when its lane is free; do not wait for unfinished groups.

Refuse concurrent coordinators for one queue. Hold the target-wide exclusive claim across run roots for every merge/repair/check. One integration attempt uses the latest adopted head. Record each same-branch forward advance only under held claims, no foreign Git operation and retained completed-integration ancestry; adoption never marks progress. Recheck exact target/candidate identities and owner-edit protection at landing. On a compatible advance during checks or landing, carry the checked result (including accepted repairs) into a new latest-head merge attempt; retain superseded attempts/worktrees and rerun combined/included-task checks. A race-refused fast-forward follows the same path without charging a clean retry to the repair budget. Branch changes, rewrites and unknown effects stop the lane. Preserve unrelated target edits; never reset, clean, force or overwrite them.

Merge and run relevant combined checks; record the resulting checked target head before the next merge. Unchanged-contract clean checked merges launch no extra agents. Changed contracts require fresh review/acceptance against original and current text; no new group/final gate follows. Conflict/behavior repair uses an isolated attempt, bounded by `ag.json` `looper-limits.max-repairs` (nonnegative integer, default 2), then independent review, renewed acceptance and affected checks. One repair may overlap task work outside the task concurrency limit. Refuse repair-worker index changes and remaining conflict markers before coordinator staging.

Blocked repair preserves its attempt and blocks its group. Release the lane only after proving all attempt writers stopped and shared Git/target state is safe; then other ready groups continue. Resume the preserved attempt on its saved base, retaining accepted repairs; carry its checked result forward before landing and repeat affected checks/review as needed. Uncertain shared effects stop the lane, while independent task work may continue. A blocked required group prevents completion.

## Native handoff and owner inbox

Host reads pending `attempts/<uuid>/assignment.md` and dispatches through real native tools using its selected model/effort, explicit worktree and complete task context. Observe the worker/descendants stopped and verify ordinary workflow before writing only `inbox/<uuid>.json`:

```json
{
  "attempt_id": "UUID_FROM_ASSIGNMENT",
  "outcome": "pass",
  "summary": "Observed result",
  "evidence": [],
  "writer_stopped": true
}
```

Allowed `outcome`: `pass`, `repair`, `needs_owner`, `blocked`. `repair` is for concrete in-scope findings from a read-only review; missing proof blocks instead of triggering code edits. The result schema applies to worker output; the host adds `writer_stopped` only after observing settlement. Use exact attempt identity and truthful stopped evidence; do not infer success from process exit. Superseded handoffs are no longer pending. Superseding an unresolved native attempt requires host stopped attestation (`answer.writer_stopped: true`); an owner decision alone never proves settlement. Host writes inbox only, never queue. Re-run `agf looper run <run-root>` to import the result; no absent-host native dispatch.

Invalid/malformed native responses or missing `writer_stopped` leave the attempt outstanding and its slot reserved; status exposes the response error. Import a corrected response on the next run only, without same-run retry or inferred stopped proof.

A cancelled ordinary-review handoff nested under a CLI task additionally accepts host-attested `outcome: "blocked", dispatched: false` with no `writer_stopped`, only after verifying no reviewer was launched. A launched reviewer still needs actual stopped proof. Cancellation retains the parent attempt, slot and queue/target claims until either attestation imports; never dispatch a `cancel_requested` handoff. This exception cannot pass review or cancel unrelated native work.

Owner responses use `inbox/answers.json`: `[{ "id": "QUESTION_UUID", "answer": "exact owner text" }]`. Host preserves exact owner text and coordinator imports it on run. Re-reading the same answer is idempotent; conflicting replacement of a saved answer is rejected. Technical blockers may receive a host correction with `"source": "host"`; ordinary answers default to `"source": "owner"`. A `needs_owner` question requires actual owner input and rejects host substitution. No separate answer/decision shell command.

## Questions and recovery

Save questions in affected-group JSON state/status; block that group while independent groups continue. Host passes actual owner answers through the inbox for coordinator persistence. Delegates cannot supply owner-only permission or changed-scope decisions.

Before fresh continuation, reconcile recorded coordinator/worker identities, candidate/base/result identities and actual Git effects; prove previous writers stopped. Preserve unfinished edits/worktrees and evidence. Unknown writer or task effects block the affected group; uncertain shared effects block the merge lane. Unsettled writers retain claims/slots and block new dispatch. Keep live identities in queue using snapshot/batched inventory updates; completed evidence remains under attempts. Never manufacture completion from an exit code, timeout or worker “done” text.

A proved distinct identity at a reused PID permits takeover; unknown identity still blocks. Technical host corrections recheck the exact saved candidate/checks rather than rerun successful task work. Recover coordinator-owned staged `commit_intent` by finishing its parent-scoped commit; reject worker staging without prior intent. A prepared isolated-merge crash preserves the attempt and retries fresh without reset. A checked result already ancestral to current main is recorded once, then later compatible movement is adopted. For an interrupted landing absent from main, require covering target reflog proving it was never applied before carrying forward; a removed result or unknown effect blocks. Missing checked proof never completes a group. No guessed PID signaling, claim deletion or destructive reset. A fresh host uses queue/evidence, not the previous conversation. Process/platform/crash guarantees require actual observations; mocked/unit results alone prove no OS/provider behavior.

## Shell entry — alphabetical

Eligible project initialization [automatically creates a missing `agf` shell function and visibly reports it](setup.md#agf-command-setup); existing bindings remain. Alternatively, explicit `npm install -g <resolved-skill>` registers the zero-dependency package bin. Only these shell commands exist:

- **`agf looper cleanup <run-root>`** — explicitly recycle a completed settled run’s generated worktrees and all run-root extras except queue/request/group plans; root required. Follow [explicit cleanup](#explicit-cleanup).

- **`agf looper run [run-root] [--cleanup]`** — start/resume the queue; host launches it. Only `--cleanup` requests the same cleanup after successful settlement; default retains scratch.

- **`agf looper status [run-root]`** — read saved group/task progress, current tasks, ready/integration state and questions without dispatch.

For run/status, omitted shell root means cwd; cleanup requires an explicit root. Missing `queue.json` errors. Status combines saved progress with a current coordinator observation (`live`, `dead-or-uncertain`, `absent`) and never mutates queue state. `run` exits 0 when complete, 2 when blocked/stopped, 1 on error; successful `status` exits 0. Chat `run-tasks` resolves Current before invoking the shell. No second owner terminal is required. Runtime/package portability is a validation target; do not claim Windows/Linux/macOS proof without actual observations on each OS.

## Explicit cleanup

Only `agf looper cleanup <run-root>` or `agf looper run [run-root] --cleanup` authorizes recycling that run’s recorded generated worktrees and all run-root entries except `queue.json`, the queue-referenced request/group files and their necessary parent directories. Require completed groups/tasks, passing saved integration/check evidence, target ancestry and stopped writers; unfinished, blocked, stopped or uncertain runs retain everything. Hold the same queue/target claims as execution; refuse foreign/live claims, dirty/non-ignored untracked or locked worktrees, active notebook markers, unsafe/current paths and declared-output overlap. Inspect selected paths/identities before movement; unknown ordinary run-root files are included. Refuse unsafe links, active notebook claims and nested checkouts; preserve all branch refs.

Default provider: macOS `/usr/bin/trash`, with accessible same-volume `~/.Trash`; unsupported/missing/inaccessible providers refuse movement. No force, prune, permanent-delete fallback or ref deletion. The final sweep recycles task records, reports, inbox/answers, released queue claims, metadata, empty directories and unknown ordinary files. Keep only queue/request/group plans; default runs retain full history. Old completed cleanup journals also receive this sweep. The active queue claim retires by exact-identity rename directly into same-volume Trash after final persistence. Ignored contents inside a proved generated worktree move with it; list them in the saved inspection.

Optional `queue.cleanup` owns the run/root binding, source/staged/retained locations, inode/device proofs, lifecycle state, timestamps and per-operation intent/outcome. Save unchanged-source-checked atomic intent before each move, Trash call and exact unregistration. A UUID bundle must be observed recoverable at its recorded Trash location before unregistering its exact worktrees. Retry only proved own effects; missing/unknown objects stay blocked, never inferred successful or replayed blindly. Unknown processes retain claims. Never mutate recycled copies. Restored files do not restore Git registration; preserved branches allow rebuilding a checkout.

Manual cleanup exits 0 on complete/idempotently complete, otherwise 1. The run flag acts only after successful settlement: blocked/stopped stays 2; failed runs stay 1 without cleanup. Task success plus cleanup failure reports both truthfully and exits 1; retry with the manual command. After compact cleanup, print the final report only; neither manual cleanup nor later cleaned run repeats recreate report files. Failed cleanup may retain diagnostics for retry. `status` stays read-only without worker settings and shows cleanup/retained paths. Cleaned repeats prove saved completion without starting workers or requiring removed worktrees; incomplete cleanup directs to its manual retry.
