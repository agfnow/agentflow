# Configuration

Host-driven; no hooks or general runners/helpers. Only authorized [initialization](setup.md#standalone-initialization), [looper execution](#looper-execution-exception) and [terminal feature lifecycle](features.md#terminal-cli) use bounded Node runtimes. Before routing, read the startup sections named in [SKILL](../SKILL.md#route-before-records); load other sections before their actions and reuse retained static rules. Reread live ag.json on activation, each later on-record owner message and configuration-dependent delivery. Apply off-record first; coordinator-supplied isolated looper overrides precede ordinary discovery/setup/upkeep. Explicitly authorized off-record product/config edits may proceed without workflow records or automatic upkeep.

## Discovery and validation

Session directory means the startup directory or the destination of a verified Codex/Claude Code `/cd` handoff under [features.md](features.md#directory-transition). Before inspecting configuration/hook candidates, parse and manipulate complete documents locally; expose only required nonsecret fields or hashes/status. Never cat/echo/return complete configuration or hook originals; preserve other properties opaquely. This guard applies before legacy classification and on current-schema reads.

- Configuration is `<checkout>/<ag-dir>/ag.json` for every existing/new project; `.agentflow` is only the default ag-dir. Outside Git use the verified session folder; features use their own checkout, never main's live config. Discover filenames under that physical root without following symlinks; prune `.git`, `node_modules`, `.aglite-records` and nested checkouts (a subdirectory with a `.git` entry). Host discovery uses ordinary tools, no helper/pointer file or depth cap; the bounded feature CLI implements the same canonical discovery without migration. A regular JSON object's effective `switches.ag-dir` (default `.agentflow`) must equal its checkout-relative parent to be a canonical candidate. Integer8, or v8-only switches `target-doc`/`workspace-dir`/`lang`/`ask-names`/`log-verbosity`/`allowed-worker`/`review-policy`/`cli-provider`/`allow-ag`/`away-gates`/`streams`/`auto-reply`/`notebook-ownership`/`large-work-minutes`/`git-timeout-ms`/`completion-cleanup`/`completion-cleanup-interval-days`/`metrics` or `pipeline-roles.cross-check` or old external-profile `tiers`/`family` at any absent/supported stamp, loads [legacy classification](legacy-migration.md#eligibility-and-preflight) before selection/validation. Unknown/newer stamps stop before repair. Resolve present legacy paths and old/new conflicts before candidate-parent matching; proven8 uses safe effective workspace-dir/default. A stamp or stray field alone proves no full-v8 provenance. Validate paths/objects before selection; unrelated bundled/misplaced files are not candidates.

- Select exactly one canonical candidate and no legacy source. Root `ag.json`, and old `.agentflow/ag.json` whose effective ag-dir differs and schema is absent/known predecessor, are legacy sources. Multiple candidates/sources or canonical+legacy stop, even if identical; name paths, never merge/choose silently. Symlinked/escaping paths, named nonregular ag.json and unsafe root/default legacy positions stop. Unmatched/malformed files or unresolved symlink directories with no selectable config require routing/absence reconciliation before setup; never silently initialize beside possible history. With no configuration/history ambiguity, use defaults/setup. No STATUS configuration or unrelated content sweep. A misplaced current-schema file requires reconciliation, not automatic relocation.

- Require a JSON object; switches must be an object if present. Other absent keys use defaults; required saving-mode follows migration below. Ignore // keys for behavior; preserve unrelated properties and external-workers. Validate selected worker fields and recognized planning/review switches below when needed. Before validation on every host read, recognized legacy fields/input follow [legacy migration](legacy-migration.md); known lower agentflow schemas or `aglite-5`, any `skip-asker`/`skip-run`/`skip-wip`/`skip-plan` key (even at current schema), review-order `external-first`/`native-first`/`host-only`, missing switches.saving-mode (including at current schema), or legacy location requires [automatic migration](upkeep.md#automatic-migration); require the target schema afterward if supplied. Unknown/newer schemas stop before repair or dependent work. Invalid JSON, types or recognized values stop dependent work with path/key/error; never reset. Owner instructions override settings without persisting them unless requested. Other missing keys need no write. An unresolved Ask binds the session to its owned notebook: changed routing or notebook selection requires owner-authorized handoff/relocation reconciling work and claims. Apply other switch changes there. All feature lifecycle commands route under [features.md](features.md) before root-notebook binding/recovery; never inspect or alter its notebook/archive/claim, even this session’s. Its state is irrelevant to lifecycle permission. Existing unrelated work remains bound separately; these commands neither close nor transfer it. A verified lifecycle /cd handoff may bind the destination feature notebook without checkpointing, releasing or recovering main; the old root claim/work stays untouched for later ordinary main recovery.

- Update only explicitly requested properties or documented migration mappings after checking the source is unchanged; atomically rename an adjacent temporary file, then reread. Create new files exclusively; never replace existing configuration with the template. Target schema is the integer schema-version in this installed skill's [bundled template](../assets/.agentflow/ag.json), not the package version or a remote latest release. Resolve it before migration; versions above it stop. Increment that integer by one for each schema revision and document its mappings/proving examples; preserve // keys and unrelated worker metadata. Maintain ascending switch names in the bundled template. Configuration selects settings only for already-authorized work.

- Nine Boolean switches accept exactly on|off. Defaults: omit-asker on; inline-reply off; omit-run on; omit-wip on; gate-design off; gate-tracker off; auto-commit on; auto-push on; saving-mode off. Require switches.saving-mode on|off: setup/migration adds off only when absent; preserve valid existing values, reject invalid values before effects. `plan-mode` accepts must|optional|off, default optional.

- use-lang accepts a nonempty locale tag (case-insensitive language plus optional script/region, hyphen or underscore). Default: observed OS locale, then en-us. Inspect platform locale settings, then LC_ALL, LC_MESSAGES or LANG, discarding encoding/modifier and C/POSIX; normalize underscores to hyphens and lowercase. Render all newly authored/displayed human text in this locale, including hardcoded template/scaffold strings and host presentations of tool results; English prompts/assets define meaning, not literal display. This includes STATUS/field and Ask/Reply labels, RUN/WIP Event/Checkpoint and bullet labels, Questions/None, notices, invariant-change/relocation headings, receipt Updated, and design/tracker headings/placeholders. STATUS field names are human labels, not fixed machine tokens: for zh-TW, Project→專案, Notebook→筆記本, Checkout→工作目錄, Branch→分支, Current→目前工作, Proven→已驗證, Next→下一步, Archived eras→封存紀錄; feature-only Stream→功能, Cleanup→清理, Session→工作階段. Reuse existing correct localized labels; never retain English Checkout as a technical-token exception. Input language never selects a locale; only explicit owner response/target-language instructions override it. Preserve original input/quotes/history and established artifact languages; keep machine IDs/prefixes, commands, owner syntax (`ans:`, arrows, `+`, markers), JSON keys/values, tracker enum values, paths, timestamps and structural punctuation exact. Raw tool/machine output and code identifiers retain source identity. No translation service, separate lookup asset or helper; rendering grants no configuration-write authority. First initialization substitutes the detected default for the template's en-us. Standalone `agf init` maps other Chinese variants to zh-tw and other valid locales to en-us for output/new config; existing config remains unchanged (see [setup](setup.md#standalone-initialization)).

- ag-dir defaults to .agentflow: a nonempty checkout-relative path without .. or symlink escape. notebook-name is a basename under ag-dir. If absent, derive `<stem>.devlog.md` from the physical checkout-root basename (verified session directory outside Git): lowercase ASCII, replace runs outside a-z/0-9 with `-`, trim `-`, take the first 32 characters and trim trailing `-`; empty stem → `devlog.md`. Example: `a002` → `a002.devlog.md`, `My Project!` → `my-project.devlog.md`. Reject empty names, either slash, absolute paths, control characters, . and .., .owner suffixes and existing directory/marker collisions; resolve notebook and ag-dir physically without checkout escape. An absent key derives this default in memory without adding it later. Fresh configuration creation persists the derived name; preserve existing settings and notebooks, never silently rename or replace history. Explicit notebook selection may use another safe path; feature routing takes precedence. Resolve physical paths before ownership; explicit ag-dir edits relocate config under [upkeep checks](upkeep.md#automatic-migration), never records implicitly. Unresolved notebook binding still requires owner handoff.

- Except bundled assets/.agentflow/, .agentflow/<suffix> means <ag-dir>/<suffix>, including ag.json. Artifacts/features follow ag-dir; the root notebook follows <ag-dir>/<notebook-name>. Link established records rather than moving them for a setting change. Archives remain adjacent; STATUS names their actual paths. Optional local project rules, backlog and the default system registry are checkout-root `<ag-dir>/{rules,backlog,sys-invariants}.md`, independent of notebook/feature-record location; established authoritative records are reused, never implicitly moved.

Terminal feature notebook writes support English/Traditional Chinese; unsupported locales stop before mutation for host rendering, without English notebook fallback. Raw terminal diagnostics may be English. This bounded CLI rendering limit does not change host locale obligations.

Optional top-level `default-editor` is a nonempty executable name/path, default `vscode` (runs `code`). Feature CLI `new-feature --open` passes its notebook as one argument with inherited terminal IO; other values run literally, without shell parsing or embedded arguments. Invalid values stop before feature mutation; launch failure warns after successful preparation. Missing values use the default without migration or a schema change. Example: `"default-editor": "vim"` or `"default-editor": "/opt/my editor/bin/edit"`. This setting grants no automatic opening or installed-binding update.

## Automatic migration

Apply [upkeep migration](upkeep.md#automatic-migration) only when a documented legacy schema/key or relocation requires it; unchanged current input causes no write. Off-record/read-only/delegated/isolated contexts defer automatic writes; compatible legacy mappings may be interpreted in memory; deferred missing saving-mode uses off, invalid values still stop. Explicit off-record config edits retain their own authority without workflow records.

## Session release check

Only the owner-facing host checks releases on on-record activation, including idle. Read optional top-level `ag.json` `next_update_date`: null/missing means due; otherwise require a real UTC calendar date `YYYY-MM-DD`. Observe today in UTC before comparing; never use the local calendar date. Before the due date, skip all release network requests across sessions. On/after it, query the latest stable [Agentflow release](https://github.com/agfnow/agentflow/releases) once; no other feed, updater, hooks, polling or background work. Delegates/isolated looper sessions, off-record exchanges and explicit read-only constraints do neither checks nor date writes. An invalid date is a disclosed upkeep error; preserve it and continue unrelated work.

After the lookup attempt, including failure/no release, set `next_update_date` to the current UTC date plus two calendar days, preserving other keys under the atomic unchanged-source/symlink-safe configuration rules. This narrow scheduling write is allowed during idle without notebook/claim/history creation; an absent config outside setup stays absent and uses only a session-local check guard. A changed/unsafe/unwritable config defers the date write, reports the limit and permits no repeat lookup in that session. No retry on lookup failure; normal work continues. The date is lookup scheduling only, never installation consent. Missing new keys use this due behavior; current-schema configurations need no schema bump for optional scheduling metadata.

Agentflow 9 is the stable successor to the aglite beta. Read installed name/version from resolved SKILL.md metadata; package version, if present, must agree. Use only `agfnow/agentflow` stable releases: installed aglite is eligible for its Agentflow 9+ successor, never Agentflow 8.x; installed Agentflow 9+ compares semantic versions within that product and never downgrades to 8.x. Schema version is unrelated. Unparseable identity or no eligible newer stable release yields no update. A newer eligible release requires a short installed/latest notice and release link before the receipt, even with inline-reply off; an otherwise idle activation may show it without notebook access. Offer to prepare the update; replacement approval follows saved Questions after concrete preparation. Routine lookup results stay in existing evidence or idle session context, without new idle records.

Installation preparation/replacement follows [approved installation replacement](upkeep.md#approved-installation-replacement); explicit owner approval is required before replacement, including beta-to-Agentflow 9.

## Switch effects

[work’s one-task fast-lane](work.md#task-modes) overrides ordinary creation, delegation, review and RUN/WIP rules without changing these switches; its retained obligations, explicit owner requirements and configured gates prevail. The skip-review command overrides ordinary review for one task only; other steps/settings remain. Advisor selection adds no switches or dispatch authority. Before deciding record requirements or authoring/revising plans, read [planning](planning.md); before task edits enforce plan-mode/gate-design conflicts and required approval, and before final delivery enforce gate-tracker. These settings create no idle/Q&A records.

- omit-asker on leaves Ask headings unnamed; off adds (<identity>) after the round ID. Use git config user.name in the checkout, then the OS account username; if unavailable omit it. Replace parentheses/control characters with spaces and collapse whitespace. Apply only to new Ask headings, never rewrite history; round parsers accept the optional suffix.

- inline-reply off uses [delivery's exact Updated receipt](delivery.md#notebook-and-delivery); on displays the complete saved Reply after verified closeout/delivery. For `append-rounds`, follow [batch transitions and output](batches.md#append-rounds). Only an explicit request to display answers in chat/terminal overrides saved-only answers; “show me”, output examples and requests to change future output do not. Explicitly displayed answers and `inline-reply: on` still end with the two-line receipt. Required actual feature handoffs prevail; hypothetical handoffs stay saved. Required invariant/backlog notices supplement the receipt or handoff. Neither setting suppresses the saved answer or necessary unfinished-work reports.

- omit-run on omits `[RUN]`; off uses [work's milestone format](work.md#execute-and-checkpoint). Retain evidence/decisions under [Round evidence](session.md#round-evidence), with lifecycle/recovery state in Current/tracker.

- omit-wip on omits `[WIP]`; off uses [work's checkpoint format](work.md#execute-and-checkpoint). At ten-minute, interruption and context-reset boundaries, retain recovery in tracker/STATUS: finished/remaining work, actual handles, checks and next action. Recover from the latest applicable record. Log switches never suppress input, Reply, questions, ownership or checks.

- saving-mode on loads [saving mode](saving-mode.md) for minimum sufficient prose/records and reuse; off preserves normal behavior; absent follows migration (effective off only while writes defer). It changes no authority, safeguards, required deliverables/checks/review, model/effort or routes.

- plan-mode optional uses ordinary design/tracker criteria; must requires both before authorized task edits; off prohibits new designs, permits needed trackers and preserves existing contracts. Before task edits, off + gate-design on stops dependent work as a named settings conflict requiring an owner choice. Task modes/explicit instructions, plan-only stops and gates prevail; no setting-driven idle/off-record/setup/lifecycle/Q&A/batch records. Read [planning modes and gates](planning.md#planning-modes-and-gates) before applying these rules, including fast-lane and isolated-task exceptions.

- plan-order accepts 3ways|external|native|host, default external for complex planning. Before already-needed planning (including advice/recommendation reports/grouping), read [planning routes](review.md#planning-routes) for proportional host selection, explicit/configured 3ways, worker controls, fallback and final synthesis. Task modes, requirements, contracts and gates prevail; settings create no work, plan, advisor stage or implementation authority.

- Result-review requirements and one-task exceptions follow [work](work.md#records-and-review); routing follows review.md.

- review-order accepts external|native|host, default external. Before already-required result review, read [result-review routes](review.md#result-review-routes) for transport order, diversity, controls/fallback, independence, explicit requirements and bounded disclosure authority. Review requirements/waivers remain in [work](work.md#records-and-review); settings create no review stage.

- gate-design on requires a saved concrete design and owner approval before implementation; off adds no checkpoint. Prior explicit approval of the same design suffices; material changes need renewed approval. Apply [planning modes and gates](planning.md#planning-modes-and-gates), including the plan-mode off conflict and independent-work exception; empty/default answers never approve.

- gate-tracker on, when a tracker exists, requires all execution/checks/review passed and owner approval of the concrete checked result before final Reply/release, delivery commit or push; off adds no checkpoint. Retain the open round/claim and awaiting-approval state. Read [planning modes and gates](planning.md#planning-modes-and-gates) before this pause, especially merge-feature prerequisite integration commits, feature-only records/claims and post-approval continuation.
