## agf command setup

During eligible first-time main/root setup and its interrupted recovery, after Git choice and notebook claim, select only the owner's configured login shell (OS account setting, then `$SHELL`); check `agf` in fresh interactive login and non-login instances of that shell. Other shells require explicit owner selection. This setup authorizes the bounded binding below without another approval; ordinary activation/idle, features, delegates and isolated loopers do not provision. Inspect executable/function/alias resolution and content before use; preserve valid bindings. Foreign, stale or conflicting definitions require diagnosis, never automatic replacement. Never execute an unverified same-name command.

If absent, verify Node >=20 in those shells and the resolved installed skill's regular `scripts/agf.js`; never assume an installation path, install dependencies or replace the skill. Generate the function with `node '<resolved-installed-skill>/scripts/agf.js' shell <zsh|bash|powershell>`, using correct literal path quoting. Review the emitted function before appending it with ordinary host tools; never evaluate generated or ordinary CLI output. This command prints only, with no installation authority of its own. Use the generated function rather than duplicating wrapper logic in prompts.

For zsh use the actual `$ZDOTDIR/.zshrc` (home when unset); for bash use `.bashrc` and the first existing login file in `.bash_profile`, `.bash_login`, `.profile` order, creating `.bash_profile` only if none exists. For selected PowerShell inspect its actual profile/loading in both modes. Inspect startup loading first; change only files needed for missing modes and never duplicate a function on recovery. Resolve safe user-owned paths, reject symlinks/foreign ownership and multi-link files; preserve existing bytes, mode/metadata and final-line boundaries, check unchanged sources, create absent files exclusively and atomically update existing files. No hooks, installer/helper, npm, PATH edit or system-wide write. Unsupported shells, unavailable prerequisites or unsafe/unwritable files leave provisioning blocked; disclose the reason and exact direct Node command, without claiming success.

The function forwards literal arguments/stdout/stderr/exit and uses a private temporary `AGF_CD_FILE` solely for successful feature destinations under [terminal transition](features.md#terminal-directory-transition). Only that validated channel may change caller cwd; never capture/evaluate ordinary output as a directory. Non-feature commands forward directly without a destination file or cwd change; looper output stays visible. Dispose the feature destination file using macOS Trash or Windows direct deletion under the narrow feature exception; when Trash is unavailable retain/report the channel instead of permanent deletion. Preserve cwd on unsuccessful commands. Existing functions/aliases/executables are never automatically upgraded, including during initialization; diagnose stale bindings and request an explicit owner upgrade instruction before replacement. An explicit upgrade uses the reviewed generated function with the same safe-file checks.

Verify fresh login and non-login interactive shells resolve the exact function and Node/entrypoint, then invoke `agf` without arguments: expect launcher's usage on stderr and exit 1, unchanged cwd and no task execution. If verification fails, report failure and exact partial changes; preserve originals, reconcile before retry and never append twice. On creation, visibly notify the owner in configured locale even with `inline-reply: off`, naming changed files and how to load them or open a new shell. Save the outcome in the setup round; an existing terminal is not automatically refreshed. A matching pre-existing binding causes no write or routine notice.

## Empty bootstrap

Only eligible first setup or explicit main-rooted `new-feature` preparation authorizes this operation, even with `auto-commit: off`; explicit commit prohibitions prevail. This section alone grants no setup/adoption or notebook access during lifecycle work. Ordinary activation/work, merge and drop gain no bootstrap authority.

Reuse a verified existing HEAD without another commit. Otherwise require the verified non-bare checkout, a valid unborn branch, no refs, Git locks or in-progress operation; detached/broken HEAD, other history/refs or unexplained errors stop. Preserve staged entries and working/untracked contents; never stage files or configure identity for bootstrap. Run `git commit --allow-empty --only -m "chore: initialize repository"` through ordinary Git controls, then verify parentless empty HEAD and preserved contents before continuing. Failure or unexpected effects retain state and stop setup/preparation; inspect actual HEAD before retry, never amend/reset or claim completion. Retain pre-existing-content exclusions for [first delivery](delivery.md#git-delivery) and recovery. No remote, push or publication authority follows.
