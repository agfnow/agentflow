# Browfield — optional brownfield development

Select only for an owner-requested eight-step procedure or a named material need for structured discovery/regression protection within authorized feature work in unfamiliar existing code. An existing repository alone never activates this path; exclude greenfield creation and standalone audits. Once selected, follow all eight gates below. Agentflow remains the workflow: preserve its configuration, routing/ownership, Task modes, record-creation rules, planning/review routes, gates and delivery. This reference supplies domain knowledge/proof gates, not another workflow, advisor, runner or permission to deploy, destroy data or send externally. Work requires a live host.

## Intake and recovery

Use the recovered Ask/records; establish outcome, affected scope, constraints and required checks from supplied input and repository evidence. Ask only for missing material decisions. Preserve unrelated work. Advance autonomously through passed gates; an owner-requested guided walkthrough pauses at each gate for explanation. Pacing never overrides approvals or supplies missing authority; it adds no persistent mode or configuration.

Recover the stage, last proven gate, decisions/questions, source state, evidence and actual handles through Current/tracker before dependent work. Reuse proof only while relevant source, inputs and environment match. A stale checklist or suggested answer proves neither completion nor approval; re-establish missing evidence and disclose the interruption without inventing history.

Keep contracts in the existing design when needed, recovery in Current/tracker and useful proof under [Round evidence](session.md#round-evidence). Create records only under normal agentflow rules, including plan-mode and fast-lane; no standalone notebook, per-stage report or second specification. Save each stage outcome in existing evidence before advancing: finding, supporting source/check, material uncertainty and pass/blocked with reason. Confirm the saved outcome is adequate; an intention to write later does not pass. Reopened gates append corrected findings without rewriting history. Necessary stage evidence remains required when RUN/WIP are suppressed.

## Eight gates

Stages iterate when facts change. Advisor links reuse canonical methods: select only the roles needed for named material questions under [advisor rules](ag.md), using the host or permitted workers. They never require eight advisor runs. With fast-lane, apply the concrete stage checks directly without loading advisor prompts; retained explicit requests and ordinary task-mode precedence still apply.

1. **Discover.** Establish a bounded map of the affected ordinary user journey, edit locations, dependencies, conventions, tests/docs and supported check commands. Reuse [codewalk](advisors/codewalk.md) for unfamiliar paths/data flow; do not map the whole repository. Gate: enough verified source knowledge to trace the affected journey; unknowns and unexamined areas saved.

2. **Reverse engineer.** Trace affected rules through source, tests and authorized representative stored data; label claims documented, observed, inferred or owner-confirmed, with source locations. Reuse codewalk's facts/inferences discipline and [requirements](advisors/requirements.md) for material intent conflicts. Gate: important rules supported or explicitly uncertain; conflicting behavior resolved before dependent changes, without treating existing bugs as approved intent.

3. **Assess impact.** Identify direct edits and indirect effects on shared calculations, callers, persistence, compatibility and failure/recovery. Reuse [explore](advisors/explore.md) for consequential alternatives or cross-subsystem uncertainty. Rank concrete risks by relative priority with a short consequence/likelihood reason, affected behavior and planned check; an ordered list suffices. Gate: preserved behavior, affected boundaries and prioritized checks identified; new dependencies or contradictions reopen impact and the contract.

4. **Establish baseline.** Before production-source edits, run relevant existing checks and retain commands, source identity, outcomes and known failures. Add and run targeted characterization for changed/high-risk existing paths. Use [spike](advisors/spike.md) only for a named falsifiable unknown that reading cannot settle. Gate: relevant old behavior reproducibly protected; missing required proof blocks dependent edits while independent authorized work continues. Observed bugs need an intent decision, not blind approval through tests; whole-system coverage is unnecessary.

5. **Specify and plan.** Reuse [spec](advisors/spec.md) for a named contract gap and requirements for unresolved intent. Under ordinary design/tracker creation rules, define scope/exclusions, acceptance examples, preserved invariants, failure/rollback, dependencies and work order in the existing contract; separate requirements from proposed defaults. Gate: material decisions and required approvals resolved. Existing authorization suffices without a separate gate; continue independent authorized work around blocked decisions.

6. **Implement.** Use ordinary agentflow execution for small scoped changes consistent with existing architecture; inspect diffs and run affected checks, preserving unrelated work. Gate: agreed behavior and failure paths implemented without incidental refactoring. New facts reopen impact/contract before dependent edits; no advisor substitutes for implementation.

7. **Verify.** Exercise new behavior, old journeys, integration/persistence and relevant trust/data boundaries. Map every acceptance criterion and applicable invariant to observed evidence, failure or an explicit gap; inspect unintended diffs. Use [ordinary result review](review.md#inspect-the-finished-result); [acceptance](advisors/acceptance.md) can supply the same matching pass, while [security-scan](advisors/security-scan.md) addresses a named trust-boundary question. Separately inspect saved gate outcomes and available sequence evidence: disclose late/missing records; finished headings or passing product checks never establish timely process compliance. Gate: required checks/review pass without weakened tests; missing proof remains blocked, limited coverage is not zero regressions.

8. **Preserve.** Follow [documentation maintenance](product-docs.md), invariant/backlog rules and normal notebook/delivery closeout. Retain affected docs, discovered rules, decisions, tests and recovery once in their established owners; use [product-docs](advisors/product-docs.md) only for a named documentation gap and [learn](advisors/learn.md) for requested learning, repeated failure or a serious unexplained incident. Gate: the next human/host can find outcome, evidence, unresolved risks and next action without reconstructing chat. Keep feature results and process-compliance findings distinct in existing evidence; acceptance readiness is not actual human acceptance.

## Decisions and failures

Use established answer locations/stable question IDs for material business ambiguity, conflicting affected guarantees, changing suspected buggy behavior, consequential scope/architecture changes, missing permission/access or unverifiable critical behavior. Provide evidence, options/consequences, recommendation/reason (or none), blocked scope and resume point; apply normal answer routing. Defaults, silence and agent answers never approve owner decisions. Ordinary reversible implementation/check choices remain autonomous within scope.

Inspect a failing check and make an evidence-backed correction before retrying. Honor an existing applicable repair budget; otherwise stop after two unsuccessful repair attempts for the same failure unless the owner changes the budget. Retain last failure, commands and next safe action; inspect saved identity before retrying an external write with unknown outcome. On stop, settle task-owned processes and save recovery under agentflow; never imply host-absent progress. Final answers follow the configured destination, with decision-changing gaps and required human actions; missing required proof is never a pass.
