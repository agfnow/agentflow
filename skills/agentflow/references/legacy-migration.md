# Agentflow 8 project migration

Demand-load after a recognized legacy trigger or explicit migration request; never scan startup/history/integrations on every activation. One-way project-format maintenance using ordinary host file/Git tools; no converter, old installer execution, runtime/helper, compatibility layer or installation replacement. [Configuration](configuration.md#discovery-and-validation), [upkeep](upkeep.md#automatic-migration), [session](session.md) and [delivery](delivery.md) retain authority.

## Eligibility and preflight

- Only the owner-facing host applies automatic migration. Off-record, read-only, delegated/isolated sessions and lifecycle root-record exclusions prevail; compatible settings may be interpreted in memory. Explicit off-record configuration edits retain their separate authority without workflow records. No blanket global cleanup, nested-project/dormant-feature migration, task execution or worker dispatch follows.

- Validate the selected source before effects: regular nonsymlink JSON object, no duplicate keys, object switches, safe physical checkout/session root and paths. Integer schema `8` requires a verifiable Agentflow-v8 shape/provenance, e.g. coherent v8-only switches and per-profile tiers matching known v8 contracts; `8` alone is insufficient. V8 fields/profile shapes under absent or supported agentflow stamps require present-field mapping/reconciliation, never silent treatment as unknown metadata. Without proven v8 semantics, infer no absent v8 defaults, priority inversion or profile conversion. Resolve legacy paths/conflicts before configuration selection. Supported lower agentflow stamps still use upkeep to reach the installed target; schema-less input gains no inferred stamp. Schemas above the installed [target](configuration.md#discovery-and-validation), below8, unknown formats, malformed values or uncertain old-field meaning stop dependent work without reset.

- Use configuration discovery/collision guards. Root `ag.json` is the legacy8 source; effective directory is `workspace-dir` or `.agentflow`. A sole v8 configuration already in that exact parent migrates in place. Other/multiple sources, canonical-plus-legacy, symlink/escaping/nonregular candidates or unresolved possible history require reconciliation; never choose/merge silently or initialize beside them. Supported agentflow schemas and obsolete current keys use upkeep's actual mappings. Current-schema input with valid saving-mode and no pending mapping/integration/STATUS conversion is a protected-write no-op.

- Map all values and planned outputs in memory first. Establish notebook routing, exact archive association, current ownership and old writer/integration safety before protected config/hook/startup/STATUS-conversion effects. Missing mapping, ownership or integration decisions leave those transformations unapplied. Ordinary safely routed claims, input, Questions and recovery evidence remain allowed; retain legacy-compatible Open/Next recovery pointers until projection is authorized. A blocked8 transition keeps the round open, with no new-format Reply/nextAsk claiming migration completion; use existing answer locations with inline-reply off. Without a safe record destination report refusal in chat, never invent a notebook.

- Apply session identity/claim/capture/gates normally. Read old STATUS only after ownership, except already-permitted idle screening; never probe a lifecycle root notebook. Preserve old `.tmp/agentflow-owner-<sha256(path_key(notebook))>.json` and its version/root/notebook/Ask/host/session/token/state. Enabled old ownership with an unreleased/conflicting owner, or populated unowned Ask requiring handoff, blocks; preserve live-writer/lock evidence. No token conversion, adoption or clearing by age.

- Active old `.worktrees` streams or pending/started `plan-NNN` queues, with or without generation envelopes, block dependent transition until settled on v8 or explicitly handed off. Preserve stream/queue/completion/receipt/control files, including hidden `.tmp` recovery evidence. Matching schema numbers grant no queue compatibility; never rename, convert, replay, reopen or automatically clean them. Old stream pointers grant no current `.wts` lifecycle authority.

## Configuration mapping

Preserve property order, unknown properties/`//` comments, unrelated metadata and valid choices. Validate old values; equivalent old/new mappings collapse, differing values stop. Remove only mapped/explicitly retired keys; stamp the installed target schema only after the complete mapping is viable. Require switches.saving-mode on|off: validate before effects, append off only when missing, preserve existing on/off; invalid values stop. Add no unrelated defaults (`native-workers`, `looper-routes`, dates, etc.). Settings do not themselves grant work authority.

- `workspace-dir` → safe checkout-relative `ag-dir`; no record relocation. `target-doc` → persisted safe `notebook-name` only when its existing physical parent is effective ag-dir. Other paths, forwarding/rename cards or ambiguous history require routing selection; never create/move/rename a notebook to fit the mapping.

- `lang` → validated `use-lang`: normalize actual locale tags to lowercase/hyphens; ambiguous free-form names need a decision. `ask-names` on/off → `omit-asker` off/on; proven established v8-template context with absent ask-names has old on, so materialize off. Retain valid `inline-reply` on/off; current receipt mechanics apply.

- `log-verbosity` all/wip/off → `omit-run`/`omit-wip` off-off/on-off/on-on. Absent old log-verbosity means all: explicitly preserve off-off. Log suppression never removes evidence/capture/recovery obligations. These old-effective-value mappings are required, distinct from pinning unrelated new defaults.

- `away-gates: on` retires with notice under current owner-only boundaries. Off/absent previously gated consequential work only; current design/tracker gates have broader scope. Preserve an existing authoritative exact replacement, otherwise stop for an explicit choice before adopting broader global on or accepting a current policy. Never silently broaden or discard old approvals. Do not infer on from the current host: proven Codex-template on is safe; Claude-template off is not an automatic global-on conversion.

- `allowed-worker` containing the complete unique external/internal/host set retires; subsets retain hard executor restrictions pending an authoritative replacement. `review-policy: prefer-independent` retires; require-independent remains a hard decision, never weakened to fallback. `cli-provider: on` retires; off's host-family restriction requires reconciliation. `allow-ag: on` retires; off/ask prohibition/approval intent needs a replacement. Retain restrictions until resolved; absent new roles/default routes grant no permission and are not equivalents.

- `streams: ask|always` retires with notice that features now require explicit lifecycle requests; off retains no automatic creation. `auto-reply: off` retires; on retires with notice that suggested defaults no longer approve. `notebook-ownership` retires into mandatory current claims, with notice when old off/absent; retain old metadata.

- `large-work-minutes`, `git-timeout-ms`, `completion-cleanup`, `completion-cleanup-interval-days` have no ordinary equivalent. Disclose retired duration/decomposition, timeout and retention behavior/nondefault operational intent; preserve evidence and stop if an actual standing constraint cannot be met. Retire known `metrics` with meaningful notice. Never repurpose `next_update_date` as cleanup scheduling.

- Preserve valid `pipeline-roles` tiers best/better/basic/cheap. Equal cross-check/acceptance may collapse to acceptance; unequal, disabled/off or custom selected roles require a decision, never silent enabling/remapping. Current final-audit uses acceptance; do not manufacture a final-audit role. For proven v8 input, materialize absent `pipeline-roles.threeways: better` (create its object if absent); preserve explicit valid tiers. Disclose that current threeways also tiers unadvised planners/challengers. Other missing roles inherit only when no predecessor-effective value/restriction is lost.

- Move each old external profile's tiers into extensible shared `model-family` catalogs; profile references that catalog. Explicit old codex family → openai, claude → claude; retain verified other families. Infer absent family only from verified old rules: all four parsed model names gpt-* → codex, all claude-* → claude; otherwise reconcile. Preserve exact model/effort strings, profile IDs, command arrays, metadata and stable order. Conflicting existing catalogs or differing same-family tiers stop; never collapse distinct profiles by substitution. Valid integer priorities1–5 → `6 - oldPriority`, preserving ordering/ties; other values require reconciliation. Validate actual selected pairs/transport only at dispatch; no probe for unused catalogs or unsupported selected-pair substitution.

- Apply [upkeep mappings](upkeep.md#automatic-migration), including obsolete keys at current schema, conflict stops and required saving-mode; real skip-wip: off retains omit-wip: off. Resolve the target from the installed template; never from a remote latest release. Preserve unrelated catalogs, workers, looper choices and scheduling metadata; release lookup/date rules remain separate.

## Hooks and startup

During a migration, inspect both existing project `.claude/settings.json` and `.codex/hooks.json` regardless of the active host, plus the effective Git pre-commit. Inventory every matched authorized unit and its planned/observed step in the existing recovery evidence; verify all inventoried surfaces after apply. An uninspected named surface or remaining owned unit prevents completion; no active-host-only shortcut. Inventory only encountered/named integration surfaces needed by this migration. Resolve effective Git hooksPath and common-dir/worktree identity, not merely `.git/hooks`; establish project ownership and active dependent writers. Global/shared hooksPath, global CLI configuration, shell functions, installed skills/plugins and cross-project dependencies need separately established scope authority. No project migration implies that authority. Known incompatible unresolved integration blocks dependent activation and successful-upgrade claims; untouched loaded hooks may require host restart.

- Project JSON surfaces are `.claude/settings.json` and `.codex/hooks.json`: `hooks.Stop`/`hooks.UserPromptSubmit` entry arrays containing `hooks` arrays of command objects. An owned unit requires exact `type: command` and command grammar `node <path-token> --host <matching claude|codex>`, no extra shell tokens. Accept one single-quoted shell literal (embedded apostrophe encoded `'\''`), double-quoted token or bare token only when literal interpretation is verified; reject expansion/operators/wrappers. Verify full installed script identity or complete `/skills/agentflow/scripts/stop-hook.js` identity, including alternate-host/relocated installation provenance; basename/substring is insufficient.

- Remove only verified owned command objects; retain foreign siblings, entry/hook metadata, keys/order and unrelated semantics. Remove an empty enclosing entry/event only if no foreign metadata/semantics is lost; otherwise retain its residual structure. Compare parsed original-minus-owned-unit with expected/actual output. Never delete the whole host configuration or assume it contains no secrets. Malformed/ambiguous registrations stop protected effects.

- Whole-file Git guard ownership requires exactly five LF-split lines, including final empty: `#!/bin/sh`; `# agentflow devlog-guard — blocks committing root devlog.md on a non-default branch (I-039).`; `# Installed by install-hook.js; remove with: node install-hook.js --project --off`; `node <literal-path>` to verified full `/skills/agentflow/scripts/devlog-guard.js`; empty. Preserve original in backup, then Trash the exact owned file. A mixed hook permits only a proven contiguous marker/invocation unit with exact script identity and bounded semantics; preserve all foreign bytes and executable mode. Unknown wrappers, modified/unbounded blocks or symlinks require a decision. Never execute old installer/helper to discover signatures, create fixtures or remove hooks.

- Correct proven project-owned old activation/manual-capture/writer directives within automatic migration authority: replace only their owned unit under [canonical AGENTS adoption](setup.md#agents-adoption), including current named-skill activation/shared-project-rule/local-rule pointers. Preserve unrelated owner instructions; ambiguous ownership/meaning requires a targeted decision. No redundant approval for an unambiguous authorized project correction; no wholesale startup-file rewrite/global cleanup.

## Apply and recover

- Before the first protected effect, retain exact originals and every planned output with source/destination identities, modes, newline convention and before/expected-after hashes in one private persistent task-owned directory outside every Git worktree and active config discovery. Default: verified physical home `.aglite-backups/<UUID>`; reject symlinks, unsafe ancestry, collisions or shared/unowned destinations; exclusively create restrictive directory/files. If unavailable, resolve a safe location before effects. Configuration as well as hook files may contain secrets: inspect only needed nonsecret fields, manipulate opaque properties locally, and never print/send raw originals or copy them into tracked evidence. No extra backup-manifest product.

- Existing canonical round evidence holds only safe backup paths/hashes, step states and exact notebook/Ask identity; link it explicitly from Current/tracker Recovery before effects. Preserve authorizing input/unfinished threads there, honoring legacy Ask links. Ordinary records do not excuse missing private originals/planned outputs. For explicitly off-record edits retain recovery privately/session-locally without creating workflow records.

- Recheck physical source/destination identity, unchanged source bytes, ownership and relevant claims before each effect. Apply proven project hooks/startup units first, then canonical configuration relocation/key conversion, then localized STATUS projection. Have complete mapped output before writes. Reject destination collisions/overwrites or a tracked config becoming ignored; safely create needed parents. Relocation uses no-overwrite move and verified source absence/destination original bytes, then exclusive adjacent temporary file and atomic replacement for mapped keys; in-place edits likewise use atomic replacement. Preserve modes/newlines, reread and compare actual output after every effect. No template replacement, record moves or foreign staging changes.

- STATUS alone projects observed Project/Notebook/Checkout/Branch/Current/Proven/Next/Archived eras under current locale/delivery rules. Preserve every unfinished Open/Artifacts/Next/Streams authority/recovery pointer through canonical Current/tracker links. Old config/test display survives in safe original evidence, not authoritative STATUS. Never invent feature Stream/Cleanup/Session identity or revive retired work. After normal capture, compare all non-STATUS bytes immediately before/after this rewrite; separately account authorized capture, Reply and nextAsk appends, never claim whole-run body equality.

- Preserve Ask/Reply/RUN/WIP/history/archive bytes, IDs, unanswered questions/answers, provenance and existing links outside separately authorized capture/appends. Recognize historical left-arrow Reply as existing history; only new phases use current right-arrow format/locale. Preserve existing archive association/bytes; old `x.archive.md` versus `x.devlog.archive.md` ambiguity requires explicit association/routing before archive operations, never a second archive, implicit rename or broken historical links.

- On interruption read the exact Current/tracker-linked evidence first, verify notebook/Ask and backup/source/destination identities, then compare live bytes with both original and expected-after hashes per step. Reuse verified already-applied steps once; source absent plus matching destination may resume relocation edits. Dual sources/destinations, unrelated modifications, foreign claims, missing proof or changed backups stop dependent work; never replay effects, guess an Ask directory, clear claims or call an unverified upgrade complete. Preserve partial state, live handles and exact next action in Current/tracker until settled.

- Verify changed keys/retired controls, preserved choices/history/foreign units, target discovery/current schema and actual integration/restart limits. Check every newly rendered STATUS/template field label against the mapped locale, not just its heading; English field names such as Checkout are human labels, not fixed tokens. Save concise outcome, decisions and proof limits at normal delivery destinations; inline-reply off keeps substantive Questions/answers saved. Settle owned processes and apply normal claims/gates/delivery. New work uses current workflow only after dependent blockers resolve. Repeat current-state migration with valid saving-mode and no pending transformations performs no protected writes; independent authorized capture/release scheduling is separately attributed.
