# Deep review

Run after applicable [result review and triage](review.md#risk-triage) for mid/high or an explicit [request](work.md#task-modes) at any risk. Bind to the exact candidate and its accepted scope. Unless host-only routes/waivers apply, fresh-context workers own substantial inspection; the host verifies findings and owns integration, acceptance and handoff. Use ordinary authority, routes, gates and record locations; add no advisor or approval. Host-only waivers preserve adaptive host checks and handoff without reinstating waived steps.

## Fresh-context inspection

- Prefer a fresh-context read-only worker for substantial deep inspection on automatic mid/high or explicit invocation. Use [existing review routes and controls](review.md#result-review-routes), including worker settings and a bounded assignment; Codex spawns require `fork_turns: "none"`. Supply exact candidate, original requirements/accepted decisions, applicable rules/invariants, relevant source and matching evidence; exclude inherited conversation. Keep bulk investigation in that context; return concise findings, proof links, gaps and requested host probes.

- Include deep inspection in an already-needed separate review when possible; matching completed inspection satisfies both. If ordinary review leaves a consequential gap, dispatch only the missing deep inspection in fresh context; do not repeat covered checks or add a second ordinary review. The host runs requested probes, resolves findings and verifies changed source before acceptance. Persistent fixes/tests require existing implementation authority; integration and shared lesson writes stay with the owner-facing host.

- Configured or explicit host routes, fast-lane and skip-review keep direct host checks/handoff; this procedure restores no waived worker. Otherwise follow permitted external/native routes, falling back to labelled host inspection only after observed unavailability; disclose lost context isolation. Required independence/provider/access controls remain blocking. Standalone invocation authorizes bounded review under these routes, not implementation or a new approval gate.

- [Looper task review](review.md#looper-task-review) keeps its selected transport/model/effort and isolation: fold deep inspection into its permitted fresh ordinary reviewer, never launch nested reviewers or substitute a route. If that reviewer cannot supply additional inspection, the task host performs missing safe checks and discloses the context-isolation limit; unmet required independence/proof stays blocked. Return findings/handoff/lesson candidates through existing task evidence, without shared writes or coordinator changes.

## Select and prove

- Reuse matching verification, ordinary review and applicable design checks. Name each consequential failure mechanism still in doubt and the smallest safe check that can resolve it; run none if proof suffices. Match depth to potential harm and uncertainty. A relevant failed baseline or unavailable required proof prevents a passing claim; identify unrelated existing failures separately.

- Choose only useful checks. Verify APIs/types against actual versions and callers; search for existing equivalent helpers, harmful duplication, over-mocked assertions, hidden side effects and needless complexity. Use complexity and coverage, including CRAP if available, as diagnostic signals for changed code. Treat scores and similarity as evidence leads, with no global threshold or refactor target.

- Use examples or meaningful properties for input ranges and invariants; targeted mutation when assertions may miss a plausible fault; controlled ordering, retry, restart or load checks for shared state; boundary/abuse cases and real user journeys for consequential behavior. For affected web journeys follow [browser testing](browser-testing.md). Prefer existing tools, fixtures and checks; safe manual equivalents may suffice. State evidence limits. Tool availability alone justifies no work; installation or dependency changes need separate authority.

- Keep reviewers read-only; request host probes if restricted. Standalone probes may write only disposable scratch or a throwaway copy, outside reviewed files and shared records. Mutation/destructive probes use an isolated disposable copy or fixture with no live side effects. Off-record leaves no workflow records. Persistent tests/fixes require applicable implementation authority; preserve scope, owner changes and test assertions. Report unsupported fixes as findings.

- Recheck affected behavior, risk, findings and handoff after material repairs; reuse unchanged proof. Retain [required independent review](planning.md) for changed protected boundaries unless validly waived, and keep ordinary review source identity current. No blanket refactor or fixed repair loop. Record blocking and unproved checks in [round evidence](session.md#round-evidence).

## Human handoff

- Save one concise localized handoff at the existing answer destination before any applicable approval. State exact candidate, risk/reason, intent, material decisions, acceptance/invariant outcome and uncertainty. Link proof instead of copying per-ID accounting or logs. Identify actual route/waiver and gaps that affect judgment. Keep low risk to its short risk disposition unless explicit review or material uncertainty warrants more.

- Rank exact file/diff locations, why each matters, and what the human should confirm. Include material data shape/flow, coupling, test assertions and behavioral evidence. For high risk, mark sensitive paths for careful human review, including failure/recovery, downstream effects and specialist decisions. State actual human-review/approval status; agent checks prove neither. Existing project rules and gates decide whether delivery pauses.

## Review lessons

- Retain only verified reusable failure mechanisms whose recurrence or severity warrants a lasting review reminder. Record applicability, mechanism, concrete check and source evidence. Deduplicate against existing lessons and authoritative rules/invariants; link binding authority. Correct or retire obsolete guidance. Summarize consequential additions in the existing handoff.

- Only the owner-facing host updates the established review-knowledge record or creates checkout-root `<ag-dir>/sys-review.md` for the first qualified lesson. Verify the safe path and unchanged source; preserve concurrent edits. Delegates and isolated looper tasks return candidates in existing evidence, never write the shared file. Off-record creates no lesson record. Lessons guide investigation; they grant no authority, proof or waiver.
