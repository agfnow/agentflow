# aglite 0.3.0

Finish authorized work and leave durable recovery facts. Record each fact once; records support development rather than become another product. Before authoring chat, Replies or reports, read and apply [writing guidance](references/writing.md); fixed records and owner instructions prevail.

## Activate and recover

An owner message containing unquoted `nolog:`, `noop:`, `off:` or `skip:` makes that exchange off-record: execute/answer in chat without notebook access or writes. Exclude its input, answer and progress from all workflow records/artifacts, including later summaries. Quoted examples do not trigger it; subsequent unmarked messages follow normal recording.

Resolve only directory/root/routing facts needed to locate configuration, then read [configuration](references/configuration.md); apply its switches throughout. Owner instructions prevail. `.agentflow/` means configured `ag-dir`; the root notebook uses `<ag-dir>/<notebook-name>`. Bundled asset paths remain literal. Resolve the notebook once from configuration/defaults before probes; never substitute a default for a configured name. Explicit/feature routing and absent-notebook history inspection still apply.

Before the idle shortcut, proactively follow First-time setup after identity/routing and notebook/archive history checks in a verified Git checkout with neither the selected notebook nor configured ag-dir, no established history or prior retirement. This authorizes setup only; off-record and feature rules prevail.

For other bare activation with no direct owner task/question, inspect only configuration, the selected notebook's latest Ask, latest Questions and Current/Next; linked open tracker/design/gate/delivery state requires normal recovery. If the selected notebook is absent, first inspect root/configured-directory notebook/archive candidates; known history requires normal recovery. Only when these establish no task, unresolved question, carried unfinished work, gate/delivery or live operation (including an absent notebook with no known history), stop and ask for the next request; do not claim, initialize or update records, or capture this idle activation retroactively. Ambiguous state requires normal recovery; lifecycle commands and managed/feature paths first follow feature routing. Skip unrelated reads/commands on this idle path.

## Task modes

- An unquoted command `grill-me [topic]` explicitly selects the [requirements interview](references/advisors/requirements.md), even without a detected gap; read [advisor rules](references/ag.md) and that prompt. Bare invocation uses an unambiguous active topic; otherwise ask for one without inventing work or persisting an interview mode. Quoted mentions do not trigger it. The host conducts connected rounds at existing answer locations, honoring `inline-reply`; no mandatory worker, document, persistent setting or implementation authority. The explicit interview prevails over fast-lane's advisor skip for that interview; retain its other rules. Stop at readiness under the requirements prompt; resume only already-authorized work.

- An unquoted command `skip-review [task]` selects host review for one identified request (possibly several tracker items), waiving ordinary separate review including the risk-boundary requirement. Mentions/examples do not activate it. Bare invocation uses unambiguous unfinished work; if ambiguous ask which task, if none wait without persisting an override or closing the Ask. Record the boundary/override once in Current or the existing tracker; retain through follow-ups/resume, expire at completion, never change settings. Keep other workflow steps, `inline-reply` and host checks/review. This command replaces earlier owner review requests for that same work; same-message/later explicit review requirements prevail. Ask when scope/intent is unclear. Exclude the selected work from other tasks’ separate-review scope/inputs unless those prevailing requirements cover it. The command authorizes stopping only its task-owned ordinary reviewers; verify stopped/settled before host review, preserve completed output as advice.

- An unquoted command `fast-lane [task]` selects direct host execution for one identified task; mentions/examples do not activate it. Bare invocation uses the current unfinished task; if ambiguous, ask which one, and if none, wait without inventing work or closing the Ask. Record the task boundary/mode once in Current or the existing tracker; retain it through follow-ups/resume, expire at task completion, and never change settings. Switching modes does not stop live workers: settle their state under existing authority before host edits.

- Fast-lane skips advisors, ordinary delegation, new design/tracker, ordinary separate review and routine RUN/WIP, even when normal creation/review criteria apply. Keep existing records minimally current and save recovery in Current/tracker at interruption or unfinished handoff. Keep identity/ownership, input capture, Reply, scope, system invariants, necessary checks, host review and authorized delivery. Explicit owner plans, reviews, executor choices, checkpoints, configured gates and feature lifecycle requirements prevail; resolve incompatible choices before dependent work. Record host review once with inspected scope, evidence, findings and unresolved limits.

- Otherwise work directly when ordinary inspection/checks suffice. Name material questions needing structured investigation as the request, inspection or evidence contradicting the chosen approach raises them; only for those or an explicit advisor or release-candidate audit request, read [advisor selection](references/ag.md) before dependent work, then only selected advisor prompts. Judge by unresolved product choices, unfamiliar affected paths, cross-subsystem contracts, technical uncertainty or trust/failure risk, not task length. Do not load ag.md/advisors for empty activation, routine work or fast-lane, except an explicit grill-me interview above. Ordinary planning, delegation and review do not require them; advisor findings confer no new authority.

## Notebook ownership

- After the idle check, at first notebook access after routing, resolve its physical path (the physical parent plus filename if new), discover only its claim Ask ID, and exclusively create `.<notebook-basename>.owner` beside it (e.g. `.devlog.md.owner`) with `fs.openSync(path, 'wx')` or equivalent before recovery or task execution; never check then overwrite. Store JSON `{session, ask, claimed_at}`. Use the actual host session ID, or generate one UUID and retain it across turns; never use a tool PID or host name. In Git, ignore each marker with an exact notebook-relative rule in the local exclude file; never commit it.

- An existing marker permits only the same session and Ask. Foreign, empty, malformed or mismatched claims at activation refuse task execution immediately; report the owner/conflict in chat without writing the blocked notebook. Other notebooks remain independently claimable.

- Only for a late ownership conflict after task work began: stop further task edits, retain results and retry exclusive acquisition after waits of 60, 120 and 180 seconds (three retries over 3½ minutes); never clear/overwrite a claim or rerun task effects. Defer the conflict report until exhaustion; then report the owner/conflict and unsaved result. After acquisition, reread STATUS, the latest Ask/Reply and resolutions; reconcile newer instructions and actual files. Reuse only an empty trailing Ask with no pending work, or append a separate unused Ask at EOF after a closed round, with the original request/source and retained result; never insert into another round or bury pending work. An occupied/unresolved tail or unsafe reconciliation stops writes for an owner decision. Rebind only this session's verified marker to the receiving Ask before mutation; per-mutation checks still apply.

- Before every notebook mutation, verify the marker still matches this session and Ask, including input capture, RUN/WIP, STATUS, archive and Reply. Retain an acquired claim across turns while the round is open; the idle shortcut creates no claim. If an owned reread shows the Ask advanced, reconcile and rebind only this session's verified marker before task work; a foreign or unexplained mismatch remains blocked.

- After saving and verifying Reply plus the next Ask and settling any configured delivery, recheck ownership and remove only this session's marker using the owner's deletion policy. Claim anew before writing the next round. Interrupted/failed closeout retains ownership. Foreign or stale claims require explicit owner-authorized clearing or handoff; never infer it from age, silence or process state.

- Hosts execute these filesystem operations directly; no helper, write lock, heartbeat or daemon. This coordinates cooperating agents, not unrestricted editors. Feature lifecycle exceptions, including an owning main launcher’s checkpoint/release, follow the feature reference.
