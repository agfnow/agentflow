# aglite 0.3.1 — 日常使用指南

[English](AG_GUIDE.md) · 繁體中文

0.3.1 發佈版（2026-10-20）。安裝及從 Agentflow 外掛切換的方式見[套件 README](https://github.com/agfnow/aglite/blob/main/README.zh-tw.md#claude-code-從-agentflow-改用-aglite)。已知舊版設定會在保留有效選項的前提下遷移；歷史紀錄及安裝替換另行處理。

執行完成後，紀錄與 worktree 仍會保留。被 Git 忽略的 `.aglite-records/` 筆記不會隨產品整合；另行授權清理前，須先保存。各類檔案、已釋放 claim 與封存要求，見[保留檔案](../references/looper.md#retained-files)。

## 用 looper 執行群組

在 `ag.json` 的 `looper-routes.task`、`repair`、`acceptance` 統一設定執行方式、提供者與模型目錄。task／repair 共用既有的 `implementation` 等級；review 與再次驗收共用 `acceptance`。

模型留在 `model-family`；上限放在 `looper-limits`，預設同時執行 3 組、最多修復 2 次。範本的路由是空的，執行前須先設定。

佇列只保存進度與每次嘗試實際採用的設定證據；恢復中的嘗試保留原設定，新嘗試才採用該次啟動讀取的設定。詳見[設定規則](../references/configuration.md#looper-settings)。

將附有預期成果、範例及保留事項的編號工作清單交給主代理。

`prepare-tasks <request>` 在 `<ag-dir>/artifacts/A-NNN-<name>/planned/group-NNN.md` 與相鄰的 `planned/queue.json`、保留原文的 `planned/request.md` 準備群組。Schema 2 只在 JSON 保存相對路徑與 SHA-256；原文變更、遺失或路徑不安全時會阻擋執行／恢復。主代理從 Current 連結 `planned/` 執行根目錄後停止。

你不必自行填寫技術 JSON。

使用 `run-tasks` 執行已連結的佇列，或以 `run-tasks <run-root>` 指定其他已準備的佇列。`handle-tasks <request>` 會接續完成準備與執行。

主代理啟動協調程式，不需要你另開第二個終端機。詳見 [執行契約](../references/looper.md)。

群組各用不同且穩定的 worktree，預設同時最多 3 組。每組依序啟動新的普通任務代理，保留既有工作流程與審查設定。

群組可用 `depends_on` 列出較早的群組。相依群組等前置群組檢查並整合完成後，才從最新已檢查的目標版本建立工作樹；等待不占工作名額。狀態會列出未完成的相依項目，已啟動工作樹保留原始基底。

原生工作階段需要在線的主代理；CLI 工作階段支援 Codex／Claude。關閉主代理會阻擋原生派工，不會擅自切換供應商。

完成的群組依就緒順序進入單一整合通道。乾淨合併執行整體檢查，不另啟代理；修復仍須審查與驗收，預設最多 2 次。

問題只阻擋所屬群組：你回答主代理，由它將回覆交給協調程式。

群組任務紀錄放在 `.aglite-records/`，不會合併到產品。

需要 shell 操作時，以 `npm install -g <resolved-skill>` 安裝，再用 `agf loop run [run-root]` 或 `agf loop status [run-root]`。

省略 shell 根目錄時使用目前目錄；找不到佇列會報錯。

狀態顯示已儲存的進度與問題。

以 `run-tasks` 接續，先核對舊寫入者與 Git 效果並保留未完成工作。

不另設提升步驟，也不因此授權清理、推送或發佈。

## 按需採用 browfield 八步驟

要在不熟悉的既有程式碼中新增已授權功能時，可輸入 `browfield <任務>`，或要求採用 brownfield 八步驟。單獨輸入 `browfield` 時，採用明確的進行中任務；若不明確則先詢問任務。主代理也可針對明確且重要的探索或回歸保護需求選用；僅因專案已有程式碼，不會自動啟用，一般任務仍走原本流程。

[內建參考指引](../references/browfield.md)涵蓋探索、還原規則、影響與風險排序、基準與特徵測試、規格、實作、驗證及保存。每個階段先儲存結論才推進，依後果與可能性排列風險，並分別檢查功能結果與程序遵循情形。

任務模式、核准、紀錄、規劃、審查及交付仍由 aglite 負責；按需重用顧問方法，不強制執行八個顧問或另一套流程。fast-lane 保留原有顧問與文件建立豁免及必要檢查；明確要求逐步教學時，每階段暫停說明。只須安裝 aglite，不必另裝 brownfield skill，以 `browfield` 選用即可。

## 開始與接續

首次使用時載入 aglite，輸入 `godev` 並說明需求。初始化或既有專案下次實際工作時，會在根目錄 `AGENTS.md` 補上僅供面向用戶的主代理於工作階段開始時預設使用 `aglite` skill 的指示，由該代理透過自身支援的技能機制尋找、載入並遵循，不限定品牌、路徑或安裝範圍；找不到時回報缺少技能，不假設檔案路徑或自動安裝；受委派的 worker／審查者依限定任務工作，不啟用流程。主機遵循此指示時，之後的用戶工作階段便會自動載入／接續，仍尊重用戶明確指定的啟用或停用方式。`godev` 仍可手動開始／接續。小任務通常只需筆記與一般檢查；較複雜的任務才需要設計及追蹤文件，任務文件只在需要或明確要求時建立。新的工作階段輸入 `godev`，便會從目前 Ask 與連結紀錄復原工作。技術驗證、檢查／審查結果、不變條件核對與除錯紀錄不得放入 devlog，包括 STATUS、RUN/WIP 與 Reply；既有歷史不搬動或改寫。省略不必要的細節；需保留的新證據放入 `<ag-dir>/.tmp/A-NNN.md`，從 Current 及產生該紀錄的 Ask（Reply 之前）連結。既有 tracker 保留任務／復原狀態並連結證據，不重複記錄。其他筆記使用 `<ag-dir>/.tmp/<notebook-basename>/A-NNN.md`，標明筆記／Ask 身分；確認命名空間所屬，遇到衝突時選安全且未使用的位置。明確指定的目的地與既有證據位置仍保留。devlog 只留簡短結果、復原連結、必要里程碑／通知、答案、Questions 及影響判斷的阻礙／限制。中斷／交接前，Current 須直接連到接續必需的證據，或連到在 Recovery 區段提供該連結的 tracker；註明用途與下一個安全動作，未完成時由 STATUS Current 保持連到這份復原資訊；沿用既有 Ask 連結，不在新 Ask 重複。多項未完成工作共用一份 tracker；豁免建立 tracker 時，在 Current 使用附標籤的既有證據連結。重啟／接續須先讀取這些連結，核對筆記／Ask 身分與實際狀態；缺少或不符的證據仍屬未證實，不猜測 `.tmp` 檔名。雖稱 `.tmp`，仍被連結的紀錄必須保留，不自動刪除或忽略。建立／連結前檢查 Git 忽略規則；必要時改用 artifacts 中未使用且不被忽略的位置，納入已授權的交付。沿用既有紀錄，不逐輪建立空檔，每項事實只留一份。生命週期復原只留筆記／Ask 身分、授權操作與清理範圍、防止重複執行所需的精確 refs、最後證實結果及下一個安全動作；連結既有證據，保留未完成的 gate／路徑更新及必要的失敗／檢查／審查／決策細節；仍須重新執行安全檢查，不新增紀錄位置或永久 drop 紀錄，也不重寫歷史。Reply 保留答案及影響判斷的限制；面向使用者的獨立驗證報告仍須明確要求。詳見 [Round evidence](../SKILL.md#round-evidence)。

追蹤文件依序放簡短目標與整體進度、**Tasks（待辦事項）**、**Recovery（復原資訊）**，最後才是證據連結／更新細節。每項先以方括號顯示狀態，例如 `- [DOING] T-1 — 改善追蹤文件可讀性`，其餘細節使用有標籤的巢狀項目。狀態為 `TODO`（尚未開始）、`DOING`（進行中，包含等待檢查／審查／交付）、`BLOCKED`（無法繼續，須寫明阻礙）、`DONE`（已證明完成）。事項維持固定 ID 順序；Recovery 標示目前事項與下一步。

新專案預設使用 `.agentflow/<簡短目錄名>.devlog.md`，例如 `a002/` 專案使用 `.agentflow/a002.devlog.md`。名稱取自實體 checkout 根目錄（非 Git 專案取原始工作階段資料夾），不取 Git 子目錄；保留既有明確名稱與歷史。STATUS 保留目前復原資訊，每輪依序為 Ask、啟用的 RUN/WIP、Reply 與下一個 Ask。每個新 Ask 標題前放一行獨立的 `---`，前後各留一行空白，初始與功能筆記亦同；既有歷史維持不變。可直接填寫下一個 Ask 再啟用；問題答案可寫在聊天或對應 `ans:` 欄位。空白答案與建議預設值不代表同意。舊紀錄保留；超過 750 行或明確要求封存時，將較早已完成輪次依序附加至唯一相鄰的 `<notebook-stem>.archive.md`，保留既有封存內容、未解決事項與最近已完成輪次，不按時期拆成編號檔。明確要求 notebook 更名時，也將該封存檔更名（`devlog.archive.md` → `notes.archive.md`）；移動前檢查所有目的地，保留歷史位元組並更新現行連結。自訂封存檔歸屬不明或歷史連結須修改時，先請用戶決定。

完整成果存於 Reply；工作完成且 `inline-reply: off` 時，聊天只顯示 `→ Updated: A-NNN | <notebook>`，下一行以兩個空白起頭，顯示括號內的工作目錄；完成說明留在紀錄中。答案、範例與問題一律儲存，只有明確要求在聊天／終端顯示才可輸出；「show me」、「what will be displayed」或修改未來輸出的要求均不構成授權。工具回讀須靜默核對，不印出答案。明確要求顯示答案及 `inline-reply: on` 時，結尾仍須附同樣的兩行收據。必要通知、未完成工作說明與實際 feature 交接沿用其操作規則；假設交接範例只儲存。在已確認存在的 checkout／資料夾中，若指定筆記與設定的 ag-dir 都不存在，且無既有歷史或退役紀錄，啟用時即主動初始化 aglite。非 Git 資料夾在寫入初始化檔案前，先於聊天詢問是否也要建立 Git repo，即使 `inline-reply: off` 亦同；若你已針對該資料夾明確選擇，則不重複詢問。同意時只在該資料夾執行 `git init`，成功後立即建立並驗證空白初始 commit，再進行其他初始化或交接；即使 `auto-commit: off` 亦同，除非你明確禁止提交。初始 commit 不納入已暫存或原有檔案；明確要求初始化 Git 亦適用此規則；復原時沿用既有 HEAD，不重複建立。若禁止提交，略過此 commit 並回報功能 worktree 需要先有 commit；提交失敗時保留 Git 狀態，回報阻礙並停止初始化。成功後重新確認身分、設定與路由；拒絕時繼續非 Git 初始化，Branch 為 N/A，略過 Git 交付；未回答則等待。Git 初始化失敗時先檢查部分建立的 Git 狀態，不刪除，回報並等候你選擇復原方式；只有確認仍為非 Git 狀態，才能繼續不使用 Git。建立 Git 的同意不授權提交原有的無關檔案、建立遠端或發布。完成初始化交付後在聊天請使用者提出下個請求，取代簡短收據；不留紀錄與 feature 規則仍優先。其他閒置啟用只讀取必要狀態後請使用者提出下個請求，不建立或更新筆記、設定或 claim。

用戶請求保留原文（憑證須遮蔽），每個以空行分隔的文字段落前加上 `+ `；同一件事的相關段落可只在第一段加上前綴。保留程式碼區塊內文與既有 `+ ` 前綴，各組之間留一行空白，不加入獨立的 `--`、引言前綴或結尾分隔線。既有紀錄保留原格式，除非使用者要求修正。

每次呼叫 Codex `spawn_agent` 都明確設定 `fork_turns: "none"`，並在任務訊息提供所有必要背景；即使未覆寫 model／effort，也不繼承 host 對話。

共用保障放在 skill 的 [專案規則基準](../references/project-rules.md)，沿用既有 backlog／不變條件規定。所有專案 agent／審查者讀取基準與適用的專案覆寫規則；讀取本身不啟動工作流程。根目錄 `AGENTS.md` 只補缺少的啟用及探索指示，保留原有內容；現有專案相對 skill 路徑失效時，回報並提出修正，不默認有效或改寫；單獨讀取規則基準仍不啟用 aglite。基準可來自已安裝 skill、已確認的 checkout 內參照或 host 提供的完整原文；基準不可用時，暫緩共用紀錄寫入與不變條件／審查驗收；提示缺口並繼續其他獨立且獲准的工作。用戶撰寫的專案例外優先於預設；保留下來的自動產生內容仍依現行 skill 定義。`<ag-dir>/rules.md` 為選用的專案例外規則，初始化不建立或覆寫。保留既有權威／自訂路徑與指示；已引用的契約缺失時須先釐清。Main／根目錄初始化從附帶範本預先建立缺少的 backlog、空白不變條件登錄檔，以及含 `.gitkeep` 的 `artifacts/`、`features/`、`.tmp/` 目錄。設定檔仍放 checkout 根目錄，筆記放已解析的位置，不整批覆蓋現有紀錄。沿用既有／自訂權威紀錄，拒絕不安全路徑，以排他方式建立檔案；空範本不代表任務或不變條件授權。初始化以外，只在首次有可追蹤項目／獲准保證時補建相應紀錄。封存、每輪文件及實際 feature worktree 仍按需建立。受管理的 feature 初始化只建立自己的設定／筆記，沿用繼承的共用紀錄。建立空白登錄檔仍使用不變條件通知標題，註明尚無獲准的 ID。其他 backlog 僅作去重來源，除非你指定採用。紀錄路徑依設定的 ag-dir，不隨 notebook／feature 位置改變；不自動搬移。

討論或提問中具體的未來工作記入 `backlog.md`，標為 **proposed**；用戶已接受但延後的工作標為 **deferred**。每項保留來源、目標、未完成原因、預估工作量或下一個決策；記錄不代表實作授權。新增或重大修改項目時提示用戶並提供 ID、狀態、原因與連結。Host 在實際工作復原、相關決策／修正／延後及結束前核對相關項目，新增／去重或更新，保留其他未完成工作。完成並驗證或用戶明確取消後，先在 notebook 記錄結果／取消，再移除該項；不因時間或沉默推定取消。不在閒置啟用時維護，也不定時掃描。

提醒配合決策時機：工作復原時提示相關依賴或範圍重疊；結束時的 Questions 只針對影響目前工作的未解決選擇提醒 backlog 項目，附 B-NNN 連結與建議預設值，未變動項目不會僅為提醒而重複列出。明確要求檢視 backlog 或建議下一項工作時，列出簡短的優先候選清單，說明理由、依賴與預估工作量；由你選定後才安排。閒置啟用時不掃描或安排 backlog 工作；定時提醒須經你明確要求。

任務首次讀取時，保留每份權威登錄檔的實體路徑與獨立的原始位元組／SHA-256 基準；檔案缺失則記錄不存在。復原時保留原始基準，中斷前將所需原始位元組或可取回快照的參照存入既有復原證據。寫入共用紀錄前及結束時重新比對，檢視包含格式在內的所有差異；記錄已接受的修改，不替換原始基準。外來修改須核對來源／授權，不覆寫或默認採用。缺少基準／原始位元組時揭露證據限制，不宣稱未變；雜湊只證明與基準的位元組相同。不新增自我雜湊、旁檔、hook 或執行程式。詳見[不變條件政策](../references/invariants.md#discover-and-reconcile)。

系統登錄檔內容有任何修改時，儲存的 Reply 與聊天結尾均須用獨立的 **System invariant changes** 標題列出受影響 ID、修改與原因，即使 `inline-reply: off` 也要顯示。標題是固定識別字；只移動路徑則用 **System invariant relocation** 分別在 Reply 與聊天說明。必要通知放在簡短收據之前，feature 交接也須包含。

## 加入後續批次

工作進行中，每批後續工作各用一則訊息，以 `append-rounds <工作內容>` 開頭。一則訊息就是一批，內含多項任務仍算同一批。例如先送 `append-rounds 更新安裝指南`，再另送 `append-rounds 檢查更新後的範例`。一般訊息仍用來修正或補充目前工作；引用範例不會安排工作，只有指令而沒有內容時會詢問要加入什麼。

只要 Current 連結的待執行區段還有項目，新批次都加入同一區段。主代理在既有 tracker 保存各批輸入與順序，不放入目前的 Ask；沒有 tracker 時，使用 Current 連結的證據紀錄。固定的批次順序編號與接收的 Ask 可區分內容相同的批次；針對後續批次的修正也隨該批保存，執行時一併移入 Ask。目前批次的 Reply、核准關卡與已授權交付完成後，才把下一批移入獨立的 Ask。執行到該批時才配置 Ask 編號及成果目錄；完成後立即儲存 Reply。STATUS Current 持續連到待執行工作，`godev` 可復原，先核對輸入是否已移入 Ask，避免重複建立。關卡、阻礙或缺少授權會暫停後續批次。帶有不留紀錄標記的批次請求不儲存也不執行；若要稍後執行，請移除標記後重送。內含功能生命週期指令的批次也不儲存、不執行；請將其餘工作以不含功能請求的 `append-rounds <工作內容>` 重送，並在準備好時另外送出該功能指令。一般批次內的指令／模式等執行到該批時才生效。沒有目前工作、待執行批次或未完成交付，且最後一個 Ask 空白時，請求直接從該 Ask 開始；其餘情況存為後續批次。已寫入下一個 Ask 的用戶需求優先執行，後續批次等待。取消批次時，先在目前 Ask 保存取消指示，再移除待執行項目。功能的待執行批次須先處理才能合併；明確放棄功能時，則連同已檢查的功能資料一起放棄。

每批 append-rounds 開始執行時，包括小工作或直接寫入 Ask 的批次，可獨立處理的工作優先交給新的原生實作子代理；fast-lane 或明確指定執行者時除外。主代理負責佇列、認領、筆記本與輸入保存、決策、驗證、整合、交付及僅能由主代理處理的紀錄作業。依[有界任務指派](../references/review.md#give-one-bounded-assignment)提供該批已保存的輸入、修正及必要背景，不繼承對話，也不交出整個佇列。僅委派單一有界批次不必建立 tracker；其他建立條件、明確要求及關卡仍適用。原生派工管道不可用時，可記錄原因後由主代理直接處理，但明確執行者或獨立性要求禁止時除外。已選設定無效或不受支援時，依既有工作代理規則交由用戶決定，不得默默替換模型或改由主代理執行。

`inline-reply: off` 時，聊天最後的收據指向最新完成的 Ask；設為 `on` 時，依序顯示這次新完成的所有 Reply，再附收據；每個新完成批次的必要通知也依批次順序顯示。待執行紀錄無法喚醒已停止的主機，也不會產生額外的聊天最終回覆。詳見[批次規則](../SKILL.md#append-rounds)。

## 易讀回答與按需檢查

Reply 只引用每題第一段，最多 100 個字元（含空白與標點），省略文字時加上 `...`。Ask 保留完整輸入；每題與修正仍須回答。

[寫作指引](../references/writing.md) 的最高目標是讓讀者完整理解（ultimate comprehension）：不必猜測或另開連結，就能理解核心結果。簡短、格式與術語都須服務這個目標。

人眼容易閱讀、快速掃描是必要條件：可用簡短 prose 段落或清單項目，每段／項只表達一個概念，通常一至三個短句，彼此空一行。重點放在開頭；交付前須拆開過長或混合多個概念的段落／項目。把長段落改成單一長項目，仍不合格。

只給機器讀的文件（包括 skill prompt）可以盡量壓縮，但須保留需求、例外、保障、精確性及正確性；混合文件依各部分讀者適用規則。

每次交付前，須確認讀者能說明結果、誰做什麼、為何重要，以及需要什麼決策或行動；適用的重點若不清楚，就須補充或重寫。

先說結論與行動，使用白話及簡短段落或清單項目，保留重要限制。刪除重複內容。

列出多份文件時使用內縮的 `-` 項目，各自獨立一行，項目間空一行。

所有報告都須先完整摘要結論、重點、適用的建議或決策及影響判斷的限制，讓讀者只讀開頭就能掌握結果。事後檢討（postmortem）與根本原因分析報告也須將原因及防範建議放在開頭；應拆段而非刪減必要內容；開頭分成多個短段落，保留完整內容。

主代理須將指引交給受委派的報告作者。

在請你做重大選擇前（包括任何改變已接受成果、保障或你選定設計的選擇），主代理必須用白話說明你要求或目前的做法及每個替代方案：誰做什麼、保留什麼、改變或失去什麼，以及如何影響你的目標。

須明說規則衝突，區分已驗證的行為、假設及示例；沒有新的衝突證據，不應重問已確定的決策。如果不熟悉領域的讀者無法複述工作與後果，必須先重寫再詢問。

規畫須先確認需求完整與授權範圍，再求精簡；元件較少不代表可以犧牲目標、目的或保障。新增內容須有授權依據；移除內容須說明保留的保障、替代方式與驗證，並考量主代理注意力及復原成本。證據不足時須明說，並繼續已獲授權的檢查；只有尚未解決的授權、成果或限制選擇才需詢問，不能默默縮減需求。沒有新的衝突證據，不應重問已確定的決策。重大架構變更應在昂貴試跑前，以簡短責任流程與一個完整生命週期對照原始需求，設計不合格方案無法通過的驗收例子。能否使用程式迴圈、主代理離線時是否繼續派工，以及誰控制一般任務事件，是三個獨立決策。審查者須取得原始需求、明確差異，以及標示清楚的限制、建議與假設。你只需提供目標、已知限制與例子；技術欄位可省略。分組、路徑、相依性、基準與檢查由主代理依證據推導，只詢問重大未知事項。沿用既有紀錄與審查；一般小修改不新增強制方案比較或核准關卡。詳見[規畫規則](../SKILL.md#records-and-review)與[審查](../references/review.md#inspect-the-finished-result)。

未完成工作、授權與復原狀態保留在 tracker；沒有 tracker 時放在 Current。STATUS Current 連到復原資訊；新 Ask 除用戶輸入外保持空白。既有 Ask 連結繼續有效。[Git 交付](../references/configuration.md#git-delivery) 保留 claim、重試與失敗處理的保障。

- **Windows：** 平台相關工作讀取 [Windows 指引](../references/windows.md)。清理須遵守刪除政策，先證明垃圾桶／資源回收筒可復原；不可改用永久刪除。

- **瀏覽器：** 自動化程式碼預設用 Stagehand，Chrome 操作用 Browserbase 的 `browse` CLI（[官方 browser skill](https://github.com/browserbase/skills/blob/main/skills/browser/SKILL.md)）；用戶／專案偏好可覆寫。[瀏覽器測試](../references/browser-testing.md) 規範任務專屬本機無介面工作階段、存取保障及實際操作證據，供 host 驗證與 acceptance 審查。

- **資安：** 既有 [security-scan advisor](../references/advisors/security-scan.md) 按風險選擇原始碼／相依套件／機密檢查，記錄可重現證據，區分疑似／已確認問題與未涵蓋範圍。執行服務測試或上傳原始碼仍需適用授權；不宣稱符合金融法規。

## 選擇需要的模式

- **直接完成：** `fast-lane 修正 README.md 的錯字` 適用一個明確任務，持續到完成，包含後續訊息與復原。略過顧問、一般委派、新增設計／追蹤文件、一般獨立審查與例行 RUN/WIP；仍由主代理審查、驗證及記錄需求／Reply，遵守明確計畫／審查、設定檢查點與功能生命週期規則。既有復原紀錄維持更新。單獨輸入 `fast-lane` 需有未完成任務，不會關閉空白 Ask。

- **單次 host 審查：** `skip-review 修正 README.md 的錯字` 讓一個明確任務只用 host 審查，豁免一般獨立審查，包含 skill 的風險邊界要求。其他步驟與設定維持。此指令取代同一工作先前的使用者審查要求；同則或後續訊息的明確審查要求優先。覆蓋持續到完成，包含後續訊息與復原，完成即失效。單獨輸入時使用無歧義的未完成任務；有歧義則詢問，沒有任務則等待且不保留覆蓋。引用範例不啟用；切換前須處理仍在執行的 reviewer。

顧問選擇、紀錄建立、規劃路徑與模型設定分別回答不同問題。建立規則決定是否需要紀錄，`plan-order` 決定已有需要的計畫由誰撰寫；顧問建議本身不要求設計／tracker。設計必備內容留在[主代理規則](../SKILL.md#records-and-review)，成果審查清單留在 [review.md](../references/review.md#inspect-the-finished-result)。Spec 針對明確的契約缺口推理；acceptance 沿用同一次成果審查。

- **聚焦顧問：** 主代理在需求或證據浮現須結構化調查的實質問題時，主動列明問題，並在相依工作前選用相關顧問。`advisors: requirements, explore` 可明確指定角色。名稱有 `requirements`、`codewalk`、`explore`、`spike`、`spec`、`security-scan`、`acceptance`、`final-audit`、`learn`、`product-docs`。一般任務不載入顧問提示；選用顧問只授權任務範圍內的建議，不代表額外實作授權。主代理依證據缺口調整深度，問題釐清後即停止。

- **最終稽核：** 使用 `advisors: final-audit`，或以自然語言要求在發佈前稽核明確的候選版本。主代理也可針對已接受發佈工作中的明確就緒證據缺口選用；專案規模或工作完成本身不會觸發。[final-audit 顧問](../references/advisors/final-audit.md) 在一般檢查及候選組裝後，檢驗系統互動與實際交付產物。較早的聚焦建議只回報該缺口的發現、涵蓋範圍與限制，不給就緒判定；一般 review 要求仍走成果審查。沿用 `acceptance` 代理設定及符合條件的成果審查，保留尚未涵蓋的義務。缺少必要產物演練仍為未證實／NO-GO；GO 不授權發佈。不新增指令、強制階段或開關。

- **漸進訪談：** 需要探索實質意圖時，requirements 角色先讀背景與專案證據，主代理再提出相互連貫的小輪問題，通常一至三題，提供選項、影響與建議。依回答決定追問，以具體例子檢驗矛盾；決策留在既有紀錄，不另建訪談歷史。直到實作／驗證不再需要猜測重要意圖即停止，沉默／預設值不代表同意。`grill-me [主題]` 即使尚未偵測缺口也明確要求此流程；至少進行一輪，請用戶確認或修正推定目標、關鍵假設與最重要的相關質疑，再於需求明確時停止；單獨輸入時沿用明確的目前主題，否則詢問主題且不保留模式，引用範例不啟用。此明確訪談要求優先於 fast-lane 的顧問略過，其他規則保留；不新增持續開關、強制 worker／文件或額外實作授權。問題沿用既有回答位置；`inline-reply: off` 時請到儲存的 notebook／design 閱讀並回答。詳見 [requirements](../references/advisors/requirements.md)。

- **Claude 優先規劃：** `3ways` 讓 Claude 根據完整需求、已定決策、證據及可唯讀存取的核准原始碼／既有計畫，撰寫主要計畫與足以達標的較簡單方案。Codex 負責挑戰需求、事實與可行性；只有高信心且經證據確認的缺陷才改動 Claude 主軸，風格偏好不構成理由。不必湊三個代理，也不代表實作核准。

已有需要的計畫、設計、規格、規劃建議及 prepare-tasks 分組都遵循 `plan-order`，預設 `external`。規劃建議指撰寫或修訂計畫的建議；訪談與蒐集證據沿用一般顧問規則。設定本身不新增計畫或顧問階段。Fast-lane 的既有／明確要求計畫由 host 處理，除非你明確指定該任務採另一規劃路徑；skip-plan 與核准關卡仍有效。

`external` 由 Claude CLI 撰寫，不自動加上 Codex 挑戰；`native` 使用全新脈絡的原生規劃代理，僅在工具確實支援時優先用 Claude；`host` 直接由目前主代理規劃，不探查 worker。若實際作者不是 Claude，必須明確標示。

所選路徑無法使用時，先記錄原因，再從該階往下：`3ways → external → native → host`、`external → native → host` 或 `native → host`；`host` 為終點。`native` 就是內部原生代理（internal）；重用可用計畫，不重複探查已失敗的路徑。所選設定無效時須取得決定；明確指定的提供者、model、effort、獨立性與唯讀限制仍優先，無相容路徑即待處理。降級不得聲稱已完成跨家族挑戰。見[規劃路徑](../references/review.md#planning-routes)。

- **不留紀錄：** 未加引號的 `nolog:`、`noop:`、`off:` 或 `skip:` 排除該次交流的需求、進度、答案及後續摘要。引用範例不會觸發；下一則未標記訊息恢復記錄。

說「先規劃，等我確認」可要求檢查點；說「規劃後實作」則授權兩者，除非仍有重要決策未定。想法與審查建議不代表額外修改、發佈、對外傳訊或清理授權。

主代理讀取 `ag.json` 頂層的 `next_update_date`（UTC 日期 `YYYY-MM-DD`，缺少或 null 代表到期）。到期前不查詢發佈資訊；到期後只查 [Agentflow 穩定版](https://github.com/agfnow/agentflow/releases)，查詢後將日期設為兩個日曆日後，失敗也一樣。委派代理／隔離 looper session 與不留紀錄的交流不查詢也不寫日期。aglite 是 Agentflow 9 的 beta 名稱，Agentflow 8.x 不會被視為更新。覆寫安裝（包含轉換至 9+）仍須核准並保留原始碼 WIP。詳見[版本檢查](../references/configuration.md#session-release-check)。

## 專案設定

`ag.json` 位於 Git 根目錄，非 Git 專案則在原始資料夾；若有 schema-version，必須為 JSON 整數 `9`；不支援的 schema 會停止相依工作。缺少 plan-order 預設為 `external`，缺少 review-order 預設為 `external`。主代理每次讀取設定時，自動將已知舊格式遷移至最新版，保留有效的使用者選擇、未知欄位與註解鍵。未知／較新 schema 或有歧義／會遺失設定的變更，須先取得決定；新增但未填的欄位沿用預設值。目前格式重讀不寫檔。詳見[遷移規則](../references/configuration.md#automatic-migration)。未來 schema 每次修訂整數加一，與套件版本分開。缺少欄位採預設值，已識別欄位的值無效時停止相依工作。可請主代理修改指定設定，或自行編輯。[設定參考](../references/configuration.md) 為正式規則。

- **路徑：** `ag-dir` 預設 `.agentflow`；`notebook-name` 僅為其下的檔名，預設 `<簡短目錄名>.devlog.md`，可省略此鍵；轉為 ASCII 小寫，連續非英數字元換成 `-`，去除頭尾 `-`，名稱主體取前 32 字元再去除尾端 `-`；空白主體使用 `devlog.md`。初始化會將產生的名稱寫入新設定。拒絕不安全檔名／路徑；明確指定筆記與 feature 路由仍依各自規則。搬移使用中的筆記需授權交接。

- **輸出／語言：** `inline-reply: off`、`skip-asker: on`；`use-lang` 預設取作業系統語系，再以 `en-us` 備援。代理的聊天與書寫依設定語系，不因輸入語言而改變；只有明確指定回覆／成果語言的指令可覆蓋。安裝範本的 `en-us` 會在首次初始化換成偵測語系。

- **進度：** 缺少欄位時 `skip-run: on`、`skip-wip: on`；附帶範本設為 `skip-run: on`、`skip-wip: off`，新初始化專案略過例行 RUN，啟用每十個活躍分鐘的 WIP。略過這些區段仍須在其他紀錄保留復原資訊。

- **計畫／審查：** `skip-plan: off`。計畫依需求規模建立；程式、操作提示、產品成果與可實作契約經 host 驗證後需審查，問答與示例則由 host 檢查。

`review-order: external`（預設）依序使用另一家 CLI → 全新脈絡原生代理 → 明確標示的 host 自審；`native` 交換兩條獨立路徑的順序；`host` 直接由 host 審查，不探查 worker。

已有需要的獨立審查若已知主要計畫作者，host 會先選不同模型家族，再選其他受支援的已設定模型，優先於一般路徑／等級預設；任務明訂的硬性限制仍優先。同家族／模型仍可審查，但須揭露限制。詳見[規劃與審查模型多樣性](../references/review.md#inspect-the-finished-result)。

選到第一條可用且符合要求的路徑即停止；fallback 前記錄路徑不可用的原因。所選 model／effort 設定無效或不受支援時，須取得決定。

必要獨立審查（含 skill 未豁免的風險邊界規則）與使用者明確要求的審查限制優先於所有順序；同則或後續訊息的明確要求優先於 `skip-review` 指令；無相容路徑時，審查維持待處理。

使用 `skip-review [task]` 可指定單次 host 審查。

- **檢查點：** `gate-design: off`、`gate-tracker: off`；設為 `on` 即加入正式規則中的核准關卡。空白答案與經過時間不代表核准。

- **Git：** `auto-commit: on`、`auto-push: on`。已驗證任務修改與使用者修改分開提交，推送需有安全且明確的遠端／分支。若兩者都不要，請設為 `off`。這些設定不授權部署或修改無關 repo；非 Git 首次初始化會先詢問是否建立 repo；拒絕時 Branch 維持 N/A，略過 Git 交付。之後的一般非 Git 工作，未經明確要求不會初始化 Git。

- **代理模型：** `pipeline-roles` 指定已選工作的 tier；`model-family.<provider>.<tier>` 統一儲存 `model/effort` 字串，以最後一個斜線分割。catalog 可新增 `gemini`、`openrouter` 或自訂名稱；依實際主機／提供者設定或使用者明確選擇取用。Codex/openai 與 Claude Code/claude 僅為附帶例子，不是主機白名單；外部 profile 以 `model-family` 參照同一份對照，CLI command 另外保留。tier 值以附帶設定為準。規劃沿用所選顧問角色，未選顧問則用 `threeways`；挑戰用 `threeways`，成果審查與 final-audit 用 `acceptance`。專案與範本包含 `product-docs: better`；未設定角色繼承 transport 預設值。缺少、模糊或不支援的已選值會阻止委派，不默默替換；使用者明確指定欄位優先。設定的組合須由主機控制項同時支援 model 與 effort；未設定角色繼承主機預設值。設定不啟動工作。見[代理設定](../references/configuration.md#worker-settings)。

筆記所有權是必要流程。主代理以工作階段身分獨占建立每份筆記的 `.owner` 標記；他人的、格式錯誤或不符輪次的標記會阻止任務執行。不可只因標記過舊或程序無動靜就刪除他人標記，需明確授權清除／交接。這只能協調遵守規則的代理，不能限制任意編輯器。Reply 與下一個 Ask 均已驗證後，先確認 worker／操作已結束，存妥未完成工作的授權、操作身分與下一步，才可在交還控制時釋放 claim。尚未關閉輪次的暫停與功能生命週期沿用既有規則；釋放不代表完成或批准。壓縮上下文後沿用同一工作階段身分；身分遺失或啟用時輪次不符須明確交接。詳見[所有權與拒絕接管說明](../SKILL.md#notebook-ownership)。

審查只在必要時複製：工具可能修改原始檔時，使用沒有 remote 的拋棄式 checkout；需要穩定快照時，固定來源。已有強制唯讀存取或停用工具並提供精確文字時，不重複複製。外部審查的工具存取須排除敏感／未獲准的檔案；無法強制限制直接存取時，改提供獲准的來源副本或精確文字。接受／重用審查前核對來源身分；有變動的路徑須重新檢查。記錄理由、來源身分與實際限制；複製保護原始檔，不隔離憑證／網路，也不是作業系統沙箱。

只保留有具體復原、審查或重要決策用途的證據；省略可由來源重現的一般成功細節，仍保留必要證明與已連結的歷史。

## 分開開發功能

`new-feature <name>` 在 `.wts/ft-<name>` 建立 `feature/<name>` Git worktree。所有 Codex／Claude Code 介面均須依序完整顯示指定語系的三步建立範本：已建立的分支／worktree、`/cd <功能工作目錄相對路徑>` 加上 `godev`，以及附上實際設定之功能筆記路徑的編輯器開啟建議。路徑以已驗證的來源對話目錄為基準，必要時改用絕對路徑；其他主機在該目錄重新開啟助理。筆記為 `.agentflow/features/<name>/<name>.devlog.md`，實際路徑依設定。準備指令不授權未指定的功能實作。三個功能指令完全略過 main 的根筆記、封存與 claim，連本 session 已持有的 claim 也不碰；根筆記缺少、忙碌或有未完成工作都不會阻擋操作。不得在其中記錄功能輸入、退役紀錄或 Reply，也不建立替代帳本。實際 Git 衝突、鎖定與目標功能的所有權限制仍適用。Git 清單取代 feature ledger／索引；準備與交接在 feature 筆記結束，指定的實作需求放入下一個 Ask。部分建立而缺少筆記時，須明確重送 `new-feature`，不得推定工作；既有退役功能紀錄不得重新開啟。只協調目標功能及其整合副本的 claim／紀錄；舊物件全數消失後，不要求掃描 main 根筆記歷史或保留永久退役標記。

`merge-feature <name>` 驗證並整合完成工作，除非明確要求清理，否則保留 worktree／分支；加上「and cleanup」才授權退役該工作目錄並刪除已合併本機分支。`drop-feature <name>` 檢查未合併及本機資料後放棄指定功能，依刪除政策將工作目錄移至已驗證的垃圾桶／資源回收筒，並刪除分支。

建立與合併狀態只放在功能專屬紀錄；放棄結果與部分清理的後續步驟只在對話回報，不保存耐久退役紀錄，功能筆記不存在也不阻擋放棄。

可直接在功能 worktree 內執行放棄指令並省略名稱；助理從 main 執行清理，移除自身工作目錄後才提供 `/cd <main 工作目錄絕對路徑>` 與 `godev`，不必事先切換目錄或重啟。

合併排除根筆記、封存與 claim 的變更，保留 main 的工作檔與暫存狀態；設定的最終核准關卡在破壞性清理之前完成。

已合併或放棄的功能不得繼續開發。

Codex／Claude Code 請輸入 `/cd <main 工作目錄絕對路徑>`，再輸入 `godev`；未完成的已授權清理則改送確切復原指令。其他主機在 main 重新開啟助理。

合併／放棄均須以編號列出結果與後續操作；第 1 步可使用簡短的縮排段落或子項目，但須保留必要事實與步驟順序。

成功且已驗證合併的編輯器建議指向 main 設定的根筆記，只以檔案資訊確認存在，不讀取或修改內容。放棄則只有已驗證且仍存在於垃圾桶外的功能筆記才加上編輯器開啟建議。

已在 main 時明說留在 main；部分清理列出確切復原指令，合併失敗則留在目前目錄處理。

不得縮成只有指令區塊；其他主機保留編號步驟並改用重啟指示。

目的地復原前須確認主機回報的目錄、Git 身分、設定與筆記所有權。生命週期操作前請讀[功能規則](../references/features.md)。

## 安裝、更新與限制

使用 `npx skills add agfnow/aglite --skill aglite` 從公開 repo 安裝，選擇主機與範圍後開啟新工作階段。Skills CLI 安裝以 `npx skills update aglite` 更新，範圍加 `-g` 或 `-p`。[現行 CLI 文件](https://github.com/vercel-labs/skills#skills-update) 說明這些指令。Claude Code 外掛方式與更新設定見[公開 README](https://github.com/agfnow/aglite#install)及[官方外掛文件](https://code.claude.com/docs/en/discover-plugins)。每個主機選一種安裝方式。

不需要 setup 指令、hooks、發佈程式或排程器。完成與復原仍依賴主代理遵守指示；缺少驗證仍屬未證明。符號連結與檔案檢查不代表已驗證所有主機／平台的自動載入或無人值守執行。

## 產品文件

已接受的變更若影響使用者、貢獻者或維護者的現行文件，須在同一變更更新相關文件；fast-lane／skip-review 亦適用。各類專案沿用既有產品概覽、手冊／速查、技術入口及 agent 指引，不強制固定文件組；無文件影響就不新增紀錄。每個變動事實有一個文件權責來源，並檢查相關摘要、翻譯及教學。多文件專案可沿用索引，或使用設定的 `<ag-dir>/doc-ledger.md`（預設 `.agentflow/doc-ledger.md`）；公開文件不得依賴私有索引連結。

對明確的產品全貌、首次文件組、交接或重大文件落差，可用 `advisors: product-docs`。選取只授權建議，不授權全面改寫或發布。內附角色預設為 `better`；未設定時沿用 host 預設。檢查受影響的矛盾、連結、範例及必要操作／散布版本；缺少必要證據仍屬未證實。不保證持續同步，也不強制全面稽核。詳見[維護規則](../references/product-docs.md)與[顧問](../references/advisors/product-docs.md)。
