# Clear answers and reports

Apply to agent-authored chat, Replies and reports; preserve quoted input and fixed record formats. Owner language/style instructions prevail.

- **Lead with the answer:** State the conclusion or recommendation and what the reader should do. Put any limit that changes that decision beside it. Use a short opening; no setup story or mandatory summary label.

- **Make scanning useful:** Put decisions/results before reasons, evidence and optional procedure. Use short bullets for parallel points, one concept each; begin with the words the reader seeks. Use short paragraphs for connected reasoning. Headings help longer reports; avoid empty ceremony. When listing several document references (e.g. Sources), use a label with nested `-` list items, one per source line and blank-separated.

- **Speak plainly:** Write for a reader without specialist knowledge. Name concrete actions and their benefit. Explain necessary jargon once; remove unexplained abbreviations, vague qualifiers and strings of compressed clauses. Concise must still be understandable.

- **Editor links:** In chat, cite files as `[file:line](checkout-relative-path:line)` from the verified checkout root; use absolute paths when the chat host cannot resolve relative targets. Never use report-relative `../` targets in chat. Saved Markdown uses document-relative file/anchor links, with line numbers outside targets. Wrap targets containing spaces in `<...>`.

- **Keep only useful detail:** Retain requirements, exceptions, safeguards and evidence needed to assess the answer. Link exact supporting records rather than repeat them. Keep workflow proof under [Round evidence](../SKILL.md#round-evidence), not in Reply unless explicitly requested; retain decision-changing limits in the answer. Move requested reproducible commands and specialist detail after the result; omit execution diaries and routine success summaries.

- **Keep claims honest:** Separate observed results, assessment and unavailable proof. Include failures, limitations and next actions when they affect the request. Never shorten away a condition that changes authority or correctness.

- **Check before delivery:** Can the reader find the answer/action in the opening and scan bullet starts for the rest? Cut points that do not answer the request, affect their decision or support assessing it; link records instead of repeating them. Compare with the full request and surrounding rules for omissions/conflicts. Preserve required fields, notices, receipts and handoffs; writing style grants no new authority.
