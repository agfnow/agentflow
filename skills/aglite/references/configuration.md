# Configuration

Host-driven; no hooks or general runners/helpers. Only explicitly authorized [looper execution](#looper-execution-exception) uses its bounded coordinator. Read before routing on activation and each later on-record owner message, and before configuration-dependent delivery. Apply the off-record exception first.

## Discovery and validation

Session directory means the startup directory or the destination of a verified Codex/Claude Code `/cd` handoff under [features.md](features.md#directory-transition).

- Configuration is <checkout>/ag.json; outside Git use the verified session directory. In a Git subdirectory use the Git root; a managed feature uses its own checkout-root file, never main's live file. Do not recursively search or use STATUS as configuration.

- Require JSON and switches objects; absent file/keys use defaults. Ignore // keys for behavior; preserve unrelated properties and external-workers. Validate selected worker fields and recognized planning/review switches below when needed. Before validation on every host read, apply [automatic migration](#automatic-migration); require JSON integer schema-version 9 afterward if supplied. Unknown/newer schemas stop dependent work. Invalid JSON, types or recognized values stop dependent work with path/key/error; never reset. Owner instructions override settings without persisting them unless requested. Missing keys need no write. An unresolved Ask binds the session to its owned notebook: changed routing or notebook selection requires owner-authorized handoff/relocation reconciling work and claims. Apply other switch changes there. All feature lifecycle commands route under [features.md](features.md) before root-notebook binding/recovery; never inspect or alter its notebook/archive/claim, even this session’s. Its state is irrelevant to lifecycle permission. Existing unrelated work remains bound separately; these commands neither close nor transfer it. A verified lifecycle /cd handoff may bind the destination feature notebook without checkpointing, releasing or recovering main; the old root claim/work stays untouched for later ordinary main recovery.

- Update only explicitly requested properties or documented lossless migration mappings after checking the source is unchanged; atomically rename an adjacent temporary file, then reread. Create new files exclusively; never replace existing configuration with the template. Maintain integer schema-version (currently 9); increment by one for each future schema revision; preserve // keys and unrelated worker metadata. Maintain ascending switch names in the bundled template. Configuration selects settings only for already-authorized work.

- Nine Boolean switches accept exactly on|off. Defaults: skip-asker on; inline-reply off; skip-run on; skip-wip on; skip-plan off; gate-design off; gate-tracker off; auto-commit on; auto-push on.

- use-lang accepts a nonempty locale tag (case-insensitive language plus optional script/region, hyphen or underscore). Default: observed OS locale, then en-us. Inspect platform locale settings, then LC_ALL, LC_MESSAGES or LANG, discarding encoding/modifier and C/POSIX; normalize underscores to hyphens and lowercase. Use the configured locale for all agent-authored chat and writing, regardless of input language. Input language is not a language instruction; only an explicit owner response/target-language instruction overrides it. Preserve quoted input, fixed identifiers and established languages of localized artifacts. First initialization substitutes the detected default for the template's en-us.

- ag-dir defaults to .agentflow: a nonempty checkout-relative path without .. or symlink escape. notebook-name is a basename under ag-dir. If absent, derive `<stem>.devlog.md` from the physical checkout-root basename (verified session directory outside Git): lowercase ASCII, replace runs outside a-z/0-9 with `-`, trim `-`, take the first 32 characters and trim trailing `-`; empty stem → `devlog.md`. Example: `a002` → `a002.devlog.md`, `My Project!` → `my-project.devlog.md`. Reject empty names, either slash, absolute paths, control characters, . and .., .owner suffixes and existing directory/marker collisions; resolve notebook and ag-dir physically without checkout escape. Omit the key for the derived default. New configuration persists the derived name; preserve existing settings and notebooks, never silently rename or replace history. Explicit notebook selection may use another safe path; feature routing takes precedence. Resolve physical paths before ownership; changing settings does not authorize relocation.

- Except bundled assets/.agentflow/, .agentflow/<suffix> means <ag-dir>/<suffix>. Artifacts/features follow ag-dir; the root notebook follows <ag-dir>/<notebook-name>. Link established records rather than moving them for a setting change. Archives remain adjacent; STATUS names their actual paths. Optional local project rules, backlog and the default system registry are checkout-root `<ag-dir>/{rules,backlog,sys-invariants}.md`, independent of notebook/feature-record location; established authoritative records are reused, never implicitly moved.

## Automatic migration

Disk migration belongs only to the owner-facing host; delegates and isolated looper sessions may interpret documented legacy mappings in memory, with no configuration writes or release checks. No migration helper or recursive project sweep. On every ag.json read, migrate the selected project to this installed skill's current schema before dependent work; explicit owner opt-outs prevail. Missing files retain setup rules. Preserve valid owner choices rather than replacing them with template defaults.

- Confirmed predecessor: `schema-version: "aglite-5"` becomes integer `9`; review-order `external-first`, `native-first`, `host-only` become `external`, `native`, `host` respectively. Apply known obsolete value mappings even when the schema is already current. Missing schema uses current defaults without a write unless another mapping applies. Unknown/newer schemas, malformed JSON/types or unmapped invalid values stop dependent work with path/key/reason; never stamp a new version over unknown semantics.

- Preserve unknown and `//` keys, key order, worker metadata and valid nondefaults. Rename keys/values only with documented equivalent mappings; differing old/new values require an owner decision. Remove only documented obsolete fields with a lossless mapping; dropping an owner choice requires approval. Missing new keys follow defaults; add only fields required by a documented migration. Do not pin every new default. Schema changes include predecessor mappings, removals/additions and proving examples in this section; increment the integer once per schema revision.

- Reuse existing atomic-write rules: reject symlink/escaping targets, retain the original bytes in existing round evidence for recovery, verify unchanged source, write an exclusive adjacent temporary file, atomically rename and reread. On unchanged current input, write nothing. Migration grants no notebook relocation, task/worker dispatch or installation authority. Report changed keys once in the saved result; before notebook recovery retain the notice in session context. Explicit read-only constraints defer migration and dependent work. Off-record activation defers automatic migration without record access; an explicit off-record config edit follows its own authority without recording that exchange. A needed migration is authorized maintenance: resolve routing from the mapped in-memory config, then use normal notebook ownership/recovery and retain pre-edit bytes before writing; the bare-activation idle shortcut applies only when no migration is due. Feature lifecycle routing and root-notebook exclusions still prevail.

## Session release check

Only the owner-facing host checks releases on on-record activation, including idle. Read optional top-level `ag.json` `next_update_date`: null/missing means due; otherwise require a real UTC calendar date `YYYY-MM-DD`. Before that date, skip all release network requests across sessions. On/after it, query the latest stable [Agentflow release](https://github.com/agfnow/agentflow/releases) once; no aglite feed, updater, hooks, polling or background work. Delegates/isolated looper sessions, off-record exchanges and explicit read-only constraints do neither checks nor date writes. An invalid date is a disclosed upkeep error; preserve it and continue unrelated work.

After the lookup attempt, including failure/no release, set `next_update_date` to the current UTC date plus two calendar days, preserving other keys under the atomic unchanged-source/symlink-safe configuration rules. This narrow scheduling write is allowed during idle without notebook/claim/history creation; an absent config outside setup stays absent and uses only a session-local check guard. A changed/unsafe/unwritable config defers the date write, reports the limit and permits no repeat lookup in that session. No retry on lookup failure; normal work continues. The date is lookup scheduling only, never installation consent. Missing new keys use this due behavior; current-schema configurations need no schema bump for optional scheduling metadata.

Aglite is the beta name of the forthcoming Agentflow 9. Read installed name/version from resolved SKILL.md metadata; package version, if present, must agree. Use only `agfnow/agentflow` stable releases: installed aglite is eligible for its Agentflow 9+ successor, never Agentflow 8.x; installed Agentflow compares semantic versions within that product. Schema version is unrelated. Unparseable identity or no eligible newer stable release yields no update. A newer eligible release requires a short installed/latest notice and release link before the receipt, even with inline-reply off; an otherwise idle activation may show it without notebook access. Offer to prepare the update; replacement approval follows saved Questions after concrete preparation. Routine lookup results stay in existing evidence or idle session context, without new idle records.

Replacement always requires explicit owner approval first, including the beta-to-Agentflow 9 transition. Resolve the real installed path first. A symlink/source checkout or dirty installation requires a WIP-preserving route and approval of that concrete route; never overwrite source through a link. Prefer the installation’s supported skill/plugin updater after verifying its controls. Manual replacement is for unmanaged copies only: stage the named release outside the install, verify its approved product/name/version and destination identity, preserve a recoverable backup under the deletion policy, replace only the approved payload and reread its version. Reject changed/unsafe state; inspect partial results before retry. No publication or unrelated config rewrite follows.

## Worker settings

- Optional pipeline-roles maps advisor names, implementation and threeways to best|better|basic|cheap. model-family maps provider/tier to a model/effort string. Split at the final slash; require a string with nonempty model and effort, validate the effective pair against actual transport support. Catalog names are extensible, including gemini, openrouter and owner-defined names; preserve unrelated keys. Resolve the native catalog from observed active host/provider configuration or explicit owner choice; Codex/openai and Claude Code/claude are bundled examples, not a host allowlist. Ambiguous selection needs an owner decision. Catalog names identify model groups, not executable commands; use the active host’s actual model/effort controls, without new runtime adapters. A configured pair is dispatchable only when those controls honor both values; missing controls make planning/review routes unavailable under [review.md](review.md); for other work obtain an owner decision or leave the role unconfigured to inherit host defaults. Unsupported selected values still require a decision. Validate only selected roles, tiers and mappings; ignore // keys. Unused catalogs need no availability probe.

- For authorized native work use its advisor role (final-audit uses acceptance; pipeline-roles.final-audit is not used), implementation, acceptance for result review, threeways for planning without an advisor and for challenges; planning advisors retain their selected role. Missing role inherits host defaults; configured roles require their provider/tier pair. Apply each explicit owner field override before support validation; both explicit fields need no mapping. Missing/malformed/ambiguous/unsupported selected settings block dispatch without model substitution; continue independent work and report the exact key/decision. Valid ordinary result-review defaults permit the disclosed [planner-diversity exception](review.md#inspect-the-finished-result); task-level hard requirements remain fixed.

- External profiles retain unique id, nonempty command argument array and finite numeric priority; model-family references the shared catalog. Selected CLI identity must match the planning/review route; lower priority numbers win among usable matching profiles, ties use file order. Resolve its role/tier from that catalog; absent role uses transport defaults. Profiles do not grant executable or provider substitution authority.

- Pass model/effort through actual supported controls under [review.md](review.md#choose-a-worker); record source (setting/file name, never credential values), requested values, tool acceptance and real handle. Never claim runtime identity without evidence. Settings do not launch work or change the host model. For already-authorized work, plan-order permits bounded read-only planning/challenge dispatch; review-order permits required result review under [review.md](review.md). Neither grants external implementation, unrelated advisor work or sends. Supply necessary nonsecret context/source only; private personal/customer data needs explicit owner authority for the receiving provider.

## Switch effects

SKILL.md's one-task fast-lane overrides ordinary creation, delegation, review and RUN/WIP rules without changing these switches; its retained obligations, explicit owner requirements and configured gates prevail. The skip-review command overrides ordinary review for one task only; other steps/settings remain. Advisor selection adds no switches or dispatch authority.

- skip-asker on leaves Ask headings unnamed; off adds (<identity>) after the round ID. Use git config user.name in the checkout, then the OS account username; if unavailable omit it. Replace parentheses/control characters with spaces and collapse whitespace. Apply only to new Ask headings, never rewrite history; round parsers accept the optional suffix.

- inline-reply off uses SKILL.md's exact Updated receipt; on displays the complete saved Reply after verified closeout/delivery. For `append-rounds`, follow [batch transitions and output](../SKILL.md#append-rounds). Only an explicit request to display answers in chat/terminal overrides saved-only answers; “show me”, output examples and requests to change future output do not. Explicitly displayed answers and `inline-reply: on` still end with the two-line receipt. Required actual feature handoffs prevail; hypothetical handoffs stay saved. Required invariant/backlog notices supplement the receipt or handoff. Neither setting suppresses the saved answer or necessary unfinished-work reports.

- skip-run on omits `[RUN]`; off uses SKILL.md's milestone format. Retain evidence/decisions under [Round evidence](../SKILL.md#round-evidence), with lifecycle/recovery state in Current/tracker.

- skip-wip on omits `[WIP]`; off uses SKILL.md's checkpoint format. At ten-minute, interruption and context-reset boundaries, retain recovery in tracker/STATUS: finished/remaining work, actual handles, checks and next action. Recover from the latest applicable record. Log switches never suppress input, Reply, questions, ownership or checks.

- skip-plan off (default, preferred) preserves SKILL.md's normal decision process: the host decides whether design.md and a tracker are needed. on explicitly skips creating both, overriding ordinary creation criteria. Empty activation creates neither. Explicit owner requests for plans/trackers, plan-only limits, requested checkpoints and enabled gates prevail.

- plan-order accepts 3ways|external|native|host, default external. For already-needed planning (including planning advice and task grouping), start at the selected route and degrade only on inspected unavailability/failure: 3ways → external → native → host; external → native → host; native → host; host is terminal; skip duplicate failed probes and reuse usable plans. [Planning routes](review.md#planning-routes) keep Claude as lead where reachable, Codex as challenger, with honest fallback authorship. Explicit 3ways selects that route for one plan. Fast-lane uses host for retained/explicit planning unless the owner explicitly selects another task planning route. Host uses no worker probes. Invalid/unsupported selected settings require a decision; explicit provider/model/effort/independence/read-only constraints block incompatible fallback. Settings create no work, plan, advisor stage or implementation authority; task modes, requested plans and gates prevail.

- Result-review requirements and one-task exceptions follow SKILL.md; routing follows review.md.

- review-order accepts external|native|host, default external. For an already-required result review, external tries supported counterpart CLI → fresh-context native → labelled host fallback; native reverses the separate routes; host uses host directly without worker probes. Stop at the first usable permitted route. Separate result review uses acceptance, with [planner diversity](review.md#inspect-the-finished-result) ranking permitted separate routes/models before ordinary order/tier defaults. Record each route’s availability failure (missing transport controls/isolation/auth) before fallback; malformed or unsupported selected model/effort requires a decision, not another route. Required independence (including SKILL.md’s risk-boundary rule unless waived there) and explicit provider/model/effort/fresh-context/enforced-read-only requirements prevail over every order; same-message/later explicit review requests prevail over the skip-review command; use only compatible routes, leaving review pending if none is usable. When host conflicts with required independent review, use fresh-context native; external review requires explicit owner authority. Failed/empty reviewer output leaves review pending; inspect the failure before retry/fallback. This authorizes only bounded external result review and necessary nonsecret inputs, not external implementation/advisors or unrelated sends; host review is never independent.

- gate-design on saves a concrete design and pauses before implementation for owner approval; create the needed design even with skip-plan on. off adds no checkpoint. Previously granted explicit approval of that same design suffices; material contract changes require renewed approval. Continue independent authorized work; a default or empty answer is not approval.

- gate-tracker on pauses after all execution items and required checks/review pass, before final Reply/release, delivery commit or push; skip if tracker is absent. Present the concrete checked result and save the pending approval/next action. Save the approval request in tracker/Current or its linked report without a final Reply/next-Ask transition; retain the open-round claim. Keep overall state awaiting release approval, not complete; perform already-authorized pending release actions after approval without redoing unchanged checks. off adds no checkpoint. Explicit approval of that same checked result satisfies it. For merge-feature, the command-authorized feature snapshot commit and merge commit are prerequisite integration operations: perform them after feature verification, then check combined main; pause before destructive cleanup, final feature-record delivery commits, push and handoff. Keep gate state/claims only in feature-specific records, never main’s root notebook. These prerequisites do not bypass final release approval, and failed integration never reaches the gate. Requested stop/checkpoints still prevail.

## Git delivery

- Git initialization approval authorizes the bootstrap commit under [First-time setup](../SKILL.md#first-time-setup), even with auto-commit off, unless the owner explicitly forbids commits. Later delivery follows the switches below.

- After setup-time `git init`, limit first-delivery commits to verified task/setup changes; leave pre-existing unrelated contents untracked unless separately authorized. Approval to create a repository grants no authority to commit those contents; this exception overrides automatic owner-edit delivery below.

- auto-commit on makes the task commit first, containing all verified Ask changes, including records/settings. Then inspect and commit owner-authored edits and foreign work separately, including pre-existing edits. Inspect index/diffs before each commit; stage named paths/hunks and commit only its verified content, preserving other staging without reset. Exclude secrets. Uncertain authorship or unsafe separation blocks only affected delivery; report it. off grants no commit authority. Without Git, skip both controls.

- auto-push on pushes this checkout's task and separate owner-edit commits on its observed branch; off grants no push authority. With auto-commit off, push only already-committed authorized results. No remote: skip. Otherwise use upstream or the sole remote with explicit current branch. Detached/changed branch, ambiguous remote or unexplained outgoing commits block push. No force/pull/rebase/reset/stash. New-feature preparation and drop-feature stay uncommitted/unpushed; merge-feature follows feature-specific lifecycle rules after verified integration/checks and gate approval, excluding main’s root notebook/archive/claim and unrelated owner-edit delivery.

- After checks/review/gates, save and verify Reply/next Ask; commit task records, then owner edits separately, then push if enabled. Retain claims during active delivery. For a verified closed round with blocked/unknown delivery, save recovery and settle workers/processes, then release the claim at turn yield under SKILL.md; retain unfinished status. Open-round and feature-lifecycle exceptions remain. Verify commit paths and remote tip; rejected/unknown push stays unfinished. Inspect identities before retry. Rebind this session's claim to the next Ask before notebook mutation; record delivery failure/next action in the tracker, or Current without one, and link canonical recovery from STATUS Current under SKILL.md’s Round evidence rules; honor legacy Ask links; preserve Reply. Outside feature lifecycle operations, before a later round delivers, reconcile attributed prior-round paths/hunks, index entries, local commits and remote target. Finish that already-authorized delivery first, or commit safely separated attributed prior-round work before the new task commit; missing attribution/authority blocks affected delivery, never silently absorbs earlier work or unrelated staging. Preserve separate-repository boundaries. Report material local-only/blocked state. Never create another commit/push merely to log successful hashes. Settings grant no release/deployment/send/cleanup or unrelated-repository authority. Failed or unavailable required checks block delivery commits/pushes, not recovery records. Before staging, record justified check exceptions for byte-preserved history/captures in tracker/notebook; never rewrite those bytes or waive failures in task-authored content.

## Notebook routing and rename

Unless the idle shortcut applies, on activation route and claim under SKILL.md, then refresh the selected notebook's STATUS path; an existing configured notebook needs no relocation. If the configured path is missing, inspect root/configured work-directory notebook/archive candidates before setup; known history or ambiguity requires owner selection, never a replacement notebook. A setting change alone does not authorize moving files or abandoning unresolved work.

For an explicit rename, use existing identity, ownership and delivery rules. Claim source and exclusively reserve destination for the same session/Ask; reject collisions, foreign claims and routing/path violations. Include its single adjacent archive in the rename: discover it from STATUS and `<old-notebook-stem>.archive.md`; replace only the notebook stem (remove its final `.md`, if present). Example: `devlog.md` and `devlog.archive.md` → `notes.md` and `notes.archive.md`. Reconcile STATUS with disk; missing listed archives or ambiguous/custom association (including another notebook sharing the stem or an archive-shaped name) requires owner selection. Include the verified unlisted stem archive; multiple archives require owner reconciliation, not automatic merging. No archive means none to rename. Preflight every source/destination and affected live link before any move; reject unsafe paths, collisions, foreign claims and concurrent changes. Recheck unchanged source/config and both claims; move notebook and associated archives without overwrite, verifying each file’s historical bytes at its destination before STATUS/live-link edits. For a destination outside ag-dir, obtain authorized routing (ag-dir change or explicit notebook selection); never encode a path in notebook-name. Update the basename atomically when applicable, STATUS and affected live links; verify all old paths absent and new history/config/live links correct, then close out at the destination and release only own claims after delivery. Ignore each marker locally.

Same-directory stem renames include associated archives under the explicit notebook-rename authority; update affected live links, preserve historical bytes. Directory relocation or historical-link edits need explicit authority. Before any rename/relocation, check unchanged historical links, including notebook/archive filenames; broken links stop for owner reconciliation. On interruption, retain claims and each notebook/archive source, destination and observed move state; inspect partial state before retry and report recovery paths, including a moved notebook with incomplete archives/configuration. Never recreate, overwrite or clear claims to recover.

## Looper settings

Optional `looper-routes` maps `task`, `repair`, `acceptance` to `{ "kind": "native|cli", "provider": "transport-provider", "model-family": "catalog" }`; optional `executable` is CLI-only. Native catalogs are explicit and extensible; CLI providers remain codex/claude. Do not store model/effort in routes or queue settings.

Task/repair use `pipeline-roles.implementation`; review/renewed acceptance share the acceptance route and `pipeline-roles.acceptance`. Split the selected catalog/tier pair at its final slash. Missing selected routes/tiers/mappings or unsupported controls block with the exact key; the shell coordinator has no host defaults. Unused optional routes need no probe. Empty bundled routes require configuration before a run; do not infer a host or silently substitute route/provider settings; host schema migration follows the rules above.

Optional `looper-limits` holds `max-workers` (positive integer, default 3) and `max-repairs` (nonnegative integer, default 2). These are settings, not switches. Limits and routes belong only in ag.json; reject queue worker/limit overrides.

## Looper execution exception

[Looper](looper.md) uses `queue.json` schema 2, separate from `ag.json` schema 9. Retain ordinary workflow, review routing and executor/provider/model/effort choices; unavailable selected controls block without substitution. Settings alone grant no execution authority. Native work requires the live host’s dispatch/result mailbox; CLI ordinary task sessions support Codex/Claude. No absent-host CLI fallback.

Read settings once per run invocation; save each new attempt’s resolved selection and source digest/route/tier as immutable evidence. Outstanding attempts retain their selections on resume; new attempts use that invocation’s settings. Lowered limits restrict new dispatch; outstanding native task/repair results still import before future routes are resolved. Status reads scheduling state without requiring valid current worker settings. Task records live in each group worktree’s `.aglite-records/`, excluded from product integration. The coordinator alone writes queue state and integrates against the protected target. Groups may register earlier-group dependencies under the execution contract; waiting needs no worker slot and launch follows checked predecessor integration. No group gates, waves, final gate or promotion setting remains. No unrelated helper, shared-record write, publication, cleanup or owner-only decision authority follows.
