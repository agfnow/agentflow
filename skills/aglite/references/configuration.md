# Configuration

Host-driven; no hooks/runners/helpers. Read before routing on activation and each later on-record owner message, and before configuration-dependent delivery. Apply the off-record exception first.

## Discovery and validation

- Configuration is <checkout>/ag.json; outside Git use the verified original session folder. In a Git subdirectory use the Git root; a managed feature uses its own checkout-root file, never main's live file. Do not recursively search or use STATUS as configuration.

- Require JSON and switches objects; absent file/keys use defaults. Ignore // keys for behavior; preserve unrelated properties and external-workers. Validate selected worker fields and recognized review switches below when needed. If schema-version is supplied, require aglite-5; unsupported schemas stop dependent work without implicit migration. Invalid JSON, types or recognized values stop dependent work with path/key/error; never reset. Owner instructions override settings without persisting them unless requested. Missing keys need no write. An unresolved Ask binds the session to its owned notebook: changed routing or notebook selection requires owner-authorized handoff/relocation reconciling work and claims. Apply other switch changes there. Main-rooted `new-feature` may prepare only its independent feature-local notebook under [features.md](features.md), after features.md’s own-claim checkpoint/release when needed, without transferring/closing the root Ask or changing root routing/configuration.

- Update only requested properties after checking the source is unchanged; atomically rename an adjacent temporary file, then reread. Create new files exclusively; never replace existing configuration with the template. Maintain the string schema-version (currently `aglite-5`) with configuration-schema revisions; retain the `aglite-` prefix; preserve // keys and unrelated worker metadata. Maintain ascending switch names in the bundled template. Configuration selects settings only for already-authorized work.

- Nine Boolean switches accept exactly on|off. Defaults: skip-asker on; inline-reply off; skip-run on; skip-wip on; skip-plan off; gate-design off; gate-tracker off; auto-commit on; auto-push on.

- use-lang accepts a nonempty locale tag (case-insensitive language plus optional script/region, hyphen or underscore). Default: observed OS locale, then en-us. Inspect platform locale settings, then LC_ALL, LC_MESSAGES or LANG, discarding encoding/modifier and C/POSIX; normalize underscores to hyphens and lowercase. Use the configured locale for all agent-authored chat and writing, regardless of input language. Input language is not a language instruction; only an explicit owner response/target-language instruction overrides it. Preserve quoted input, fixed identifiers and established languages of localized artifacts. First initialization substitutes the detected default for the template's en-us.

- ag-dir defaults to .agentflow: a nonempty checkout-relative path without .. or symlink escape. notebook-name is a basename under ag-dir. If absent, derive `<stem>.devlog.md` from the physical checkout-root basename (original session folder outside Git): lowercase ASCII, replace runs outside a-z/0-9 with `-`, trim `-`, take the first 32 characters and trim trailing `-`; empty stem → `devlog.md`. Example: `a002` → `a002.devlog.md`, `My Project!` → `my-project.devlog.md`. Reject empty names, either slash, absolute paths, control characters, . and .., .owner suffixes and existing directory/marker collisions; resolve notebook and ag-dir physically without checkout escape. Omit the key for the derived default. New configuration persists the derived name; preserve existing settings and notebooks, never silently rename or replace history. Explicit notebook selection may use another safe path; feature routing takes precedence. Resolve physical paths before ownership; changing settings does not authorize relocation.

- Except bundled assets/.agentflow/, .agentflow/<suffix> means <ag-dir>/<suffix>. Artifacts/features follow ag-dir; the root notebook follows <ag-dir>/<notebook-name>. Link established records rather than moving them for a setting change. Archives remain adjacent; STATUS names their actual paths. Optional local project rules, backlog and the default system registry are checkout-root `<ag-dir>/{rules,backlog,sys-invariants}.md`, independent of notebook/feature-record location; established authoritative records are reused, never implicitly moved.

## Worker settings

- Optional pipeline-roles maps advisor names, implementation and threeways to best|better|basic|cheap. model-family maps provider/tier to a model/effort string. Split at the final slash; require a string with nonempty model and effort, validate the effective pair against actual transport support. Catalog names are extensible, including gemini, openrouter and owner-defined names; preserve unrelated keys. Resolve the native catalog from observed active host/provider configuration or explicit owner choice; Codex/openai and Claude Code/claude are bundled examples, not a host allowlist. Ambiguous selection needs an owner decision. Catalog names identify model groups, not executable commands; use the active host’s actual model/effort controls, without new runtime adapters. A configured pair is dispatchable only when those controls honor both values; missing controls make result-review or `3ways` routes unavailable under [review.md](review.md); for other work obtain an owner decision or leave the role unconfigured to inherit host defaults. Unsupported selected values still require a decision. Validate only selected roles, tiers and mappings; ignore // keys. Unused catalogs need no availability probe.

- For authorized native work use its advisor role (final-audit uses acceptance; pipeline-roles.final-audit is not used), implementation, acceptance for result review, threeways for approach challenge. Missing role inherits host defaults; configured roles require their provider/tier pair. Apply each explicit owner field override before support validation; both explicit fields need no mapping. Missing/malformed/ambiguous/unsupported selected settings block dispatch without model substitution; continue independent work and report the exact key/decision.

- External profiles retain unique id, nonempty command argument array and finite numeric priority; model-family references the shared catalog. Supported counterpart command identity must match the requested host route; lower priority numbers win among usable matching profiles, ties use file order. Resolve its role/tier from that catalog; absent role uses transport defaults. Profiles do not grant executable or provider substitution authority.

- Pass model/effort through actual supported controls under [review.md](review.md#choose-a-worker); record source (setting/file name, never credential values), requested values, tool acceptance and real handle. Never claim runtime identity without evidence. Settings do not launch work, change the host model or authorize external implementation/advisors. Review routing authority is limited to the review-order rule below and requested `3ways` under [review.md](review.md#3ways-compare-before-implementation); it covers sending necessary review inputs without credentials or private personal/customer data unless the owner explicitly authorizes that data to that counterpart provider, not unrelated messages or disclosures.

## Switch effects

SKILL.md's one-task fast-lane overrides ordinary creation, delegation, review and RUN/WIP rules without changing these switches; its retained obligations, explicit owner requirements and configured gates prevail. The skip-review command overrides ordinary review for one task only; other steps/settings remain. Advisor selection adds no switches or dispatch authority.

- skip-asker on leaves Ask headings unnamed; off adds (<identity>) after the round ID. Use git config user.name in the checkout, then the OS account username; if unavailable omit it. Replace parentheses/control characters with spaces and collapse whitespace. Apply only to new Ask headings, never rewrite history; round parsers accept the optional suffix.

- inline-reply off uses SKILL.md's exact Updated receipt; on displays the complete saved Reply after verified closeout/delivery. Explicit full-answer requests and required feature handoffs prevail; required invariant/backlog notices supplement the receipt or handoff. Neither setting suppresses the saved answer or necessary unfinished-work reports.

- skip-run on omits `[RUN]`; off uses SKILL.md's milestone format. Retain evidence/decisions under [Round evidence](../SKILL.md#round-evidence), with lifecycle/recovery state in Current/tracker.

- skip-wip on omits `[WIP]`; off uses SKILL.md's checkpoint format. At ten-minute, interruption and context-reset boundaries, retain recovery in tracker/STATUS: finished/remaining work, actual handles, checks and next action. Recover from the latest applicable record. Log switches never suppress input, Reply, questions, ownership or checks.

- skip-plan off (default, preferred) preserves SKILL.md's normal decision process: the host decides whether design.md and a tracker are needed. on explicitly skips creating both, overriding ordinary creation criteria. Empty activation creates neither. Explicit owner requests for plans/trackers, plan-only limits, requested checkpoints and enabled gates prevail.

- Result-review requirements and one-task exceptions follow SKILL.md; routing follows review.md.

- review-order accepts external-first|native-first|host-only, default external-first. For an already-required result review, external-first tries supported counterpart CLI → fresh-context native → labelled host fallback; native-first reverses the separate routes; host-only uses host directly without worker probes. Stop at the first usable permitted route. Separate result review uses acceptance. Record each route’s availability failure (missing transport controls/isolation/auth) before fallback; malformed or unsupported selected model/effort requires a decision, not another route. Required independence (including SKILL.md’s risk-boundary rule unless waived there) and explicit provider/model/effort/fresh-context/enforced-read-only requirements prevail over every order; same-message/later explicit review requests prevail over the skip-review command; use only compatible routes, leaving review pending if none is usable. When host-only conflicts with required independent review, use fresh-context native; external review requires explicit owner authority. Failed/empty reviewer output leaves review pending; inspect the failure before retry/fallback. This authorizes only bounded external result review and necessary nonsecret inputs, not external implementation/advisors or unrelated sends; host review is never independent.

- gate-design on saves a concrete design and pauses before implementation for owner approval; create the needed design even with skip-plan on. off adds no checkpoint. Previously granted explicit approval of that same design suffices; material contract changes require renewed approval. Continue independent authorized work; a default or empty answer is not approval.

- gate-tracker on pauses after all execution items and required checks/review pass, before final Reply/release, delivery commit or push; skip if tracker is absent. Present the concrete checked result and save the pending approval/next action. Keep overall state awaiting release approval, not complete; perform already-authorized pending release actions after approval without redoing unchanged checks. off adds no checkpoint. Explicit approval of that same checked result satisfies it. For merge-feature, the command-authorized feature snapshot commit and merge commit are prerequisite integration operations: perform them after feature verification, then check combined main and any authorized cleanup; pause before final delivery-record commits, push and handoff. These prerequisites do not bypass final release approval, and failed integration never reaches the gate. Requested stop/checkpoints still prevail.

## Git delivery

- auto-commit on makes the task commit first, containing all verified Ask changes, including records/settings. Then inspect and commit owner-authored edits and foreign work separately, including pre-existing edits. Inspect index/diffs before each commit; stage named paths/hunks and commit only its verified content, preserving other staging without reset. Exclude secrets. Uncertain authorship or unsafe separation blocks only affected delivery; report it. off grants no commit authority. Without Git, skip both controls.

- auto-push on pushes this checkout's task and separate owner-edit commits on its observed branch; off grants no push authority. With auto-commit off, push only already-committed authorized results. No remote: skip. Otherwise use upstream or the sole remote with explicit current branch. Detached/changed branch, ambiguous remote or unexplained outgoing commits block push. No force/pull/rebase/reset/stash. New-feature preparation and drop-feature stay uncommitted/unpushed; merge-feature follows lifecycle rules after verified integration/records and gate approval.

- After checks/review/gates, save and verify Reply/next Ask; commit task records, then owner edits separately, then push if enabled. Retain claims until delivery settles. Verify commit paths and remote tip; rejected/unknown push stays unfinished. Inspect identities before retry. Rebind this session's claim to the next Ask before notebook mutation; record delivery failure/next action in the tracker, or Current without one, and put a labelled recovery link in that Ask without duplicating that state; preserve Reply. Report material local-only/blocked state. Never create another commit/push merely to log successful hashes. Settings grant no release/deployment/send/cleanup or unrelated-repository authority. Failed or unavailable required checks block delivery commits/pushes, not recovery records. Before staging, record justified check exceptions for byte-preserved history/captures in tracker/notebook; never rewrite those bytes or waive failures in task-authored content.

## Notebook routing and rename

Unless the idle shortcut applies, on activation route and claim under SKILL.md, then refresh the selected notebook's STATUS path; an existing configured notebook needs no relocation. If the configured path is missing, inspect root/configured work-directory notebook/archive candidates before setup; known history or ambiguity requires owner selection, never a replacement notebook. A setting change alone does not authorize moving files or abandoning unresolved work.

For an explicit rename, use existing identity, ownership and delivery rules. Claim source and exclusively reserve destination for the same session/Ask; reject collisions, foreign claims and routing/path violations. Include its single adjacent archive in the rename: discover it from STATUS and `<old-notebook-stem>.archive.md`; replace only the notebook stem (remove its final `.md`, if present). Example: `devlog.md` and `devlog.archive.md` → `notes.md` and `notes.archive.md`. Reconcile STATUS with disk; missing listed archives or ambiguous/custom association (including another notebook sharing the stem or an archive-shaped name) requires owner selection. Include the verified unlisted stem archive; multiple archives require owner reconciliation, not automatic merging. No archive means none to rename. Preflight every source/destination and affected live link before any move; reject unsafe paths, collisions, foreign claims and concurrent changes. Recheck unchanged source/config and both claims; move notebook and associated archives without overwrite, verifying each file’s historical bytes at its destination before STATUS/live-link edits. For a destination outside ag-dir, obtain authorized routing (ag-dir change or explicit notebook selection); never encode a path in notebook-name. Update the basename atomically when applicable, STATUS and affected live links; verify all old paths absent and new history/config/live links correct, then close out at the destination and release only own claims after delivery. Ignore each marker locally.

Same-directory stem renames include associated archives under the explicit notebook-rename authority; update affected live links, preserve historical bytes. Directory relocation or historical-link edits need explicit authority. Before any rename/relocation, check unchanged historical links, including notebook/archive filenames; broken links stop for owner reconciliation. On interruption, retain claims and each notebook/archive source, destination and observed move state; inspect partial state before retry and report recovery paths, including a moved notebook with incomplete archives/configuration. Never recreate, overwrite or clear claims to recover.
