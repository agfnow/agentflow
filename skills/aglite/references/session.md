# Session recovery and ownership

Read for actual owned on-record work, including Q&A, after the entrypoint’s off-record, isolated-looper, lifecycle, setup and idle guards. Those exceptions prevail. Read [delivery](delivery.md) only when updating/rendering STATUS, Reply or next Ask, closing out, archiving, renaming or performing configured Git delivery. Q&A alone requires neither planning nor execution procedures.

## Activate and recover

Apply [entrypoint routing](../SKILL.md#route-before-records) first; it owns off-record/looper/lifecycle/setup/idle ordering, command alias and early guards. Configuration owns discovery/migration and date-gated release checks; owner-facing hosts apply those checks, delegates/isolated loopers do not. Apply configured switches throughout; with `saving-mode: on`, load [saving mode](saving-mode.md) before authoring and pass it to report authors. `.agentflow/` means configured ag-dir except literal bundled assets; configuration is `<checkout>/<ag-dir>/ag.json`, root notebook `<ag-dir>/<notebook-name>`. Explicit/feature routing and absent-notebook history checks still apply.

1. Verify physical startup directory or verified `/cd` binding, Git root/branch/worktrees (outside Git, existing folder and Branch N/A) before recovery/writes. Apply entrypoint missing/Trash/contradictory-identity stops: only read-only inspection, verified feature directory transition or bounded terminal cleanup of an already-authorized own-feature drop/post-cleanup merge-delivery recovery is allowed. Never recreate/fall back. On lifecycle requests, managed `<main>/.wts/` paths/subdirectories or feature branches, read [features](features.md) before routing/execution; authorized `aglite-*` looper worktrees instead use their execution contract’s explicit isolated notebook. Features governs routing, STATUS rejection and handoffs. Lifecycle bypasses main/root notebook/claim/recovery/capture/closeout; root state cannot block it. Creation/merge records stay feature-specific, drop results in chat; no root retirement record/replacement ledger. Read [Windows](windows.md) for Windows/explicit portability operations. Subprocess cwd cannot relocate the session; only a verified Codex/Claude Code `/cd` handoff under features may rebind subsequent identity/routing. Never delete startup checkout/ancestors except explicitly authorized terminal cleanup of its successfully merged/dropped own feature under that contract.

2. Missing managed-feature notebooks follow [features](features.md), never generic setup. Outside a managed feature, use the explicitly supplied notebook or `<ag-dir>/<notebook-name>` (default name derived under configuration). A feature branch outside the managed layout requires an explicit local notebook. If absent and the idle shortcut did not apply, follow [setup](setup.md#first-time-setup) after identity/routing checks. For an existing notebook, read only the latest Ask heading needed to claim it, then follow [Notebook ownership](#notebook-ownership) before STATUS, full recovery or task execution, unless the idle shortcut applies. Reread under ownership and reconcile the Ask before continuing. Inspect Git status when available and preserve unrelated edits; isolate or stop writes conflicting with another writer.

3. Read the active Ask through its end, linked plan/design/tracker and latest applicable recovery record. On restart/resume follow STATUS Current and active/next Ask recovery links; before dependent work read tracker Recovery plus linked evidence, or Current’s direct evidence without a tracker. Verify notebook/Ask identity and proof against live files/handles. Missing/mismatched evidence leaves dependent claims unproved; never assume completion or treat arbitrary `.tmp` search as authority. Search live `ans:`, `-> ask:`, `-> ans:` and question IDs; read surrounding questions and later resolutions. Skip handled questions only if the named Reply fully answers them; newer corrections prevail. Read evidence relevant to active work/reviewed claims; reconcile files, Git and handles. Empty answers, defaults and stale state are not approval. Under ownership, a selected STATUS with old `Configuration: … schema v8` or combined `Current commit` and `Open`/`Streams` fields loads [legacy projection recovery](legacy-migration.md#apply-and-recover) before dependent work; no preclaim/history sweep or lifecycle root probe. Recover pending [batches](batches.md) before declaring idle. Bare `godev` resumes nonempty work; empty Ask/no pending uses the idle shortcut.

4. Before task edits, copy each unrecorded manually authored owner chat/terminal message in order; stage explicit `append-rounds` messages and corrections explicitly targeting a pending batch under [batches](batches.md) instead of inserting them into the active Ask; exclude feature-lifecycle exchanges/results from root-notebook capture and later summaries, following features.md instead; leave content already authored in the Ask unchanged. Preserve message contents except credential redactions and these capture prefixes: prepend `+ ` to each blank-line-delimited prose paragraph; related paragraphs about one matter may share one prefix on the first paragraph. Preserve code-block interiors and existing `+ ` prefixes; separate groups with a blank line. Add no standalone `--`, blockquote prefixes or closing separator. Exclude host-injected context even when carried in a user-role message (e.g. AGENTS.md instructions, environment metadata, skill/system wrappers). Use message provenance, not role or headings alone; preserve such text when the owner quotes it as task input. Insert owner messages immediately before the active Ask’s first RUN/WIP/Reply heading; if none exists, append after its existing input. Never place owner input inside RUN/WIP. Redact credentials with an explicit secure-location reference. Carry recovered answers with their source; append a current-round resolution naming the original question. Preserve historical bytes except authorized owner-input insertion or explicit owner-authorized capture corrections; verify placement before delivery.

5. Before task work, follow [Project rules and backlog](#project-rules-and-backlog), then read [system invariants](invariants.md) and follow its discovery, applicability and maintenance rules, even without a design/tracker. Infer outcome, scope and observable success from the whole Ask. Challenge mistaken premises, infeasible approaches or needless complexity with reasons and a workable alternative; distinguish facts from uncertainty. Respect informed owner choices and existing authorization. Ask only for material missing decisions, requested checkpoints or new authority; continue independent work meanwhile. Corrections steer the task; questions do not cancel it. Activation alone authorizes only eligible first-time setup, never invented project tasks.

## Project rules and backlog

- After identity/ownership and capture on actual work/setup, read [shared project rules](project-rules.md), then established local rules (default checkout-root `<ag-dir>/rules.md`) if present. Preserve rules; never copy the baseline locally or merge automatically. Report unavailable authority/conflicts; defer dependent shared-record writes and invariant/review acceptance, continuing independent authorized work. Configured ag-dir is independent of notebook/feature paths. No idle adoption; host uses direct file operations, no helper.

- Before creation/adoption, discover established rules/backlog/registry from root directives/current records. Different established paths or missing referenced authority require owner routing/reconciliation; explicitly “if present” references remain optional. Never overwrite authority or duplicate records/local-file directives. During [setup](setup.md#first-time-setup), create missing [backlog](../assets/.agentflow/backlog.md)/empty [registry](../assets/.agentflow/sys-invariants.md); otherwise only for the first trackable item/accepted durable guarantee respectively. Reuse owner-designated records. Foreign backlogs are read-only for deduplication absent append/move authority. Registry entries follow [invariants](invariants.md). Owner-authorized moves preserve entries/links; no automatic migration or replacing known custom records because defaults are missing.

- Reconcile relevant backlog entries at actual task recovery, relevant decisions/corrections/deferrals and before closeout, never an idle/timed sweep: capture actionable future work from owner discussion/questions as proposed, explicit accepted deferrals as deferred; exclude off-record exchanges, ordinary explanations, speculative agent suggestions and completed work; deduplicate preserving corrections, update changed status/outcome/reasons, record source/outcome/open reason/effort or next decision, and notify the owner with ID/status/reason/link. Entries, questions, defaults and elapsed time grant no execution authority; bare activation never schedules them. Save proved completion or explicit owner cancellation in the notebook before removing its entry; never infer cancellation. Preserve other open entries; never clear backlog during setup. Move owner-scheduled work with its source into the active tracker/notebook.

- At actual recovery, surface relevant backlog dependencies/overlaps; ask only for material unresolved decisions. At closeout, add backlog Questions only for unresolved choices affecting active work, with B-NNN links and suggested defaults; do not repeat unchanged entries solely as reminders. On explicit backlog/next-work requests, show short prioritized candidates with reasons, dependencies and effort; await owner selection before scheduling. Idle activation never scans/schedules backlog; timed reminders require an explicit owner request.

Encountered old Agentflow startup/manual-writer directives first follow [authorized legacy correction](legacy-migration.md#hooks-and-startup), not silent duplicate adoption. On actual work or setup, check root AGENTS.md and add missing directives under [adoption](setup.md#agents-adoption) after discovery above; no idle/off-record adoption.

## Notebook ownership

- After the idle check, at first notebook access after routing, resolve its physical path (the physical parent plus filename if new), discover only its claim Ask ID, and exclusively create `.<notebook-basename>.owner` beside it (e.g. `.devlog.md.owner`) with `fs.openSync(path, 'wx')` or equivalent before recovery or task execution; never check then overwrite. Store JSON `{session, ask, claimed_at}`. Use the actual host session ID, or generate one UUID and retain it across turns and compaction in host session context; never use a tool PID or host name. Reading an ID from a marker or notebook is not proof of session identity; lost identity requires explicit handoff. In Git, ignore each marker with an exact notebook-relative rule in the local exclude file; never commit it.

- An existing marker permits only the same session and Ask. Foreign, empty, malformed or mismatched activation claims immediately block execution; report the valid marker fields (session, ask, claimed_at), or the parse defect, and an exact-notebook takeover request in chat without writing the blocked notebook. Do not infer a cause or live owner from marker age. Other notebooks remain independently claimable.

- Only for a late ownership conflict after task work began: stop further task edits, retain results and retry exclusive acquisition after waits of 60, 120 and 180 seconds (three retries over six minutes); never clear/overwrite a claim or rerun task effects. Defer the conflict report until exhaustion; then report the refusal fields above and unsaved result. After acquisition, reread STATUS, the latest Ask/Reply and resolutions; reconcile newer instructions and actual files. Reuse only an empty trailing Ask with no unresolved work in that Ask (separately staged batches do not occupy it), or append a separate unused Ask at EOF after a closed round, with the original request/source and retained result; never insert into another round or bury pending work. An occupied/unresolved tail or unsafe reconciliation stops writes for an owner decision. Rebind only this session's verified marker to the receiving Ask before mutation; per-mutation checks still apply.

- Before every notebook mutation, verify the marker still matches this session and Ask, including input capture, RUN/WIP, STATUS, archive and Reply. Retain an acquired claim across turns while the round is open; a verified Reply plus next Ask closes that round even when recovery remains; the idle shortcut creates no claim. If a reread within an already-claimed turn shows the Ask advanced, reconcile and rebind only this session's verified marker before task work; a foreign or unexplained mismatch remains blocked.

- After verifying Reply plus the next Ask, finish immediately possible authorized delivery while retaining the claim. Before yielding, settle all task-owned workers and mutating operations. If one cannot be settled, retain the claim, save its live handle and next action in Current/tracker, and report blocked claim release. Inspect immediately available external identities first. If delivery is blocked or its external result remains unknown after the process settles, verify saved authority, operation identities, unfinished state and next action in Current/tracker. For pending Git delivery, attribute exact prior-round paths/hunks, index entries, local commit IDs and remote target; preserve other staging and delivery boundaries. Then recheck ownership and release only this session's marker under the owner's deletion policy, even with carried recovery or unfinished delivery. A task-owned process that may still mutate, failed recovery persistence or an unverified round transition blocks claim release. An unknown external result from a settled process does not. Reacquire and reread before later task work, notebook mutation or delivery retry; inspect saved external identities before retry. Open means no verified Reply-plus-next-Ask transition. Open-round pauses, abrupt interruption and feature-lifecycle exceptions retain existing claim rules; activation with a same-session Ask mismatch still requires explicit handoff. Read owner answers at their existing question locations after claiming and rereading a released closed round. Foreign/stale claims require explicit owner-authorized clearing or handoff; never infer release from a Reply alone, age, silence or process state. Release grants neither completion nor approval.

- Hosts execute these filesystem operations directly; no helper, write lock, heartbeat or daemon. This coordinates cooperating agents, not unrestricted editors. Feature lifecycle commands never use main’s root notebook/claim; feature-notebook exceptions follow the feature reference.

## Round evidence

Round reports/related records (designs, trackers, briefs, raw evidence, captures) use `<ag-dir>/artifacts/A-NNN/` relative to the selected checkout/folder, including managed features; A-NNN is the producing Ask. Create only needed files; use unused names for inherited/unrelated collisions, never overwrite. Source/product files, notebooks/archives and ownership markers keep their own paths; explicit owner destinations prevail. Preserve existing locations; link carried work instead of copying it each round. Workflow proof follows the exception below; link needed raw evidence. No owner-facing verification report unless requested.

Keep technical verification, check/review results, invariant accounting and debugging logs out of devlog STATUS, RUN/WIP and Reply: no Verification sections, proof paragraphs or detailed logs. Omit routine detail lacking concrete recovery/review/decision use. Save needed new evidence under `<ag-dir>/.tmp/A-NNN.md`; an existing tracker keeps task/recovery state and links this evidence rather than duplicating it. For non-root notebooks use `<ag-dir>/.tmp/<notebook-basename>/A-NNN.md`. Explicit destinations prevail; preserve established records/history without automatic moves/reformatting. No mandatory per-round file follows. Identify physical notebook/Ask and verify namespace before reuse. Foreign/ambiguous collisions require safe unused locations, never replacement. Reject escapes/symlinks; create exclusively; before updates verify this session’s claim and unchanged source.

Before interruption/handoff, link all resume-critical evidence from STATUS Current directly or via tracker Recovery, and from its producing Ask before Reply. Each pointer states supported facts and next safe action. Keep Current linked to canonical recovery while work remains; honor legacy Ask links without copying them into new Asks. Link every unfinished thread and its authority in one tracker; when fast-lane waives tracker creation, use labelled Current pointers to existing recovery evidence instead. Establish links before omitting next-Ask pointers or archiving their sole legacy pointer; never remove historical links. Retain pointers as STATUS advances until dependent work settles; filenames alone cannot provide recovery. Other proof needs only its producing Ask link. Despite `.tmp`, linked evidence is durable: never automatically ignore/delete it. In Git, check ignore rules before creating/linking; use an unused nonignored artifacts path when needed, and include the record in authorized delivery. Keep unfinished state/authority/next action in Current/tracker; questions stay at existing answer locations. Off-record/idle rules prevail.

Lifecycle recovery required by features.md retains notebook/Ask identity, authorized operation/cleanup scope, exact retry-prevention refs, last proven result and next safe action. Link existing proof; retain pending gates/path updates and details needed for unresolved failures, required checks/review or consequential decisions. Omit repeated check results/explanations, never fresh safety checks. No new record location/mandatory report; drop has no durable record. Preserve historical evidence.

New evidence retains only recovery, required review/proof or consequential-decision support: concise check/results for reuse, source/scope, useful finding resolutions, unresolved failures, authority/identity and proof limits. Omit source-reproducible routine detail; never prune existing linked records. Group same-reason N/A IDs; omit repeated unchanged statements, command transcripts and hashes unless exact identity matters. Link existing proof instead of duplicating it. Evidence location never waives checks/review or turns missing proof into a pass. The devlog retains concise outcome/recovery pointers, required RUN/WIP milestones and notices, answers, Questions and decision-changing blockers/limits; link proof instead of copying it.
