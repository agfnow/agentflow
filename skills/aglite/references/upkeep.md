# Configuration and installation upkeep

Load only for a needed migration/relocation or concrete installation-update preparation. Apply off-record, read-only, delegate, isolated-session and feature-lifecycle exclusions before upkeep; explicitly authorized off-record product/config edits retain their own authority and create no workflow records. Discovery, validation and atomic configuration-write rules remain in [configuration](configuration.md#discovery-and-validation).

## Automatic migration

Disk migration belongs only to the owner-facing host; delegates and isolated looper sessions may interpret documented legacy mappings in memory, with no configuration writes or release checks. No migration helper or migration across nested projects. On every ag.json read, migrate the selected project to this installed skill's current schema before dependent work; explicit owner opt-outs prevail. Missing files retain setup rules. Preserve valid owner choices rather than replacing them with template defaults. Recognized Agentflow8 and schema-less v8 markers first follow [legacy migration](legacy-migration.md#eligibility-and-preflight); do not stamp8→12 through the later-format mappings below. Before documented migration, or an explicit migration request, inspect only existing project `.claude/settings.json`, `.codex/hooks.json` and effective Git pre-commit for known Agentflow stop-hook/devlog-guard markers; a hit loads [integration retirement](legacy-migration.md#hooks-and-startup). Resolve actual ownership/scope there before protected effects; no every-session integration sweep.

- Known predecessors: integers `9`/`10`/`11` or string `aglite-5` → integer `12`; retain review-order mappings `external-first` → `external`, `native-first` → `native`, `host-only` → `host`. Rename `skip-asker` → `omit-asker`, `skip-run` → `omit-run`, and `skip-wip` → `omit-wip`, retaining on|off. Map `skip-plan: off` → `plan-mode: optional`, `skip-plan: on` → `plan-mode: off`; the owner accepts that needed trackers become permitted. Apply obsolete mappings even at current schema; equivalent old/new pairs collapse, differing pairs stop with path/keys. Preserve absent schema unless migration needs a stamp; validate old values first. Unknown/newer schemas, malformed types and unmapped values stop without reset. Gate-design on + plan-mode off remains a settings conflict before task edits.

- Schema 11 → 12 changes only the schema stamp; absent `saving-mode` means off and absent `native-workers` retains existing resolution. Add neither key during migration. Schema 12 adds the optional switch/native binding; preserve all existing settings and immutable attempt selections. Example: schema-11 custom catalogs/roles plus unknown/comment keys become schema 12 with identical contents otherwise; schema 13 stops.

- Host-only relocation uses normal owned recovery, even on bare activation: route sole legacy settings in memory; claim the established notebook or, for eligible history-free setup, exclusively reserve/scaffold its routed new notebook before migration proof. Keep exact originals in a private persistent backup outside Git/configuration discovery; existing evidence links safe backup paths/hashes and exact source/destination identities. Destination is `<checkout>/<effective ag-dir>/ag.json`, including nested custom directories; root and previous fixed-default files migrate here for all future activations. Never create a template beside existing configuration. Reject unsafe paths, changed source, collisions or a tracked config becoming ignored; safely create needed parents, move without overwrite, verify source absent/destination bytes identical, then atomically edit keys/schema at the destination. Preserve index/foreign work and all record locations. No helper or notebook/record relocation.

- Interrupted relocation resumes only from saved identities/original bytes: source absent and matching destination permits remaining edits; dual files stop for reconciliation. Discovery/current schema at the new path must not discard preserved pre-migration evidence. Configuration alone does not establish task history; ordinary notebook/archive/retirement checks still precede setup.

- Proving examples: root schema-9 `skip-plan: off`, `skip-wip: off`, `ag-dir: notes` → `notes/ag.json`, schema 12, `plan-mode: optional`, `omit-wip: off`; old on → plan-mode off without another choice. Schema-10 `.agentflow/ag.json` with `ag-dir: docs/agent/notes` moves to `docs/agent/notes/ag.json`; default ag-dir stays in place. Conflict `skip-wip: on` / `omit-wip: off`, dual files, unsafe paths and schema 13 stop. Nested custom config is rediscovered without a pointer/depth cap; current input rereads without writes; interrupted moves retain bytes/history.

- Off-record/read-only/delegated/isolated contexts defer relocation and upkeep writes; compatible known legacy settings may be read in memory. Lifecycle commands never migrate main's live config or touch its root notebook/claim; authorized feature-local preparation follows features.md. Pending relocation counts as migration, not an idle scheduling write. New-feature setup and future-date/release scheduling use the feature-local/canonical path respectively.

- Preserve unknown and `//` keys, key order, worker metadata and valid nondefaults. Rename keys/values only with documented mappings; differing old/new values require an owner decision. Remove only documented obsolete fields under their mappings; other changes to owner choices require approval. Missing new keys follow defaults; add only fields required by a documented migration. Do not pin every new default. Schema changes include predecessor mappings, removals/additions and proving examples in this section; increment the integer once per schema revision.

- Reuse existing atomic-write rules: reject symlink/escaping targets, retain original bytes privately outside Git/configuration discovery and link safe recovery references, verify unchanged source, write an exclusive adjacent temporary file, atomically rename and reread. On unchanged current input, write nothing. Migration grants no notebook relocation, task/worker dispatch or installation authority. Report changed keys once in the saved result; before notebook recovery retain the notice in session context. Explicit read-only constraints defer migration and dependent work. Off-record activation defers automatic migration without record access; an explicit off-record config edit follows its own authority without recording that exchange. A needed migration is authorized maintenance: resolve routing from the mapped in-memory config, then use normal notebook ownership/recovery and retain pre-edit bytes before writing; the bare-activation idle shortcut applies only when no migration is due. Feature lifecycle routing and root-notebook exclusions still prevail.


## Approved installation replacement

Replacement always requires explicit owner approval first, including the beta-to-Agentflow 9 transition. Resolve the real installed path first. A symlink/source checkout or dirty installation requires a WIP-preserving route and approval of that concrete route; never overwrite source through a link. Prefer the installation’s supported skill/plugin updater after verifying its controls. Manual replacement is for unmanaged copies only: stage the named release outside the install, verify its approved product/name/version and destination identity, preserve a recoverable backup under the deletion policy, replace only the approved payload and reread its version. Reject changed/unsafe state; inspect partial results before retry. No publication or unrelated config rewrite follows.
