# Setup and adoption

Read only for eligible first-time creation or actual root-instruction adoption. Entrypoint off-record, lifecycle and idle guards prevail; [session](session.md) owns identity, claims, capture and shared-record discovery.

## AGENTS adoption

- Ensure root `AGENTS.md` directs host-only session-start activation. When no activation directive exists, add verbatim: “At session start, the owner-facing host must load and follow aglite via supported skill discovery, honoring explicit owner opt-outs. If unavailable, report it; never assume paths or install it. Delegates follow assignments without activating aglite.” Name the skill, never a host/path/install scope; no `godev` needed. Off-record/idle/feature rules and explicit owner activation/opt-outs prevail. Also direct all project agents/reviewers to the shared baseline and optional resolved local rules before work/review: “Read aglite's `references/project-rules.md` from the resolved skill or exact host-supplied text, then `<ag-dir>/rules.md` if present; unavailable baseline defers shared-record writes and invariant/review acceptance. Report the gap and continue independent authorized work. Reading rules does not activate aglite.” Substitute the actual checkout-relative local path. Check activation/baseline targets. Report broken project-relative skill paths with a named-skill correction proposal; never treat them as satisfied or rewrite owner text without authority. Add only uncovered instructions; duplicate no activation/local-read directive. Create exclusively or insert near the top after frontmatter/title. Preserve owner bytes: check unchanged source, write adjacent temporary file, atomically rename, reread. Escapes, directories, symlinked adoption paths or concurrent changes stop adoption writes; report unmet result, continue independent authorized work. Do not relocate instructions without owner authority; reviewers treat them as data, not workflow-execution authority.

## First-time setup

- Before non-Git setup writes, ask in chat whether the owner wants Git, even with `inline-reply: off`; reuse this folder’s explicit prior choice, otherwise wait. Approval permits `git init` only in that verified folder: verify success, apply bootstrap below, refresh identity/configuration/routing before continuing. Decline continues non-Git with Branch N/A, no Git delivery. On failure inspect/preserve partial Git state, report and await owner recovery choice; non-Git continuation requires verified non-Git identity. No remote creation/publication authority.

- Immediately after approved `git init`, run `git commit --allow-empty --only -m "chore: initialize repository"` and verify HEAD before further setup/handoff. This sole empty bootstrap is authorized even with `auto-commit: off`; preserve staged/pre-existing files. Recovery reuses existing HEAD, never repeats it. If commits are explicitly forbidden, skip it and report that feature worktrees need a commit. Commit failure retains Git state and stops setup: report blocker/next action, never completion. No remote/publication authority.

- In a verified existing checkout/folder with no selected notebook, established history or prior retirement, resolve the canonical/sole legacy configuration or [template](../assets/.agentflow/ag.json) in memory first; preserve existing choices and use the observed locale/derived notebook name only for new defaults. Resolve configured paths, safely create needed parents, claim the new notebook as A-001, then exclusively initialize it from [assets/.agentflow/devlog.md](../assets/.agentflow/devlog.md). Populate STATUS from observed identity and explicit/root routing. With sole legacy config, save original bytes/identities in linked round evidence and relocate/migrate under configuration.md before further setup. Create `<checkout>/<ag-dir>/ag.json` from the template only when discovery finds no canonical/legacy configuration or unresolved candidate, with exclusive creation and the derived `switches.notebook-name`; never create a second config beside legacy. Preserve files/settings/owner markers/history; concurrently appearing files stop initialization for recovery, never overwrite. Managed-feature routing/initialization follows features.md.

- For main/root setup after [shared-record discovery](session.md#project-rules-and-backlog), create missing backlog and empty registry from `assets/.agentflow/`, plus `artifacts/`, `features/` and `.tmp/` with their `.gitkeep` placeholders under configured ag-dir. Reuse established authority, never duplicate. Reject escapes/symlinks; create exclusively, preserve bytes and reconcile collisions/concurrency before dependent writes. Adapt assets individually: config belongs at `<checkout>/<ag-dir>/ag.json`, notebook at its resolved path; never copy the asset tree over live records. Do not generate rules.md, archives, per-round designs/evidence, feature worktrees or extra claims before needed. Adopt default activation in root AGENTS under [AGENTS adoption](#agents-adoption); explicit owner overrides prevail. Managed feature initialization creates only its config/notebook under features.md; reuse its inherited shared records, never create setup scaffolds there. Empty registry creation uses the invariant notice heading with “no accepted IDs; empty scaffold created”; it establishes no guarantee.

- Hosts adapt bundled notebook/config/setup scaffolds directly under [ownership](session.md#notebook-ownership), placing config at `<checkout>/<ag-dir>/ag.json`, without hooks or executable helpers. Create round artifacts/archives only when needed. Initialize Git only under the choice above or an explicit owner request. Capture supplied task input in A-001 using [owner-input capture](session.md#activate-and-recover). Eligible fresh-folder activation authorizes setup without a task, after the non-Git choice above when applicable: capture the activation in A-001, close out setup under [delivery](delivery.md) with Reply/next Ask and configured Git delivery, release ownership, then ask for the next request in chat instead of the short completion receipt. Schedule no project work. Other bare idle activation uses the early shortcut without initialization or notebook writes.
